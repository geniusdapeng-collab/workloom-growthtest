## 三、本轮修掉 / 登记的解析层问题

### 3.1 【已修 · 真缺陷】参数配方表被当"提示词写法"吸收（CINE-002 §6.3）

**现象**：`CINE-002 §6.3 组合公式（景别 + 焦距 + 光圈联动）` 的表头是 `想要的效果 | 组合 | 提示词关键词`，
单元格内容是 `ECU + 85mm + f/1.4 效果` 这类**参数配方**。旧解析器只认五种表头
（创作意图 / 中文意图 / 参数组合特征 / 技术参数 / 参考特征），认不出时 `tableKind` 保持 `null`，
但兜底分支 `entries.push({ kind: "prompt" })` **照样吸收** —— 于是整张表（**连表头行本身**）都进了条目池，
产生 6 条假条目：`intent="想要的效果" zh="组合"`、`intent="**情绪炸弹**" zh="ECU + 85mm + f/1.4 效果"` 等。

**影响面**：条目池会被 `selectEntries()` 消费，输出到 `trace.explored` 与 `cine-kb-cli search`，
与知识库总则"提示词里不要直接写 f 值 / mm 值"直接冲突；`intent` 还带着 markdown 加粗记号。
本轮机检确认：因 `minScore=4` 门限，这 6 条在 36 场景中没有进入自动注入字段，属"污染池"而非"已泄漏"。

**修法**：表头改为**按 markdown 结构识别**（表头行的下一行必是 `|---|` 分隔线），认不出表头的表整表跳过并登记 `unknownTables`；
同时剥离单元格里的加粗记号。改完 CINE-002 条目 23 → 17，全库 394 → 388，参数配方型条目归零。

**回归**：`audit-round4.test.ts` › "参数配方表（CINE-002 6.3 组合公式）不再被当 prompt 条目吸收"。

### 3.2 【已修 · 真缺陷】OPTICS-001 §八 决策树 6 个意图只解析出 4 个

旧正则只认 `（f/x 效果）` 一种写法，漏掉两类叶子：

- `"夜晚/暗光手持" → 最大光圈效果（f/1.4–f/2.8）` —— "效果"在括号外；
- `"运镜叙事/焦点转移" → 浅景深 + rack focus` —— 叶子没有 f 值（方向型规则，不是档位型）。

**修法**：两种句式都认；方向型叶子单独进 `directionRules`（不参与档位选择，
避免 `aperture=null` 的规则被选中后落回"人景皆清"这类无关档位）。
结果：**6/6 叶子全覆盖**（5 档位型 + 1 方向型），并恢复 `夜晚/暗光手持 → f/1.4–f/2.8` 这条决策依据。

**回归**：`audit-round4.test.ts` › "OPTICS-001 第八节决策树 6 个叶子全覆盖"。

### 3.3 【登记 · 未修，属内容资产】第六章 bullet 段不解析（10 篇 31 条）

第六章后半的"氛围叠加词"是 bullet 列表（如 `- 大光圈氛围：柔焦 glow、朦胧 hazy、梦幻 dreamy`），
解析器只读 3 列表格，这些词汇进不了条目池，自动注入与 `search` 都够不到。
涉及：CINE-001(4)、LIGHT-001(3)、LIGHT-002(3)、OPTICS-001(2)、OPTICS-002(2)、OPTICS-003(3)、OPTICS-004(2)、PHYS-001(4)、SCENE-001(4)、STYLE-002(4)。

**为什么不直接改**：这类词是"叠加词"而非"意图 → 写法"映射，强行入池会让自动注入多出难以判定的候选。
建议在解析结果里加显式的 `ambientTerms` 字段供 Agent 主动取用（提案见 `proposals/kb-gap-round4-2026-09-25.md`）。

### 3.4 【登记 · 未修，当前无消费方】章节语义名按位置推导，非标准章节顺序会标错

`parseTopic` 的 `semantic` 用 `CHAPTER_NAMES["一二三四五六七八九十".indexOf(numeral)]` 按**位置**取名。
九章骨架的篇目无碍，但 COLOR-002 / HUMAN-001 / STYLE-001 的章节顺序偏离骨架，于是出现明显错标：
COLOR-002 §四「黑位的学问」被标成"视频特有规则"、§五「影调与光比的联动」被标成"常见误区"、
HUMAN-001 §七「AI 视频特有问题（人脸崩坏规避）」被标成"提示词模板"、§八「提示词模板」被标成"决策树"、
STYLE-001 §九「常见误区」被标成"关联知识"。

当前 `semantic` 字段没有任何消费方（机检 `grep -rn "\.semantic" bundles packages scripts` 无命中），
故不影响线上行为，但会误导后续"按语义取章节"的代码。建议改为按标题推导，或删掉该字段。

### 3.5 观察项：mm 级焦距词仍在"中文提示词写法"里（6 条，属 KB 原文口径）

`OPTICS-002 §6.1/6.2`（"35mm 纪实视角""85mm 人像镜头"）、`OPTICS-004 §6.2`（"35mm 胶片质感"）、
`STYLE-001 §6.1`（"35mm 颗粒"）的中文写法本身就含 mm —— 这是 KB 作者的口径（KB 显式允许 "35mm documentary look"）。
本轮只清掉 `f/x` 值污染，mm 保留；这类条目也不被任何自动注入规则引用。

## 四、占位符台账（调用区 17 条）

`resolvePlaceholders()` 只覆盖 5 类元素候选（灯笼 / 水面与倒影 / 摇橹船 / 往来行人 / 飘落的花叶），推不出就填"画面内元素"。
调用区里带占位符的条目如下 —— **其中只有 CINE-001「固定机位观察」会被自动注入**，
其余只在自由检索（`selectEntries` / `cine-kb-cli search` / `trace.explored`）里出现，而**自由检索路径不实例化占位符**：

| 篇目 | 条目 | 中文写法 | 是否被自动注入 |
|---|---|---|---|
| CINE-001 | 固定机位观察 | 固定机位，镜头完全静止，画面内[元素]自行运动 | 是（有兜底实例化） |
| CINE-001 | 聚焦关键道具 / 细节 | 镜头缓缓推向[物体]，周围逐渐虚化 | 否，仅自由检索 |
| CINE-001 | 降落到主体 | 镜头从高空缓缓降落到[主体] | 否 |
| CINE-001 | 斯坦尼康流畅穿行 | 镜头平稳顺滑地跟随人物穿过[空间] | 否 |
| CINE-001 | FPV 穿越俯冲 | FPV 无人机高速穿越[峡谷/楼宇]，贴地俯冲 | 否 |
| COLOR-001 | 黑白中一点颜色 | 黑白画面，仅[主体]保留红色 | 否 |
| OPTICS-002 | 背景巨大化 | 远处[落日/月亮/建筑]巨大地悬在人物身后 | 否 |
| SCENE-002 | 框架构图 | 透过[门/窗]框住[主体]，画中画构图 | 否 |
| SCENE-002 | 纵深层次 | 前景[遮挡物]虚化，中景主体，远景交代环境 | 否 |
| STYLE-002 | 情感慢动作 / 超慢动作 / 瞬间凝固强调 / 喜剧快进 / 焦虑跳切 / 倒放魔法 / 一镜到底 / 匹配剪辑转场 | 含 [动作] [瞬间] [主体] [形状/动作] 等 | 否 |

**结论**：自动注入路径的占位符风险已被兜底覆盖；自由检索路径仍会把 `[物体] [主体] [动作]` 原样吐给 Agent
（与 playbook §一 事故 7"模板占位符下发"同源，只是换了一条路径）。登记为待办（见 round4 报告 F9）。
