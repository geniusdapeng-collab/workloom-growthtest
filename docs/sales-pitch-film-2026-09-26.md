## 三、真机缺陷与修复（都在本 PR 内）

### 1. 关键帧缓存"洗白"（`plate-cache.ts` + 管线）

- **现象**：把出镜服装从西装改回角色档案 w1（月白旗袍）后重跑关键帧，被监制打回的 4 张旧图
  因为"文件在盘 + >50KB"命中缓存分支，**直接记 ok 且不再送审**——旧图被当成合格产物。
- **修复**：缓存命中改为四验——文件在场且够大 + **出图指纹**（提示词 sha256）+ 锚点模式 + 上次裁决放行；
  放行才写出图指纹，被驳回的图必然重出。判据抽到 `packages/video-studio/src/plate-cache.ts`（8 例单测）。

### 2. 【场景】被写实校验静默替换（`shot-spec.ts`）

- **现象**：镜头卡写"打烊店铺前厅 + 门外虚化的街道霓虹"，vendor 写实校验命中禁用词「霓虹」后
  把整段【场景】换成中立模板"简约室内房间…"，**且不写任何日志**；只能等监制看画面与卡片不符打回。
- **修复**：`prepareShotPrompt` 增加零 token 确定性检测 `sceneSubstituted`（与兜底模板逐字比对 +
  字符二元组重合度双判据），在 spec 报告与运行日志里显性暴露（7 例单测，含真机链路复现）。

### 3. 配乐卡点判定失真（bgm-bridge + 管线）

- **现象**：标称 120BPM 的曲目被判 **99.6BPM**、17 个剪辑点只有 7 个落在 ±80ms 内（平均 122ms），
  工位自判 `unaligned` → 监制连续打回配乐环节。
- **根因**：`deriveTempoFromCuts` 只挑"离基准 BPM 最近"的单个候选，而调用方没把曲目真实 BPM 交给混音器，
  基准落到默认 100：5.00s 间距反推 96、被转场偏移的 4.82s 反推 99.6、4.50s 反推 106.7 → 99.6 胜出，
  而 99.6BPM 的网格**对不上自己的剪辑点**。
- **修复**：① 管线在"曲库音乐床"与"点名曲目"两条路径都把曲目真实 BPM 透传（`--bgm-bpm`）；
  ② `deriveTempoFromCuts` 改为 **±2BPM 聚类取票数最高**（个别被偏移的间隔不再带偏整体 BPM），
  并在回执里给出票数；③ 口径修正：口播型销售片用**硬切基准卡点**（见下）。4 例单测覆盖真机复现。

### 4. 编辑口径：硬切基准卡点

- 逐刀转场（hblur 0.18s）会按刀数吃掉时长，剪辑点随之偏离 0.5s 网格（实测只能对上 7–8/17）。
- 本片改为**全片硬切**：剪辑点稳定在 0.5s 网格 → 与 120BPM 音乐床做到 **17/17、平均 0ms**。
  结论已写入模板 `sales-pitch-5ring`（`editing.cut_transition`）：确需甩镜时，要么接受卡点降级，
  要么给转场点之后的镜头补足等长时长。

### 5. #165：重建桥产物缺【服装】字段 + 台词竖杠（并行会话的卡点）

- **现象**（连续 4 轮营销片真实模型复现）：vendor Phase 3 失败后宿主侧重建的 prompt **没再过一遍字段契约**，
  被 `render-pipeline-guard` 的 `COSTUME_LOCK`（缺【服装】）与 `DIALOGUE_FORMAT`（台词含 `|`）稳定拦下，
  渲染零提交。
- **修复**：`rebuildPromptsFromFields` 重建后调用新增的 `healPromptContract`——
  台词 `|` → `，`（含两侧空白归一）、缺【服装】时按"卡片 costume 字段 → 角色描述 → 显式未锁定声明"
  补齐并**重排字段编号**；未锁定时记 `costumeLock=false` 并在桥日志里点名，不静默放行。5 例单测。

   出现"同一主角重复副本 + 合成硬边"（监制打回）。本次改用**物体主导**版式交付；
   建议后续为人主导版式加"底图去人（虚化/裁切）"处理后再放开。
2. **变体的风格轴**：当前多风格交付包按"调色 + 封面文案"派生（画面差异实测达标、音轨 delta 0）。

3. **战报数字的对外口径**：第 16 镜"内容产能翻二十倍"取自 PPT《苏州洲际 90 天战报（模拟数据）》，

## 六、第二轮返修（产品所有者真机反馈，T-2026-0927-0001）

产品所有者拿到首版后反馈两处问题，均已定位到管线缺陷并修复：

### 6.1 开场同一句被说了两遍（"没动嘴先说一遍，紧接着又重复一遍"）

- **根因（管线回执自证）**：第 1 镜模型人声**已经正确说出台词**（ASR 匹配 1.000、转写逐字一致），
  但"人声活动度 0.228 < 下限 0.25"触发了补旁白；`keep-dialogue` 把 TTS 旁白**叠在原声之上**，
  复核转写变成"还在给平台打工吗**还在给平台打工吗**"。
- **修复**：
  1. `speechAcceptance`（新模块 `packages/video-studio/src/narration.ts`）——**强匹配（≥0.6）时不得因活动度偏低而补旁白**，
     转写对得上就已经证明台词在场，活动度只是制作指标；
  2. `isDoubledNarration` —— 补旁白之后**查重复播报**，同一句出现两次即判补旁白失败、
     **删除配音产物并回退原片**（绝不把"说了两遍"的音频交付出去）。
- **复核**：新母版前 6 秒转写「还在给平台打工吗」（匹配 1.000、语音段 1、活动度 1.000）。

### 6.2 片头多余字卡（标题压在口播上）

- **现象**：字幕工位的 `--title` 会在片头叠一张标题卡（约 2–3s），与开场钩子抢注意力。
- **修复（交付口径）**：本片交付统一传 `--title ""` 关闭标题卡，开场即口播；
  封面改为**集成进片头的 1.2s 封面卡**（见 6.3）。

### 6.3 封面没有集成进成片（首版只在成片外给了 PNG）

- **修复**：主交付改用「封面卡 1.2s + 正片」的 `with-cover` 版本；
  三支风格变体与干净版也各自拼接了**与自身调色档同调**的封面卡（变体封面卡按该变体的
  `gradeProfile/intensity` 单独调色后拼接）；封面底图改用「五环灯环」（与"五环闭环"文案同源）。
- **封面夜景一致性误判（顺带修掉的真缺陷）**：封面设计稿本已选中灯环底图，
  但"标题含夜景字眼 → 底图必须是夜景镜"的校正用了过宽字表 `/夜|灯|亮/`，
  设计理由里的「五环**点亮**」被误判成夜景意图，把底图换成人物近景（双手交叠）→
  封面因此被监制判"肢体畸变"打回。现改为窄口径 `coverPrefersNightBackground`
  （只认 夜色/夜景/夜晚/夜间/深夜/夜幕/灯火/灯海/灯光秀/霓虹），并补 4 例单测。

### 6.4 其他收口

- **配乐真峰值**：AAC 编码后会有 ~0.1dB 过冲，按混音器默认 −1.0 dBTP 出片会变成 −0.9 dBTP，
  越过终审"真峰值 ≤ −1.0 dBTP"硬上限 → 新增 `--bgm-true-peak`（默认 −1.5，本片用 −1.6）。
- **时长守恒**：为容纳 1.2s 封面卡，把 GR-08（4.5→4.0s）与 GR-13（5.5→5.0s）各收紧 0.5s
  （两镜语速仍在 2.77–2.80 字/秒预算内）；成片 **88.9s**，含封面卡 **89.9s**，仍在 80–90s 带内。
- **终审**：封面 90 / 配乐 90 / 终审 **88 分放行**；变体差异实测 15.3–24.6（G-DLV1 通过）。
