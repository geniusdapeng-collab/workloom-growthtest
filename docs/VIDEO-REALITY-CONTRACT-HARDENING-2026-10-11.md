# 视频"实体与物理常识"加固（T-2026-1011-0001）

> 背景样本：`VID-ZXRRC-12`（TikTok 30s 竖屏获客片 · 张雪机车 820RR-RC · 主角=系统 1 号模特陈卓）。
> 产品所有者逐条复盘出 7 类严重问题（人车比例像玩具 / 无人驾驶 / 台词镜换人 / 末镜中文口播 / 像 CG 游戏过场 /
> 缺头盔 / 单张商品图还原差）。本文是**抽象后的根因与设计**，实现见
> `packages/video-studio/src/plausibility-review.ts`（模型侧）与 `dialogue-contract.ts` + `product-archive.ts`（机械侧）。

## 0. 先说结论：不要枚举世界

第一版修复（已回滚）走的是"给机车写规则"：`vehicle-policy.ts` + 品类知识库。
**这是错的**——换成汽车、自行车、相机、3C、牛肉馅饺子……世间万物无法穷举成规则表，
而且每条规则都要人去猜、去维护，必然"头疼医头"。

正确分工：

| 层 | 判什么 | 谁来做 |
|---|---|---|
| **机械合同层**（确定性，零 token） | 引用式台词与 `dialogue` 是否逐字一致；台词语言与影片语言是否一致；无台词镜是否被写了"说话"；档案是否缺少可核实事实（尺寸/多角度） | `dialogue-contract.ts` / `product-archive.ts` / `first-pass.ts`（只保留可枚举的事实） |
| **世界模型层**（模型，通用） | 主体在真实世界里由谁使用、怎么用；运动有没有动因；必备装备/配套物；人与物的真实尺度；重力/支撑/接触/动力；使用状态；商品保真；实拍感 vs CG/游戏过场；法规与安全硬边界 | `plausibility-review.ts` 的**实体与物理常识审核 agent**（用模型自己的世界知识，不预设品类） |

## 1. 抽象后的根因（与品类无关，换任何商品都成立）

1. **系统只有"画面语言"，没有"主体语义"**：构图/光线/运镜齐备，但"这个主体在真实世界里怎么存在、怎么被使用"从未被任何环节检查过。
2. **运动没有动因约束**：只要动词出现，模型就按字面渲染——摩托车会无人驾驶、相机会悬空自动拍照、饺子会凭空悬浮。
3. **尺度没有量纲**：档案/卡片不携带可核实尺寸时，模型只能靠语料先验猜大小 → 大件被画成玩具。
4. **身份一致性只查文本、不查证据**：说明书（卡片）说"同一人"，但没有任何环节看**生成出来的画面**是不是同一人。
5. **只校验字段"存在"，不校验跨字段"同一事实一致"**：台词在 `dialogue`/时间轴/导演意图三处各说各话仍能过闸。
6. **真实性只有负面词，没有实拍证据要求**：写"不要 CG"不等于给了真实光学/材质/痕迹的约束。
7. **语言与平台文化是隐式默认（全中文）**：作品语言不做一等元数据，英文片会出现中文腔口播、中文弹幕、ASR 强制 zh。

## 2. 设计

### 2.1 实体与物理常识审核 agent（模型侧，核心）

`packages/video-studio/src/plausibility-review.ts`

- **通用 rubric（品类无关）**：要求模型用**自己的世界知识**逐镜回答——主体是什么/谁在用/怎么用；任何运动是否有可见动因；该主体真实使用需要什么（模型自己判，不依赖清单）；人与物的真实尺度；重力/支撑/接触/动力；使用状态是否明确；商品是否与档案事实一致；实拍还是 CG/游戏过场；法规与安全硬边界；叙事逻辑是否接得上。
- **事实输入**：逐镜卡片 + 实际编译出的提示词 + 商品档案（名称/品牌/类别/真实尺寸/角度照片/参数）+ 角色档案（含身高）+ 平台/语言/画幅/时长。
- **两个调用点（都是花钱前）**：
  ① `pre-render`：关键帧之前（卡片+提示词+档案）；
  ② `pre-submit`：逐镜视频提交之前（附关键帧画面，视觉核对比例/身份/装备/保真/实拍感）。
- **结论形态**：`verdict=pass|block|unverified` + `findings[{severity: blocker|warning, shotId, issue, why, fix}]` + `promptPatches[{shotId, clauses[]}]`（模型自写的提示词条款，直接追加进该镜提示词）。
- **纪律**：这是**事实闸**，不受 `--review-policy off` 影响；无模型 / HTTP 失败 / 结构非法 → `unverified` → fail-closed（未花钱停）。

### 2.2 机械合同层（确定性，只留可枚举事实）

- `dialogue-contract.ts`：引用式台词逐字一致（抓"时间轴残留旧台词"）、台词语言与影片语言一致、无台词镜禁人声词句；提示词注入【台词语言】（含逐字要求）【无台词】。
- `product-archive.ts`：商品档案新增 `category` / `photos[].angle` / `specs.dimensions`；大件类（如 `category=vehicle`）硬校验"≥2 角度 + ≥2 项真实尺寸"——这是**数据完整性**要求（给审核 agent 提供可核实事实），不是世界知识。
- `continuity.ts`：无人物镜不参与造型一致性判定。
- `first-pass.ts`：保留机械事实（台词合同、时点锁定、帧率、红线…）；"有台词却无可见面部"降为中风险提示（最终由审核 agent 判）。
- `full-chain-film.mts`：影片人声语言解析（显式 > 台词推断）、人物身高进外貌文本、弹幕语言感知默认、素材镜提示词挂写实/台词条款、纯后期补跑不再被强制记成 narrative。
- 写实负面词补 `no video game look / no game cutscene`（机器标记；真实性判断仍由 agent 结合画面判）。

## 3. 验证证据

1. **本案（摩托车）**：同一套 agent、零品类规则，对 820RR-RC 原分镜给出 `block`——
   "赛车无骑手自行弹射起步""运动镜无任何骑手防护装备""手触排气尾段未标注冷车/熄火""仅手部与侧脸入画存在断手风险""台词 speaker 与画面人物关系未标注"等，并给出逐镜提示词补丁。
2. **跨品类泛化（不改一行代码）**：
   - 汽车："SUV 自己启动驶出车位、车内无人" → blocker；缺安全带/驾驶姿态 → warning；补驾驶员+安全带+车灯+尺度锚的提示词补丁。
   - 相机："微单悬空自动对焦按快门" → blocker（无支撑、无动因）；"镜头自转"在物理上不成立 → warning；补吊臂/云台/安全绳/摄影师手部/尺度参照的提示词补丁。
   - 牛肉馅饺子："饺子盘悬空 + 塑料质感且无热气" → blocker；"无使用状态/无尺度锚/牛肉馅不可画面验证/时长不闭合" → warning；补实拍化（热气、面皮纹理、筷子与醋碟尺度锚）的提示词补丁。
3. **单测**：`plausibility-review.test.ts`（rubric 通用性、上下文预算、解析、block/pass、无模型 fail-closed、补丁幂等）+ `dialogue-contract.test.ts` + 既有 `first-pass/shot-spec/plate-prompt/product-archive` 套件；`packages/video-studio` 全量 91 文件 1674 例通过。
4. **复现探针**：`scripts/tools/plausibility-probe.mts`（四类场景 + 真实模型；证据日志随 PR 提交）。

## 4. 边界

- 本批只加"事实与常识"判据，不恢复渲后审美复审；"成功渲染默认直接采用"口径不变（审核发生在**花钱前**）。
- 审核 agent 输出的是**可执行结论**（问题/为什么/最小修法/提示词补丁），不是分数；不产生新的品类规则表。
- 商品档案的"多角度 + 真实尺寸"是数据要求：没有它，任何评审（人或模型）都无法核对比例与保真。
- 后续（未在本批）：关键帧人脸比对（身份锚的机器证据）、渲后台词语言 ASR 复核默认开启、素材镜多参考图。
