## 一、修复清单

### F5.1【严重 · 已修】字段预算把注入整段吃掉，却仍记在 trace 里（假回执）

- **现象**：`camera_movement` 原文 342 字 + 一条注入 → 结果字段被 `slice(0,319)+"…"` 截成 320 字，
  **注入短语完全没写进去**，而 `trace.applied` 里照样记着 `added:"手持镜头，轻微自然晃动，纪实风格"`。
  同源第二例：`lighting` 原文 360 字 → 注入同样消失。卡片作者写的原文尾部也被截掉（数据损坏）。
- **根因**：合并顺序是"原文 + 注入"，截断施加在**合并后的整串**上，且截断结果没有任何标记。
  这是 playbook §〇 明令禁止的"无回执"形态——审计看不到"实际写进去几条"。
- **修复**：原文一字不动；注入**放得下才追加**，放不下整条丢弃并在 trace 记
  `dropped:"field-over-budget"` + `writtenChars` + `originalChars`；字段本来为空时只截注入自己。
- **回归**：`audit-round5.test.ts` › "原文超预算：原文逐字保留，注入整条丢弃并在 trace 里如实记账" +
  "原文放得下：正常追加，writtenChars 与实际写入一致"。

### F5.2【严重 · 已修】条目打分用的是未剥否定的原文 → "避免赛博朋克"反而让赛博条目命中

- **现象**：卡片 `director_instruction:"避免赛博朋克全息广告的科幻感"`，
  `STYLE-001#赛博朋克`（"赛博朋克，霓虹雨夜，品红青光，湿地反射"）以 **10.8 分**进入候选池。
- **根因**：`detectContext` / `injectionContext` 都做了 `stripNegatedContext`，
  但 `selectEntries()` 把 **`shotSignals(card).text`（原始文本）** 交给 `scoreEntry`，
  于是意图命中、2-gram 重合、以及 `styleConflict()` 的"卡片里有没有赛博语境"白名单三项**全部看到了被否定的词**。
  情绪派发（`recipeDispatch`）的 `moodText` 同病（"不要孤独感"会派发孤独配方）。
- **修复**：统一改用 `stripNegatedContext(signals.text)` 作为打分文本；派发文本同样剥离。
- **回归**：`audit-round5.test.ts` › "「避免赛博朋克全息广告」不再让赛博条目命中"（含**肯定表述对照组**，
  证明不是把打分机制削平了）。

### F5.3【一般 · 已修】NARR-001 情绪配方派发线索被丢弃

- **现象**：`selectEntries()` 算出 `recipeDispatch`（如 `孤独 / lonely, solitary, isolated / 配方缩写`），
  但 `enrichShotCard()` 调用后只保留了 `picks`，**派发线索直接丢弃** ——
  KB 检索总则要求"先取情绪配方，再按配方回查细节"，这条链路的凭据在 trace 里无迹可查。
- **修复**：trace 新增 `recipeDispatch` 字段（未命中为 `null`）；`cine-kb-cli enrich` 摘要里一并打印。
  真机可见效果：`SC-05 … · 情绪配方派发 温暖`。
- **回归**：`audit-round5.test.ts` › "mood 命中情绪 → trace.recipeDispatch 非空" + "只做线索、不直注"。

### F5.4【严重 · 已修】天气时序：雨后/雪后被当成"正在下"

- **现象**（真机语料直接命中）：
  - `雨后的古镇石板路，积水倒映着白墙黛瓦` → 注入"**细密雨丝如雾般飘落**"（雨已经停了）；
  - `雪后的古镇清晨，屋顶积雪` → 注入"**雪花缓缓飘落**，天地纯白宁静"（雪已经停了）。
  round3 的回归用例甚至**把这个错误当成了期望值**（`expect(light(雪后)).toContain("雪花")`）。
- **根因**：`rain: /雨/`、`snow: /雪/` 只有"有/无"，没有"正在下 / 已经停"。
- **修复**：新增 `rainNow` / `snowNow` 两个信号（`snowNow` 要求"正在下"的字面，且排除"雪后/雪停/残雪/融雪"；
  **"积雪"不算停雪证据**——"大雪纷飞…屋顶积雪"同时成立）：
  - 落雪（lighting / props）只在 `snowNow` 命中；
  - 细雨只在 `rainNow` 命中，暴雨新增走 KB「暴雨倾盆」行（该行此前无任何规则引用）；
  - 雨停之后走 SCENE-001「雨后初晴」（"雨停后阳光刺破云层，湿街反射金色天光"），并排除夜景（该行写的是阳光）。
- **回归**：`audit-round5.test.ts` 的"天气时序"四条 + **修正 round3 的期望值**（见 §三）。
- **KB 缺口**：雪后/积雪静景 KB 无对应行 → 登记 **G18**。

### F5.5【一般 · 已修】静止回眸被写成"行走中回头"

- **现象**：`{action:"回眸一笑，身体不动", camera_movement:"固定机位"}` → composition 注入
  "**行走中**回头看向镜头"——注入短语断言了卡片明确否定的动作（与 playbook §一 事故 5 同源，触发词不同）。
- **根因**：`lookBack` 只判"回眸/回头/回望"，没有判"是否真在走动"，而 HUMAN-001 该行的中文写法自带"行走中"。
- **修复**：规则加 `&& c.walking`；真实走动回眸（如 SC-01"缓步向前，停步回眸"）不受影响。
- **回归**：`audit-round5.test.ts` › "静止回眸不再被写成「行走中回头」；走动回眸照旧"。
- **KB 缺口**：静止回眸（"转身回望/回眸定格"）KB 无对应行 → 登记 **G19**。

### F5.6【一般 · 已修】两套上下文取词字段不同 → 光圈侧与注入侧看到的世界不一样

- **现象**：`{scene:"巷口", timeline:"夜晚 20:00"}` → `detectContext().timeOfDay = ["night"]`，
  但 `injectionContext().night = false`（注入侧不读 `timeline`）；反向地，
  `baseline` / `pacing` / `makeup` 只有注入侧读得到。
- **根因**：两个函数各写一份字段清单（代码注释却写着"与 detectContext 同口径"）。
- **修复**：抽出 `CONTEXT_FIELDS` + `contextText(card)`，两边共用。
- **回归**：`audit-round5.test.ts` › "两套上下文共用同一张字段表"两条。

### F5.7【一般 · 已修】7 条 framing 规则是死规则（永远不可能命中）

- **现象**：`{composition:"景别：中景 / 近景 / 特写 / 大特写"}` 四种卡片，composition 注入**全为"无"**。
- **根因**：规则条件是 `when: (c) => c.framing === "中景"`（要求**已知**景别），
  而循环里又有 `if (rule.id === "framing" && ctx.framingKnown) continue;`（要求**未知**景别）——
  两个条件互斥，七条规则从未生效过。
- **处置**：删除七条规则与那条守卫（保留 `framingKnown` 供「平视 + 未声明景别」规则使用），
  并在注释里写明结论：卡片自己已写景别，再注入一行是同义重复；CINE-002 景别行改为**只经自由检索**可达（登记 **G20**）。
- **回归**：`audit-round5.test.ts` › "不存在永远不可能命中的 framing 规则"。

### F5.8【建议 · 已修】其余死配置

| 项 | 结论 | 处置 |
|---|---|---|
| `TOPIC_TARGET_FIELDS`（主题→字段映射表） | 除定义外**零引用**（落点早已由 `INJECTION_RULES[].field` 决定） | 删除，注释指向唯一事实源 |
| `APERTURE_INTENT_HINTS` 的 `prefer:["建筑","城市"]` | §三 场景表里**没有这两行**，标签永远匹配不到任何行 | 改为实际存在的 `["街拍"]`（幕墙镜头仍落 f/8） |
| `contradictionPenalty` 的 `daytimeOnly` 含 `"overcast"` | 它是 **weather** 的键，不可能出现在 `timeOfDay` 里（死条件） | 移除（对真实输入行为不变） |

### F5.9【建议 · 已修】规则-行引用完整性此前没有任何守卫

- **风险**：`pickRow()` 找不到行时**静默跳过**——KB 改一个行名，注入就悄悄少一条，没人会发现。
  本轮机检 51 条规则当前全部可解析（0 条悬空），但这是"当下安全"而非"以后安全"。
- **修复**：新增三条源码级哨兵测试（每条规则的 `(topic,row)` 必须能在 KB 解析到；
  不得再出现 framing 死规则；prefer 标签必须能匹配到真实场景行），并给出**可达性下限**（≥45 条唯一 KB 行）。

### F5.12【建议 · 已修】KB 自带的检索建议解析了却没人输出

- **现象**：`_INDEX.md` 的"联合检索高频组合"被 `parseIndex` 解析进 `index.jointSuggestions`，
  但 `cine-kb-cli index` 不打印，Agent 只能自己猜该联合哪几篇；`recipeDispatch` 同理（见 F5.3）。
- **修复**：`index` 打印"↳ 联合检索建议：…"；`enrich` 摘要打印"情绪配方派发 X"。
