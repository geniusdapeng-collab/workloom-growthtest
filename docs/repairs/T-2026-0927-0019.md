## 实现与取舍

**A / POST07**：以实际项目镜号登记表为事实源，修复 SC 专用表达式、裸“换”误判和缺省全片重生成。支持 NC/CF/GR、Unicode 连字符、大小写、自定义镜号；分句中的字幕/封面镜号不串入画面返修范围。未知编号、空/重复登记、无法归因的整句或部分意见、未明确画面范围均停止计划。

**A**：比较两个方案后采用“直接归因层 + 显式依赖图 + 两段执行范围”。只扩关键词并集虽改动少，但无法保证修改字幕后重新做配乐、软轨、终审和交付，也无法避免单镜过滤传播到全片后期。本方案不添加模型调用，保留已有阶段名称，需调用方消费新增 `executionSteps`。

- 场景一：运营人员说“换配乐”，全部原始镜头带真实 SHA-256 复用，只规划 `bgm → mux → master → deliver`。
- 场景二：导演说“NC-01 字幕错了，CF-02 人物畸变”，仅 CF-02 重生成；后期合成、字幕、调色等以完整项目运行，其他镜头复用。
- 场景三：验收人员说“整体高级一点”或点名不存在的镜号，报告明确不可执行，不生成可被旧调用方误跑的部分阶段。

`RevisionPlan` 新增 `executable/blockers/requestedLayers/executionSteps`，保留原有字段。`RevisionReport.renderSubmitApproval` 明确 G8 是 `unverified` 或 `not_applicable`；计划可执行不等于付费渲染获批。复用哈希必须是 64 位十六进制；读取失败有明确原因，禁止用 `missing` 等字符串充当证据。本批无数据库、网络接口、依赖版本或计费逻辑改动。
