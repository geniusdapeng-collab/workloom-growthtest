## 问题与采用的方案

[A] 原商品采集把搜索摘要直接送入回填模型，只校验部分 URL；一个已知 URL 可以掩护同条目的另一个未知 URL。vendor 的缓存复用、batchMode 和 G1 执行时序不能证明本次营销主张实际有网页正文支持。正常营销也没有与叙事同等的正式资格正常路径。

候选一是扩大 URL 白名单并增加 G1 的 approved 字段，成本低，但仍不能证明正文、逐主张支持关系和当前执行归属。采用候选二：服务在取得项目 lease 后执行正文取证、逐主张引用、独立支持关系审核、档案装订和 G1；仅通过后调用创意引擎。完整最终镜头再次审核事实，资格签发及提交均重读同一事实包。此方案增加实际取证及审核成本，换来可审计的来源与执行绑定。

覆盖用户场景：① 明确商品营销，取证后正常走预生产→资格→提交；② 来源不可访问、无评价或无竞品，明确失败或限制允许主张；③ 来源变化或预生产重试，旧的未派发资格失效，已 accepted 的原请求仍按原内容补账。

## 实现与边界

- [A] `fetchMarketingSource` 接受无凭据的标准 HTTP/HTTPS 地址，检查每跳 URL 和全部 DNS 答复，并把已验公网地址绑定至底层 request 的 lookup。最多 4 次重定向、15 秒、2 MiB 解码后正文、24,000 字符；完整正文超限直接拒绝，压缩炸弹、空页、访问验证页和非正文类型失败关闭。原始解码字节与正文分别保存 SHA-256。底层传输注入只供代码测试使用，生产接口没有允许私网开关。
- [A] `validateStageFacts` 使用严格 A1/A2/A3 schema，全部事实叶子逐项对应 JSON Pointer、来源 ID、完整连续原文与位置。缺引证、重复/错指针、未抓取 URL、非页面图片、改写评价和 inferred 主张均被拒绝；source/channel 由真实页面域名产生。此层状态仅叫 `source_bound`，不冒称语义已被证实。
- [A] `prepareMarketingFacts` 的每站支持关系审核通过现有 `reviewStage` 实际读取全文与主张，要求 llm、模型标识、非降级、完整内容 SHA。A1 至少有身份与一个规格/卖点；A2/A3 实际执行后可明确 `no_evidence`，但同时禁止相应口碑/评分/竞品/比较主张。vendor 的 A1–A5 plan/assemble 保持只读。
- [A] `studio-worker` 在当前 StageRunner attempt 内先完成宿主 G1，再执行 `VideoStudio`；G1 被拒绝、auto/fallback、自报通过或不匹配正文摘要均不会执行创意。包入口只接受宿主绑定的三站 raw 和商品查询；清除 metadata 自报档案，强制本次重装订，避免 batchMode 与旧缓存替代宿主 G1。
- [A] 完整最终镜头逐一对照事实主张和用途限制审核；失败不得写成功事实包或完成回执。输出保存 `marketingFactsRef`/SHA。prompt/output/context 中的商品档案引用和媒资投影都指向当前 attempt 的实际 dossier 目录，重试不会继续指向工作区旧档案。
- [A] `production-authority` 为 marketing 增加 G1 和来源资格检查，保留既有 G2–G7、完整请求审核、签名、lease、RLS 和幂等机制。签发与新提交均检查 tenant/workspace/project/run/attempt、24 小时来源有效期、源字节、主张/引文/位置、审核文件、完整镜头与 G1 摘要。已 accepted/finalized 只允许原请求补账，不能换 key 或改内容重发。
- [C] 公开叙事路由已有 `applyRouteToMetadata` 清除 dataMining/brief.product；此批未更改路由。包内宿主配置并不是公开的签名资格，正式生产权仍由服务/数据库边界持有。

无新增数据库表、迁移、公开 RPC 或依赖。事实包 schema 为 `workloom.marketing-facts/v1`，由当前 `production_stage_runs.output_sha256` 绑定，正文与评审文件位于当前项目档案内；不跨项目复用旧包。主要失败码为 `MARKETING_A1_UNVERIFIED`、`MARKETING_SUPPORT_REJECTED`、`MARKETING_PROMPT_FACTS_REJECTED`、`MARKETING_FACTS_CHANGED`、`MARKETING_FACTS_EXPIRED`、`MARKETING_G1_UNBOUND`，都保持不可生产状态。

本批不将网页内容等同于客观真理，不保证公开搜索覆盖全部市场；每站最多尝试 6 个候选、读取 3 个完整来源，并记录遗漏数量与失败原因。图片仍只是来源页里的候选 URL，图片实际字节的生产绑定由后续受控执行批解决。本批不实现白板/口播/Remotion 的资格，也未调用真实付费模型；真实营销质量、AV 和成本验收由主任务继续执行。

网络实现参考前序已核实的 [Node HTTP request 官方文档](https://nodejs.org/download/release/v24.16.0/docs/api/http.html#httprequesturl-options-callback)，通过实际本地 HTTP 服务器验证固定 DNS、重定向与中断；不依赖搜索摘要推断 API 行为。
