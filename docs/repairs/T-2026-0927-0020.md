## 实现与证据

- **A** `StageRunner.run` 的 claim/input/output/finish 是必需证据。认领异常或回执形状无效时不执行；输入失败不执行；输出和终结回执失败不返回成功。执行已返回但持久化未证实时记 `interrupted / RECEIPT_UNVERIFIED`，保留已知产物路径/摘要。日志、心跳与观察钩子仍是旁路。
- **A** `makeLedgerWriter` 认领从当前工作区的项目行计算 attempt，事务锁含 tenant/workspace/project/stage；完成回执必须 UPDATE 一行，或精确命中已有同内容终态，冲突/不存在不能假装成功。
- **A** `startRun` 禁止 `ARCHIVE_ENABLED=0`；租约失败、项目缺失/越权、档案初始化失败都不执行预生产。解锁、日志摘除任一失败不会跳过其它清理，也不会遗留 running 内存投影。
- **A** 执行者、人工恢复和启动扫描共用包含 tenant/workspace/project 的无歧义锁键。取锁结果不明或解锁失败时 `release(true)` 销毁连接，不将可能持有会话锁的连接归还池。事务回滚失败同样销毁并保留两份错误。
- **A** 启动扫描按 `COALESCE(last_heartbeat_at, started_at)` 判过期；持有同一运行事务锁后再次核实过期条件。finding 去重键包含项目/阶段/attempt；报告只在 COMMIT 返回成功后计数。
- **A** 恢复遇到 PG 或本地 meta 的待核实回执、或 interrupted attempt 的输出证据时，返回先对账提示；无断点默认不再启动新预生产。它不是自动对账服务。

官方行为依据：[node-postgres 释放连接](https://node-postgres.com/apis/pool#releasing-clients)、[PostgreSQL advisory locks](https://www.postgresql.org/docs/current/explicit-locking.html#ADVISORY-LOCKS)。本批无依赖升级或迁移。

## 采用的决策与边界

本批选择保留现有文件档案+PG 索引，并把关键证据失败从旁路改为失败关闭。另一方案是直接新建整套权威 production run/artifact schema，但会与后续预占、供应商对账、阶段 DAG 合同耦合，不适合在租约修复批同时落地。本批不实现完整对账、不证明供应商幂等、不覆盖其它 renderer/CLI 入口的旁路治理，不声称所有 vendor 全局补丁并发隔离。

`ARCHIVE_ENABLED=0` 对预生产已不再是允许生产执行的回滚开关；回滚本提交会恢复旧风险，应停用入口后按主控发布流程回退。会话锁编码变化要求正在运行的旧进程先结束，再启动新版本，避免新旧版本持有不同锁键。
