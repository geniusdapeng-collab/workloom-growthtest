## 问题与完成行为

原实现会把唯一档案或旁白 speaker 当成出镜证据；无 active 时取最后一版；`--pin` 只记录数字却复制 active 文件；服装与请求变化可能复用旧图片，部分角度成功也会替换 active。（A，修改前对应 `resolveShotCharacters`、`loadCharacterEntry`、`bindCommand`、`runPortraitAgent`。）

现在按原镜头的明确身份、主体和人数作四态选角：空镜/商品/动物不带人，未知身份或同名歧义保持未验证，明确人数矛盾与冲突 cast 失败。`cast` 可以细化每人的版本和服装，不能取代 `character/characters` 声明。单人旧接口遇到多人镜头不返回首人；参考配额不足或任一人缺照时返回未验证和空参考数组。（A，`resolveShotCast`、`pickCharacterPortraits`、`allocateReferenceSlots`。）

生成计划绑定人物源、服装、模型、端点、尺寸、seed（含0）、角度、提示词、背景策略和锚点实际字节。相同完整请求与当前产物收据一致才复用；更换服装、来源或修改就绪产物必须新建候选。必需四角度和全部已声明角度都核验，半套保留未激活候选，旧 active 不变；同请求恢复只补失败角度。显式激活重读精确版本及文件证据。（A，`buildPortraitPlan`、`runPortraitAgent`、`verifyPortraitSet`、`activatePortraitVersion`。）

两个 CLI 已接真实实现：`--pin` 消费指定版本，项目索引保存精确版本和复制后 SHA；`--wardrobe-id / --wardrobe` 进入生成请求，`activate` 校验后切换指针。未 pin 是绑定当时 active 的快照，后续不会暗中跟随。写档案和项目绑定互斥，JSON 原子替换，来源/输出目录 symlink、路径逃逸、保留标识和目录与档案身份错配被拒绝。（A。）

## 方案、场景与边界

| 候选 | 优点 | 代价与风险 | 决策 |
|---|---|---|---|
| 仅补人物关键字和文件名后缀 | 修改少，保留旧默认路径 | 无法证明版本/服装/字节，仍可能把空镜变人物或覆盖旧版 | 不采用 |
| 原镜头解析 + 明确版本 + 请求/字节收据 + 完整候选激活 | 能解释每个人、每张图及换装失效原因；错误与不适用清晰 | 老档案只有当前字节证据；全入口仍需调用方消费四态 | 采用 |

三类已覆盖的使用场景：

1. 无人物手表营销镜：项目有人物档案和旧 `portraits` 也不绑定人；不用此规则会无意带入人脸。
2. 双人叙事镜：按原顺序保留两个身份与各自服装/版本；不用完整多人接口会只带首人的参考。
3. 主角换红色外套：新服装先形成独立候选，缺侧面时旧服装仍 active，补齐再激活；不用候选隔离会半套换脸或复用旧衣服。

本批 P0：主体/身份/人数、版本与字节、服装候选、完整激活、CLI 参数真实消费及并发写保护。P1（整合任务）：服务端权威档案及当前生成资格绑定、全链路调用消费四态。P2（后续质量实验）：按实际图像评人脸同一性与跨镜服装视觉执行，不能用当前哈希检查替代。

不做：不改 vendor，不改 fullchain 或服务端生产出口，不接付费模型，不把本地文件 hash 当平台授权，也不把 `asset://` 格式有效当授权有效。旧档案标记 `legacy-current-bytes-only`；外部素材 ID 标记 `external-asset-id-not-provider-verified`。本批无法证明实际图片中的人脸与衣服符合描述，最终真实模型与盲评属于完整任务的后续验证。

## 数据与接口

`PortraitSet` 新增 `workloom.portrait-set/v2`、`status=candidate|ready|failed`、源/请求/服装 hash、角度精确路径、当前字节收据和实际请求 hash。沿用文件库，无数据库表或索引迁移。active 与 pinned 都只选准确版本；inactive/newest 不作兜底。

调用整合合同（均已由 `src/index.ts` 导出）：

```ts
const library = loadCharacterLibrary(libraryRoot);
const cast = resolveShotCharacters(originalShot, library);
// failed / unverified 必须阻断；not_applicable 不绑定人物；passed 才取 characters。
const slots = allocateReferenceSlots({ characters: cast.characters, venueRefs, maxRefs: 4 });
// 检查 slots.status，禁止丢弃身份后继续提交。

const pinned = loadCharacterEntry(characterDir, { pinnedVersion: 2, wardrobeId: "red" });
const multiple = pickCharacterPortraits(projectPortraitIndex, originalShot);
// multiple.status passed 才取 picks；每个 pick 含 sourceHash/version/assetHash/scope。
const refs = composeShotReferences({ portrait: null, portraits: multiple.picks.map(p => p.file!), venueRefs });

const plan = buildPortraitPlan(profile, { wardrobeId: "red", model, baseUrl, seed: 0 });
const candidate = await runPortraitAgent({ libraryRoot, characterId, apiKey, model,
  config: { wardrobe: { id: "new-red", name: "红色外套" }, activate: false } });
await activatePortraitVersion(libraryRoot, characterId, candidate.version);
```

主要错误：`PORTRAIT_VERSION_CONFLICT`（同版本不同来源）、`PORTRAIT_VERSION_OCCUPIED`（就绪文件已变/孤立文件）、`PORTRAIT_ACTIVATION_UNVERIFIED`、`PORTRAIT_ARCHIVE_BUSY`、`PORTRAIT_INPUT_CHANGED`、`CHARACTER_PATH_INVALID`、`PORTRAIT_WARDROBE_AMBIGUOUS`。参数/外部失败保留可诊断状态；下载失败不宣称生成成功，同次执行的普通网络失败不会自动重发同角度付费请求。跨次运行缺失产物的恢复仍需服务端权威任务与供应商回执去重，本地候选不能代替该资格。
