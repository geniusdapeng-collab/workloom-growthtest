# 出镜人物 成片反馈与制作契约修复

任务卡：[T-2026-1005-0001 / #103](https://cnb.cool/workloom-ai/workloom-growthtest/-/issues/103)。

本批属于 Growthtest 隔离副本。产品所有者已授权修复成片反馈、发布上一轮本地生产修复，并分析制作耗时与 Codex 接入阻力；不向其他仓分发，不增加付费视频生成。

已落盘的真实素材证明：第 1、3 镜原生台词识别通过，但统一后配参数替换了它们。封面未进入主片由关闭参数与旁路副本两者共同造成；字幕烧录在没有封面时自动添加了取自镜头清单的开场标题。第 3 镜的人物和服饰连续性缺陷保留为失败样本，不用再次生成掩盖。

本批已把这些要求落实为生产契约：出镜对白保留原生音轨；后配仅用于明确画外音；最终发布片首帧嵌入干净封面且保持时间轴；额外标题须显式声明；授权角色、统一参考素材、服饰与身份检查分别留证，缺证据保留内部候选；交付检查计算实际摘要并核对声明元数据。

候选方案已确定：封面前置若干秒会改变片长与字幕偏移；首帧替换保留声音、时长和字幕时间轴，作为默认正式交付方式。人物颜色检查只作服饰信号，身份需要带授权参考图的独立视觉回执，技术分数不能代替。

## 最终行为和入口

## 人物合同与异常路径

`buildCharacterReleaseContract` 统一角色 canonical refs、授权登记基准和显式 wardrobe；`generationIdentityLock` 写入实际生成提示词。专用 producer review 通过 `buildCharacterIdentityReviewRequest` 绑定当前生成提示词、片段、授权参考图与观察帧 SHA，再由 `adaptCharacterVisualVerdict` 和 `assessCharacterRelease` 判断 canary/发布。一般审美 `review-policy=off` 不能关闭此事实来源要求。

人物视觉判据采用独立参考图评审。候选二为 RGB/服装色差或技术分数代理：执行成本更低，但不能证明脸部身份，也无法证明明确款式；不采用。视觉服务不可用、降级、回执畸形、参考来源不明、输入/输出被改或任一镜头被拒时，结果为内部候选；不伪造绿色，不再拿自己生成的首帧认证自己。

阶段账本新增 `requestInputVerified`、实际 requestHash、原始 prompt/raw/reference SHA 和音频 policyHash；本地受理 journal 用于安全 GET 接续。交付清单保存封面装配回执、标题来源、角色发布合同和素材披露元数据；没有数据库表结构变更。文件指纹、source/recipe 与最新回执决定缓存复用，不以 mtime 或存在性代替。

父服务在预占额度前独立检查冻结音频、画幅、源分辨率、时长、引用数量与当前参考字节。真人素材模式禁止另一个首帧覆盖登记授权组。第一人物镜头按本次选择和同一角色确定；继续该角色前复核原供应商档及当前片段，其他人物或产品镜不授予其身份许可。

`workloom.film-video-submission/v1` 回执只从本次真实父通道响应取得，绑定实际编译请求、受理任务与下载字节；它不是签名或人脸证明。供应商原档单独保留，副本时长归一通过父通道 `media.fetch` 的 `normalizeToSeconds` 执行，必须等于冻结镜头时长。变速后的独立 SHA 和原档 SHA 分别复核，不能覆盖原档，也不能用变速产物的 SHA 冒充供应商原字节。合法多行提示词按原始 UTF-8 字节绑定。

专用人物通道不受一般 off/advisory 策略控制。父服务重新读取受控登记源，独立探测视频时长、重建两个实际时间点的 JPEG 并核对子进程送审帧，再构建自己的完整请求。真实 producer review 一次查看完整视频抽帧、显式帧和登记原基准；模型、完整字节回执或注册资料不可用时仍未验证。子进程不得提交自己的 bindings 或选择父服务资料库。

本次真实 CI 的提交规范门禁曾把已合入 main 的历史标题再次归入 PR：预合并 checkout 的 `before..HEAD` 与本次 source 的新增提交并非同一范围。最小修复按 CNB 的 source/target 完整 SHA 和预合并双亲核实 `target..source`，并单独校验实际 source tip 的自定义 merge 标题。缺对象、缺字段、过期绑定、空范围或不符双亲均失败关闭；多提交范围在浅克隆中也拒绝，流水线仅在浅克隆时先补齐 Git 历史。既有格式、任务号、过渡期及标准 Merge 豁免规则不改。真实 Git 分叉、浅克隆夹具和原协议回归接入静态门禁；这项修复只纠正检查对象，不豁免本次新增提交。

随后真实 Prepare 日志显示，CNB 在 target 已是 source 祖先时用普通 `git merge` fast-forward，工作区 HEAD 为 source，而状态回执另绑定平台预合并 SHA。此时仍读取平台声明的实际 merge 对象，核对 target/source 完整双亲及工作区树；source HEAD 还须满足 target 祖先关系。不同 hash 的预合并 wrapper 仅在完整双亲和树相同时接受，不能把 source 单独通过冒充包含 target 的合并通过。CI 仅在平台 merge 对象缺失时按已验证的 40 位十六进制 SHA 取得对象，不改环境变量或检查结果。
