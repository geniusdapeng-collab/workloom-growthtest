# 出镜人物 成片反馈与制作契约修复

任务卡：[T-2026-1005-0001 / #103](https://cnb.cool/workloom-ai/workloom-growthtest/-/issues/103)。

本批属于 Growthtest 隔离副本。产品所有者已授权修复成片反馈、发布上一轮本地生产修复，并分析制作耗时与 Codex 接入阻力；不向其他仓分发，不增加付费视频生成。

已落盘的真实素材证明：第 1、3 镜原生台词识别通过，但统一后配参数替换了它们。封面未进入主片由关闭参数与旁路副本两者共同造成；字幕烧录在没有封面时自动添加了取自镜头清单的开场标题。第 3 镜的人物和服饰连续性缺陷保留为失败样本，不用再次生成掩盖。

本批已把这些要求落实为生产契约：出镜对白保留原生音轨；后配仅用于明确画外音；最终发布片首帧嵌入干净封面且保持时间轴；额外标题须显式声明；授权角色、统一参考素材、服饰与身份检查分别留证，缺证据保留内部候选；交付检查计算实际摘要并核对声明元数据。

候选方案已确定：封面前置若干秒会改变片长与字幕偏移；首帧替换保留声音、时长和字幕时间轴，作为默认正式交付方式。人物颜色检查只作服饰信号，身份需要带授权参考图的独立视觉回执，技术分数不能代替。

## 最终行为和入口

| 触发 | 原行为 | 本批行为 |
|---|---|---|
| 出镜讲话 + `--narration-unified` | 原生音画已合格仍被统一 TTS 替换 | 提交前拒绝；原生音频关闭也在付费调用前拒绝 |
| 原生台词识别不通过 | 后期换音轨继续走 | 停线并保留失败样本；不以 TTS 修补出镜口型 |
| GET 接续已受理任务 | 下载/恢复记录混入新渲染次数，输入可能被冒认 | 受理 ID 去重；没有原始 requestHash 时来源保持未验证，回收媒体只能内部候选 |
| 主片、软字幕、风格变体交付 | 封面另存旁路视频，正式视频仍用旧来源 | 通过官方封面工位出稿并装配发布首帧，回执输出实际进入交付文件 |
| 未显式给开场标题 | 从片名或 cover hook 自动推导并烧录 | 只有 `--opening-title` 的显式文案可以烧录；缺省不加额外标题 |
| 人物参考和服饰漂移 | 技术通过或生成镜头首帧被当作身份锚点 | 授权登记参考图和显式服饰合同锁定；专用视觉回执与当前 prompt/clip/reference SHA 绑定 |
| canary 或部分人物镜头通过 | 可能被误用作其他镜头发布许可 | canary 只授权继续生成；发布仍逐镜核验实际身份和服饰回执 |
| 仅跑 mux/master/deliver 或复用旧字幕版 | 同路径的旧 TTS/后期文件可进入发布 | 实际源镜、voice、compose、color、subtitle、danmaku、bgm、sfx 逐边绑定当前来源；缺回执或错误上游拒绝 |
| Codex 计划与交付检查 | 建议命令缺参数，fps 写死，只检查文件存在 | 返回完整 argv/cwd/产物目录，fps 读作者声明；有阻塞不返回命令；交付分块核验 SHA256/bytes |

复用当前 `speechMode`，不增加第二套音频业务枚举。合同错误码由 `film-audio-policy.mjs` 与 `film-publication-policy.mjs` 返回。官方 CLI 和 Agent 能力共享 `film-render-ledger.mjs`；无有效任务 ID 的调用独立列未知，台账不作为费用账单。

## 人物合同与异常路径

`buildCharacterReleaseContract` 统一角色 canonical refs、授权登记基准和显式 wardrobe；`generationIdentityLock` 写入实际生成提示词。专用 producer review 通过 `buildCharacterIdentityReviewRequest` 绑定当前生成提示词、片段、授权参考图与观察帧 SHA，再由 `adaptCharacterVisualVerdict` 和 `assessCharacterRelease` 判断 canary/发布。一般审美 `review-policy=off` 不能关闭此事实来源要求。

人物视觉判据采用独立参考图评审。候选二为 RGB/服装色差或技术分数代理：执行成本更低，但不能证明脸部身份，也无法证明明确款式；不采用。视觉服务不可用、降级、回执畸形、参考来源不明、输入/输出被改或任一镜头被拒时，结果为内部候选；不伪造绿色，不再拿自己生成的首帧认证自己。

阶段账本新增 `requestInputVerified`、实际 requestHash、原始 prompt/raw/reference SHA 和音频 policyHash；本地受理 journal 用于安全 GET 接续。交付清单保存封面装配回执、标题来源、角色发布合同和素材披露元数据；没有数据库表结构变更。文件指纹、source/recipe 与最新回执决定缓存复用，不以 mtime 或存在性代替。

## 验证与发布边界

验证包括失败断言、已落盘原生媒体负例、真实 FFmpeg 首帧/音轨/软字幕守恒、能力入口与恢复回归、官方 CLI AST 提取的发布入口与五层后期来源负例、独立修复/验收会话、隔离数据库上的 `release:gate`。本地测试使用自有夹具和 mock，不据此宣称现实模型口型或人脸认证通过。旧 GT-03 白衣失败素材与原有交付片不被改写成已修复合格作品。

上一轮必要本地补丁一并纳入：受理先落盘与 GET 接续、真人主档 URI 血缘修复、BGM 峰值响度与实测 BPM、不同变体选曲、封面空设计回退。声明直混来源记录为 `declared-unverified / stemsVerified=false`，部分阶段复跑从当前有效历史回执恢复元数据。

修复回归通过不等于远端发布完成。发布通过受保护 PR #104，需实际 CNB 检查和独立平台评审；桌面 release helper 仍声明 Growth 发布目标，本任务不启动错误目标的安装器流程。回滚使用实际合并提交的 revert。
