# 当前产物血缘与局部返工执行闭合

任务卡：https://cnb.cool/workloom-ai/workloom-growth/-/issues/245

## 问题与交付行为

旧成功记录、文件修改时间或旧配音可使当前被拒绝或已经换源的媒体继续参与合成；带 `--only` 的返修还可能把项目后期缩成一镜。本批改为保存执行前输入、执行后输出和评审对象的 SHA-256，按项目、镜号、源输入、配方与最新裁决核对。最新失败覆盖旧成功；未核实、降级和缺文件不得取得生产通过。终审通过后才原子晋升最终母版。

功能场景：换一个镜头后阻止旧配音复用；只修 NC-02 时逐镜步骤只处理 NC-02 而项目后期保留完整镜号；审片结束后文件被替换时拒绝将新字节冒充已审产物。

## 范围与假设

P0：当前产物字节血缘、门检查校验、失败终态、配音候选晋升、返修组件调度。P1：统一服务资格和可信封签在独立任务落地。P2：跨仓移植和真实双管线成片验收在整体任务继续执行。

本批的 JSON 血缘只是本地一致性证据，不是供应商回执或服务签章。具备文件写权限的调用者不能凭此取得正式交付资格。已有无血缘日志不兼容放行，需要从当前源重新执行相应阶段。默认不承担恶意管理员对同一内核与密钥的攻击隔离。

## 方案选择

方案一继续按 mtime 和任一历史成功复用，实现成本低，但同路径替换、旧失败、不同项目或不同配方仍会误通过。方案二按内容哈希、最新记录及执行前快照判定，增加文件读取成本与旧缓存重建成本，能明确拒绝上述反例。本批采用方案二；对大媒体的读取成本仍须在真实出片阶段测量。

## 数据与接口

`production-lineage/v1` 保存 projectId/sourceHash/runId/stage/shotId/recipeHash/status、输入输出 path/realpath/sha256/bytes、不适用理由与错误。状态为 passed/failed/unverified/not_applicable；不适用必须有原因。日志改为 `logs/<project>/stages.jsonl`，不再共享项目成功记录。

`captureLineageInputs` 在工具调用前保存输入；`createLineageReceipt` 核对工具执行期间输入与审片后的媒体字节；`stageLineageApproved` 逐镜读取最后裁决；`reusableLineageArtifact` 要求候选属于该裁决输出且直接输入相连。

`executeRevision` 从反馈和实际素材哈希重新规划，不接受调用方声明的 executable；调用登记的阶段适配器，逐步检查未选镜头不变，子过程非零或异常即停。CLI `--execute-revision` 执行规划的组件；默认仅生成计划并如实写 planned。选镜阶段与完整项目阶段分别调用，修订上下文进入生成提示和执行日志。后期各语义修改参数的完整映射仍属于后续集成，不把调度 completed 当成修改效果验收。

门检查拒绝空数组、重复判据、非布尔值、非法分值和降级裁决。未知阶段、非法镜号、重复镜号、越界路径、选镜夹带项目后期、正式流程豁免参数均非零退出。母版缺上游、缺音画证据、缺字幕证据或最新拒绝均不能发布。

## 关键流程与失败路径

源文件单次读取并绑定；运行中源文件改变立即停止。每个工位调用前拍输入快照，执行后记录实际字节；生产评审的文件哈希再核对。输出路径已有文件时先保留到唯一 previous 路径，防止失败子过程把旧输出误作本次成果。

逐镜缓存同时满足请求缓存、当前血缘及最新门结果；旧回执不能在新请求中变成成功。素材后期模式缺已核实的原始模型回执直接拒绝。调色失败不能套用被拒绝版本的批准；退回原片必须另行通过当前原片评审。

合成前检查全部应有逐镜与配音证据；旁挂字幕清单和实际字幕一同纳入输出哈希。终审在工作候选上执行，通过后复制到新候选，检查源与候选字节一致再晋升。交付必须当前母版证据通过。
