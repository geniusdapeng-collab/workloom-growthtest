## 需求、方案与取舍

使用者是从服务预生产镜头发起生成的工作台用户和受控 CLI。用户必须能选择当前镜头、查看真实计划时长与报价、通过最终请求审核，再提交一次；客户端手写脚本或 `approved:true` 不能变成生成资格。失败或不确定接受结果不能通过重试、更换幂等键或重新签发随机脚本编号重复调用供应商。

候选一是在 CMS approved 状态上追加布尔校验，代码少，但无法证明内容来源、完整供应商请求、最新裁决和请求字节不变，拒绝采用。候选二是服务读取本作用域当前成功预生产档案，审核并签发不可变的完整请求资格，提交仅消费该资格；引入一张表和独立签发密钥，能够验证身份、版本、时效、来源和最终字节。本批采用候选二。

假设签发服务、数据库所有者和服务工作目录属于受控信任域；客户端不能取得签发密钥。资格有效期 30 分钟。图文证据或提示词超过可完整审核的上限时明确拒绝，不静默裁剪。多项目并发受数据库连接池约束，项目签发/预生产排他，提交持共享租约；租约与短事务复用同一个连接，避免池容量为 N 时 N 个请求各自持一个连接、再等待第二连接的死锁。模型网络期间没有数据库事务。

## 数据、接口与正常流程

`0045_production_qualifications.sql` 新建 `production_qualifications`，记录 tenant/workspace/project/shot、source stage run/attempt/output SHA/prompts SHA、canonical script ID/version、model/provider/provider model、完整 compiled request/request hash/payload hash、参数/mode、passed/failed/unverified 三态、监制回执、发行者/key ID/signature/issued/expires/actor。`seq` 形成镜头最新裁决顺序，索引覆盖 scope/project/shot/latest 与 script。表强制双作用域 RLS，只授予 SELECT/INSERT；触发器阻止 UPDATE/DELETE并核对当前来源与脚本作用域。已签发脚本正文/身份/字段不可变，只允许提交状态投影改变。

脚本保护触发器以迁移所有者运行，固定 `search_path=pg_catalog,public,pg_temp`、表名限定 `public`，撤销 PUBLIC 对该触发器函数的直接执行权限。实测发现 invoker 模式下错误 tenant GUC 会隐藏资格行而绕过保护，新增反例后修复。实现依据：[PostgreSQL 17 CREATE FUNCTION](https://www.postgresql.org/docs/17/sql-createfunction.html) 与 [Row Security Policies](https://www.postgresql.org/docs/17/ddl-rowsecurity.html)。

- `video.production.shots({projectId})`：只读当前作用域服务器档案与摘要，返回 source stage/attempt/prompts SHA 和各镜头 shotId/durationSec/prompt/fields/prompt SHA。无需先手工创建 CMS 行。
- `video.production.qualifyShot({projectId,shotId,modelId,params,mode?})`：从服务档案编译，实际审核完整 endpoint/model/bodyJson，成功返回 qualificationId/token/scriptId/scriptVersion/modelId/params/mode/requestHash/payloadHash/promptSha256/expiresAt。拒绝外部正文、文件路径、评分、passed、自报 scope。失败裁决也追加保存，最新拒绝使旧通过不能继续消费。
- `video.render.submit({qualificationToken,allowOverage?,idempotencyKey?})`：按 token 加载 canonical 输入；兼容旧字段但只允许逐项相等，不接受覆盖，不再重新夹紧时长或追加 prompt 标签。费用围栏与内容资格分别验证；mode=auto 不改变服务禁止自动审批的配置。
- `loadQualifiedRenderInput(app,scope,token,env?)`：给服务路由/受控 CLI 加载 canonical script 全文与字段、模型/参数/mode、compiled 请求、request hash和是否仅补账。客户端不持签发密钥。

使用场景：① 新项目预生产完成，Studio 直接列出服务镜头、选择某一镜审核生成；② CMS 工作稿与档案一致时可从片库审核生成，未保存修改或与服务正文不一致时提示重新预生产；③ 网络回执丢失后重试签发相同镜头请求，已派发请求复用原资格与幂等键，accepted/finalized仅补账，unknown/submitting不盲目重发。

错误类别包括缺少当前预生产、旧/降级/裁剪档案、缺失门证据、字节或路径变化、无签发密钥、请求过长、参数覆盖、模型不可用、资格过期/错 scope/篡改/被最新裁决替代、项目繁忙、供应商接受结果不确定与已接受待补账。以上均在外部生成调用前或持久预占保护下处理，不能落回远端 mock 或未审核的 fallback。

部署须在服务进程配置独立 `WORKLOOM_RENDER_SIGNING_SECRET`（至少 32 字节），可选 `WORKLOOM_RENDER_SIGNING_KEY_ID`（默认 render-v1）。该密钥用于 `purpose=render-submit`，不能替代 delivery 签名密钥或生成最终交付封签。
