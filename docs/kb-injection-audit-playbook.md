## 一、为什么这块重要（已发生的真实事故）

这些都是**真机交付链上实际发生过**的问题，不是假想：

1. **提示词侧整段失效（NaN 事故）**：`platePrompt()` 数组里残留 diff 标记 `+`，
   通用空间物理不变量那一行求值成 `NaN` —— 评审侧有这条纪律、提示词侧没有，
   于是"无头之桥"（桥面两侧直接临水、看不到两端连接）屡次通过评审却屡次复现。
2. **题材错配**：糖粥/海棠糕镜头被注入"咖啡杯热气"（KB 的蒸汽行示例是咖啡专用）。
3. **场景错配**：白天支巷挂红灯笼的镜头被注入"烛火小而稳定…暖光晕开"（烛火行只判 `lantern`）。
4. **道具串场**：点心镜头被注入"酱汁油亮挂壁"（食物质感行只判"食物"）。
5. **动作误读**："发丝随转头轻摆"被读成"回头"→ 注入"行走中回头看向镜头"，与卡片写明的"全程正脸"冲突。
6. **否词吞噬**："**无光污染**的星空银河"被否定剥离整段吃掉 → 星空专项光圈规则不触发。
7. **模板占位符下发**："画面内**[元素]**自行运动"原样进提示词，模型当成字面文本。
8. **语言自违**：卡片【语言约束】要求全中文，KB 行却附英文括注（`（bright afternoon sunlight…）`），监制判"自相违背"。
9. **时段自相矛盾**：上午镜头被注入"明亮的**午后**阳光"（斜光行措辞只写了午后）。
10. **字段位置错**：丝绸光泽这类**服装材质**被注入到 `props`（道具）字段，读起来像"画面里飘着一块丝绸"。

**共同点**：问题都不在"模型不行"，而在**注入层**——规则触发条件、措辞归属、字段落点、否词处理、模板完整性。
这一层是确定性的、可穷尽、可测试的，因此值得专项审计。

## 二、审计对象（一张图看清数据流）

```
知识库（19 篇 Markdown）
  bundles/ai-video/library/cinematography-kb/*.md
        │  解析（章节/表格/要点行/决策树）
        ▼
注入引擎  bundles/ai-video/connectors/cine-kb-bridge/core.mjs
   ├─ parseApertureKnowledge()  光圈顾问（§二 档位表 / §三 题材行 / §八 决策树）
   ├─ injectionContext()        词面信号（时段/天气/主体/运镜/道具/专项意图…）
   ├─ INJECTION_RULES[]         确定性注入表（field / when / topic / row）
   ├─ enrichShotCard()          注入执行 + trace（applied / picks / explored / suggestedParams）
   └─ recommendAperture()       光圈档选择 + 意图分支 + 手部纠偏
        │
        ├─► 镜头卡（shotlist.json 的字段被就地增强：lighting/composition/props/costume…）
        │        │
        │        ├─► platePrompt()（关键帧提示词，含空间物理不变量与桥类硬约束）
        │        └─► prepareShotPrompt()（25/30 字段提示词 + 交付闸）
        │
        └─► trace 落盘：work/<vm-work>/cine-kb/<shotId>.json（审计的一等证据）
```

**审计必须打到的三处**：
1. **解析层**：KB 原文 → 结构化（表格行、要点行、决策树、模板占位符）是否漏parse/错parse；
2. **决策层**：触发条件（`when`）与场景语义是否一致（该触发没触发 / 不该触发却触发）；
3. **落地层**：短语措辞、字段归属、长度上限、语言口径、幂等与去重。

## 三、审计维度（12 维 · 每维都有可判定检查单）

> 每维给出：**要问的问题 → 判据 → 怎么测**。全部落到脚本/用例上，禁止只用眼睛看。

| # | 维度 | 要问的问题 | 判据 | 怎么测 |
|---|---|---|---|---|
| A1 | 触发召回 | 该有知识行吗？ | 场景 → 期望命中的行（人工标答表） | 场景矩阵逐条比对（见 §四） |
| A2 | 触发精度 | 不该有的行进来了吗？ | 否命题：不应命中清单 | 反例集（水下/冰面/白天灯笼/无人物…） |
| A3 | 措辞归属 | 这条行说的是这个意思吗？ | 行文本与场景名词一一对应（咖啡≠糖粥） | 关键词互斥表：行文本出现 `咖啡` 时场景必须含咖啡 |
| A4 | 字段落点 | 落在对字段了吗？ | 材质→costume、道具→props、光位→lighting、档位→depth_of_field | trace.applied 的 field 与行语义比对 |
| A5 | 否词处理 | "不要/无/不含"被正确处理了吗？ | 否定短语不得产生正向信号；限定否定不得吞掉中心词 | 否词集（"无光污染的星空""不横移不环绕""避免日落"） |
| A6 | 时段一致性 | 注入的光与卡片时段一致吗？ | 同一卡内不得出现两个互相冲突的时段词 | 时段词共现检查（上午×午后、白天×夜色…） |
| A7 | 模板完整性 | 下发的是不是模板原文？ | 提示词正文不得含 `[占位符]`/`NaN`/`undefined`/`[object Object]` | 退化哨兵断言（已在 plate-prompt 单测里） |
| A8 | 语言口径 | 与卡片【语言约束】一致吗？ | 默认全中文；英文关键词只进 trace | 拉丁词扫描（排除画幅/编码/时间码/路径） |
| A9 | 长度与去重 | 会不会撑爆/重复？ | 字段级一条、总量 ≤5、单字段 ≤320 字、同一行不重复落多字段 | trace.applied 计数与同一 `topicId#intent` 去重 |
| A10 | 可溯源 | 每条注入都能回到 KB 原文吗？ | trace.picks 能定位 `topicId + intent`，且文本与 KB 原文一致（去掉英文后逐字比对） | 溯源一致性脚本（KB 原文 vs trace） |
| A11 | 幂等与可复跑 | 跑两次结果一样吗？ | 同输入 → 同输出（无随机、无时序依赖） | 双跑 diff（trace 逐字节比对，除时间戳） |
| A12 | 与评审链一致 | 提示词侧与评审侧纪律一致吗？ | 提示词里写死的约束，评审侧有同名类目；反之亦然 | 双方清单比对（plate-prompt 常量 vs PRODUCER_RUBRICS） |

## 五、执行计划（建议 6 个阶段 · 每阶段都有可交付物）

### P0 建账（半天）
- 冻结基线：`git rev-parse HEAD`、KB 版本、`kbStatus()`（篇数/条数/缺篇）；
- 跑一遍现有回归：`pnpm exec vitest run bundles/ai-video/connectors/cine-kb-bridge packages/video-studio`；
- 产出 `work/kb-audit-baseline.md`（覆盖率声明：精读/机检/抽样/未读各多少）。

### P1 解析层穷尽（1 天）
- 逐篇 KB 做"结构化覆盖率"：每篇的表格行/要点行/决策树被解析进 `kb.aperture` / `kb.topics` 的比例；
- 找出**所有含占位符**（`[...]`）或模板句的行，登记"能否实例化、如何实例化"；
- 产出 `docs/kb-parse-coverage.md` + 解析层单测（每类语法一条）。

### P2 决策层穷尽（1–2 天）
- 用 §四 矩阵（含扩展）跑 `enrichShotCard`，生成"场景 × 命中行 × 字段"大表；
- 对每条命中问三句：**该不该命中 / 措辞对不对 / 字段对不对**；
- 反例集（A2/A3/A5）单独成组：任何"不该命中"出现即算缺陷；
- 产出 `docs/cinematography-kb-audit-roundN.md`（沿用既有格式）+ 回归用例。

### P3 落地层与评审链一致性（1 天）
- A7–A12 全部脚本化：退化解、语言口径、长度/去重、溯源一致性、幂等、双清单比对；
- 真机 A/B：用**真实镜头卡**（`work/film/shotlist.json` 之类）跑 before/after，逐镜判读（脚本模板已有 `/tmp/kb-ab-regress.mjs`）；
- 产出 `docs/kb-injection-invariants.md`（把 12 维写成"不变量清单"，供以后当验收单）。

### P4 缺口提案（半天）
- 把"KB 缺行"逐条登记（见 §七 台账），写提案（建议行文案 + 依据 + 影响面），**不改 KB 原文**；
- 产出 `proposals/kb-gap-*.md`。

### P5 长跑与回归（持续）
- 每次改注入规则：先跑矩阵 → 再跑真机 A/B → 最后跑交付链（`full-chain-film.mts`）；
- 每轮审计结束把新增/关闭的缺口更新到本文件 §七（保持"活台账"）。

## 八、报告格式与证据纪律（沿用舰队规范）

每轮审计报告必须包含（缺一即视为未完成）：

1. **覆盖率声明**：范围内文件数 / 精读 / 机检 / 抽样 / 未读（逐项列出未读原因）；
2. **证据分级**：A＝代码精读；B＝全量机检；C＝抽样；D＝推断（B/C/D 不得用"确认/全部/通读"这类 A 级措辞）；
3. **修复清单**：每条 = 现象 → 根因（文件+行/函数）→ 修复 → 回归用例 → 真机证据；
4. **缺口台账更新**（§七 增删）；
5. **收尾报告**：已完成/未完成/自主追加事项/假设/置信度/建议复核；
6. **自检表**（覆盖全范围？没把可自主事项推给用户？结论可验证？经得起资深工程师逐行审查？）。

## 十、边界（明确不做什么）

- **不改 KB 原文**：缺口只登记 + 提案，不改写知识库内容（KB 是内容资产，改动要走评审）。
- **不为了过闸而放宽闸**：闸（门）反映的是真问题，修的是注入层，不是把判据删掉。
- **不做与注入无关的重构**：发现的问题记进台账，不在本任务里顺手重构别处。
- **不隐瞒**：测不出来就说测不出来（例如"人工判读"要标 C 级），禁止用"应该没问题"结案。
