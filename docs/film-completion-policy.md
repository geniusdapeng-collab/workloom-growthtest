# 高完成度作品优先

给用户或客户交付高完成度作品是影视制作的最高优先级。完整动作、整句口播、叙事收束与自然观看节奏高于名义总时长。用户说“30 秒”，完整的 28、32、35 秒作品允许保留。不得为凑 30 秒把一个完整的 4 秒多动作压成或截成 2 秒，也不用补帧、冻结、循环或填充。

读者是调用制作能力的 AI 工作台、导演规划与后期工位。此规则让创作者围绕作品完成表达，避免数值约束把合理素材变成奇怪镜头。渲染后素材默认采用的现行规则继续生效；没有新增质审模型、用户专业问卷或付费返工。

## 具体场景

1. 获客片标称 30 秒，三段完整源片合计 28 秒。规划与 spec 接受完整 28 秒，交付写明目标 30、实测 28、差值 −2；不补两秒静帧。否则用户会看到拖沓或无意义片尾。
2. 出镜人物 口播加产品展示合计 32 或 35 秒。完整保留动作、原声与 CTA，按真实钟排字幕和切点。否则口播或发卡动作可能被截断，或人物被压速。
3. 客户明确提供“素材不得超过 30 秒”的投放位合同。登记显式硬上限，超过时先修订镜头计划。对已生成的 30.125 秒原片同样不能截去端点帧蒙混达标；应保留来源并给出需要修订的具体冲突。否则投放规格与真实文件不一致。

## 方案选择与执行

| 候选 | 行为、成本和风险 | 适用前提 |
|---|---|---|
| 继续精确凑总秒数 | 后期需要裁切、变速或填充；动作与整句口播可能被破坏，还掩盖源片真实钟 | 只适用于已明确允许且能独立证明内容完整的专门剪辑合同，本标准生产不采用 |
| 创作目标与显式硬上限分开 | 共用纯策略模块，保留源片；目标偏差有回执。硬上限冲突在生成前返回修订要求，已有片保留 | 本系统默认；采用此方案，优先完整表达和真实来源 |

`packages/video-studio/src/film-completion.mjs` 是唯一时长策略。无网络或媒体副作用。调用链实际执行：

- `director-planner.ts` 在每个文字岗位提示中传入最高优先级指导和时长意图；有明确动作的规划源镜登记 `lockTrim=true`，现有导演 EDL 和节奏反馈因此不能按模板比例截短动作。规划回执绑定实际镜头池总时长。
- 只读 `productionPlan` 增加完成度前置检查，合法目标偏差仍提供现有正式 CLI 命令；显式硬上限溢出则不提供执行命令。
- `full-chain-film.mts` 在生成之前读取完整源卡并校验政策。连续性不再把创作目标当相等硬闸；spec 校验完整镜头合计和显式硬上限。单镜供应商 4–12 秒整数、语速、参数、授权等已有预检继续执行。
- `standard-post-contract.ts` 从冻结原稿字节构建 v2 合同。原稿总秒数是目标，源片逐镜完整帧范围、顺序、零入点、速度 1、同文件原声继续绑定；实测完整钟决定 compose、配乐、字幕、母版和文件名。
- 正常交付与独立标准后期交付清单均包含 `completion`：目标、实测钟、差值与政策。消费代码摘要包含纯策略文件。原稿和首次受理回执不改写；旧派生 v1 合同须从规范原片重新构建，不将旧合同哈希当新政策证明。

## 输入与失败路径

```json
{
  "durationSeconds": 30,
  "durationIntent": { "hardMaximumSeconds": 35 }
}
```

`durationSeconds` 是可省略的创作目标（标准原片合同仍要求其为正数）；`durationIntent.targetSeconds` 可显式声明同一目标，二者冲突拒绝。`hardMaximumSeconds` 必须来自真实明确要求；缺省没有硬上限。自然语言中的单一秒数只解析为软目标，不推断硬上限；歧义保留原话，不猜数。

政策数值必须有限且为正；未知政策字段、目标/硬上限冲突和政策篡改抛 `FILM_COMPLETION_INVALID`。完整计划或源钟超过显式硬上限抛 `FILM_COMPLETION_HARD_LIMIT`，不触发自动裁切、压速或新增生成。文字模型最多按已有有界重试修订，仍不合规则停止媒体启动。网络未知受理状态仍按现有防重复账本处理，时长规则不创造重发资格。

正常标准后期的每段完整帧数还须与该镜供应商请求相符，最多保留一个真实端点帧。28/32/35 秒允许的是完整镜头池合计与软目标的偏差，不是允许伪造单镜测量或剪坏原片。音频检查记录技术钟，不认证发音或音素口型。

## 功能优先级与边界

| 优先级 | 可验证行为 | 用户不用它会怎样 |
|---|---|---|
| P0 | 目标与硬上限分离，28/32/35 完整镜头池实际可执行 | 合理作品被整数总时长拦住 |
| P0 | 动作镜规划锁裁切，标准源片零入点与速度 1 | 模板比例可能把完整动作缩成半个动作 |
| P0 | 规划/spec/原片合同/交付共用政策与实际钟 | 前期放行、后期再次被同一目标误拒 |
| P0 | 默认事实检查质量分 `null`，审美未验证 | 用户把未评审误当 100 分质量认证 |
| P1 | 清单含目标、实际、差值、政策和代码绑定 | 无法追溯为什么成片多或少几秒 |
| P2 | 后续独立创作编辑可设计有明确语义的剪辑范围 | 本次标准后期保留完整源片；自由剪辑另立产品合同 |

不做：自动审美评分、渲染后第二次审核、自动 paid 返工、声称口型/发音认证、猜测平台硬上限、改变生成预算、修改首次受理凭证、用本规则绕过授权或事实门。写入“完成度优先”并不证明某支影片达到审美高分，最终作品效果由客户真实观看判断。

验证覆盖软目标 28/30/32/35、显式上限及端点溢出、空/非法/冲突/篡改输入、真实 CLI 函数、父服务默认无质量分、实际规划 EDL 的完整动作保护。合成和 HTTP 夹具只验证代码，不认证付费素材质量。
