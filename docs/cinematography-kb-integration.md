# 摄影知识库接入视频管线 v1（2026-09-24）

> 任务：T-2026-0924-0001（续）· 知识库来源：产品所有者提供的 19 篇「AI 视频生成提示词知识库」
> 一句话：**写镜头提示词前先让 Agent 去库里走一圈**，按场景把光圈/景别/光位/色调/材质的关键细节定下来，
> 再把"参数意图"翻译成"画面语言"写进字段——这是"像摄影大师"与"模型随手编"的分水岭。

## 一、要解决的问题

镜头提示词的关键不是长度，而是**关键细节是否恰当**：

- 同一个江南水乡人像，光圈选 f/1.4 还是 f/5.6，出来的是"电影感"还是"打卡照"；
- 光位与色温写错，皮肤就发黄或发塑料；
- 景别、影调、材质各写各的，片子就没有统一的影像语言。

以前这些靠模型自由发挥（或靠人肉经验），同一个题材能出十种风格。现在改为**查库定档 → 翻译成画面语言 → 落字段**。

> 知识库自身的铁律（`_INDEX.md` 检索总则）：**视频生成模型不认技术参数（F 值/ISO/快门数值），只认视觉效果描述。**
> 因此本接入的产出分两路：**提示词正文 = 画面语言**；**技术参数 = trace（留档给监制复核）**。

## 五、自动注入的纪律（为什么不用相似度）

首版用"2-gram 相似度"自动挑条目，真机立刻翻车：日景镜头被注入「逆光日落剪影」、中景镜头被注入
「大远景，人物渺小」、平静清晨被注入「运动人像，动态模糊」。根因是中文 2-gram 会被"画面/光线/人物/镜头"
这类高频词带偏——**参数对、气质错**。

改为**确定性意图映射**（`INJECTION_RULES`）后，规矩是：

1. **有意图才注入**：先用词面判断（时段/天气/主体/景别/运镜/材质/风格）确认"这个镜头有没有这个意图"；
2. **取指定行**：命中后到知识库取**指定那一行**的原文措辞（措辞永远来自 KB，不另写文案）；
3. **≤3 条 / 一字段一条**：宁少勿滥，"一针见血"优先于堆满提示词；
4. **矛盾闸**：日景不配日落/夜景配方；白天巷口的灯笼不算夜景；传统水乡不配赛博霓虹；室内不配户外天空现象；
5. **否定语境剥离**：卡片里的"避免日落时段的金色调"是白平衡锚点，不能被读成"要日落"；
6. **景别不叠加**：卡片已写"中景"就不再注入别的景别；
7. **自由检索仍保留**：`selectEntries()` / `cineread.search` 供 Agent 主动提问，但**不参与自动注入**。

## 七、边界与后续

- 只管镜头语言与质感：不改叙事、不改事实、不决定镜头数量与时长（那是剧本/剪辑环节）。
- 库未覆盖的题材必须如实说"库里没有对应条目"，不许拿近似条目硬凑；允许结论是"本镜无需注入"。
- 后续可做：① `NARR-001` 配方驱动联合检索（先取情绪配方，再按配方回查各专题）闭环；
  ② 把 `cineread.*` 接进运行时 ToolExecutor，让摄影指导在同一次 Agent 会话里调用；
  ③ 用真机出片做 A/B（同 seed、同关键帧、开/关知识库）量化"质感提升"。
