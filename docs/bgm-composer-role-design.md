# BGM 配乐师岗位设计（ai-video 行业包 · 后期音频链路）

> 建档：2026-09-22 ｜ 岗位 preset：`bundles/ai-video/presets/bgm-composer.yml` ｜ 任务：`[T-2026-0921-0005]`
> 定位：把"给成片配个乐"从一句口头要求，变成**有技能、有配方、有工具、有围栏、有证据、可复现**的岗位职责。
> 本文同时回答产品侧最关心的那个问题：**配乐到底怎么和"已经带音轨的成片"结合？**

## 0. 先给结论（三句话）

1. **配乐不是"静音 + 盖音乐"，而是"分层 + 让位"**：默认保留原片人声与现场声，BGM 在人声出现时自动下压（侧链让位，8–14dB），而不是把别人录好的声音整条删掉。
2. **只有三种情况才需要人声分离**：要换环境声（replace-bed）、只留人声（配音重做）、只留伴奏（翻唱底）。多数片子正确解是让位，不是分轨。
3. **能不能用某首曲子，取决于许可，不取决于"是不是 AI 生成的"**：MusicGen 这类模型的**权重是 CC-BY-NC（禁商用）**；本仓默认走**自算作曲**（零第三方权利、时长可裁、可复现），外部曲库走"登记 + 许可校验 + TASL 署名"通道。

## 1. 为什么配乐值得单设岗位

| 理由 | 说明 |
|---|---|
| 它是**情绪的第二次表达** | 同一组镜头，音乐换成小调/慢速/低频，观众读到的是"压抑"；换成大调/中速/拨弦，读到的是"轻快"。配错方向等于改了片子的意思。 |
| 它有**硬技术面** | 让位深度、人声频段、响度（EBU R128）、真峰值、卡点对齐、循环点，每一项都有客观验收线——失手就是"听不清台词"或"配了跟没配一样"。 |
| 它**跨所有内容类型** | 广告、口播、美食、科技、旅拍、夜景、美妆、亲子、汽车、房产、促销、纪录、高端品牌、剧情、悬疑、喜剧——每类的配乐语言不同。 |
| 它踩**版权红线** | 音乐是外部权利最密集的素材：CC-NC 不能商用、AI 生成不等于无版权、署名义务常被漏掉。 |
| 它决定**能不能发** | 响度不对（过小/过大）、台词被压住、音乐中途硬切，都会直接导致平台端观感差或审核投诉。 |

## 4. 核心问题的正面回答：配乐怎么和"带音轨的成片"结合

上游交付的成片音轨里通常同时存在四类内容：**对白/人声、现场声（环境/动作）、底噪、可能还有上一版音乐**。
用户提出的三种做法（全静音 / 直接盖 / 先分离人声再配）各自对应一种**处置手段**，但都不该是默认流程：

| 做法 | 本质 | 什么时候可以用 | 代价与风险 |
|---|---|---|---|
| ① 声音全去掉 | 丢弃原声轨 | 纯卡点片、**无人声**素材 | 连对白和现场信息一起丢，不可恢复；有人声时被 G-BGM3 直接阻断 |
| ② 直接盖新音乐 | 不做让位的叠加 | 几乎不适用 | 音乐与口播抢字，人声清晰度直接掉；实测不做让位时台词被压 |
| ③ 先分离人声再配 | 分层的一种极端形态 | 要换环境声 / 只留人声 / 只留伴奏 | 分离质量决定成败；近似分离（中心声道法）会把人声混响留在伴奏、把中置伴奏漏进人声 |

**本仓的默认做法（分层 + 让位）**：

```
成片音轨（只读）
  ├─ 侧链键：200–4000Hz 带通 → 作为 sidechaincompress 的控制信号
  └─ 声音床：按策略选择（原声 / 仅人声 / 静音）
BGM（自算或曲库）
  └─ 循环铺满 → 卡点偏移 → 音量 → 淡入淡出 → 被人声侧链压下去（8–14dB）
      → 与声音床合流 → 两遍法 loudnorm（-14 LUFS / -1 dBTP）→ 与视频轨合流（画面 copy）
          → 复检：响度 / 让位深度 / 人声-音乐余量 / 配乐可闻度 / 卡点达标率
```

四种分层策略（`bgmwrite.mix` 的 `policy`）：

| policy | 声音床 | 适用 | 纪律 |
|---|---|---|---|
| `keep-dialogue`（默认） | 原声全保留 | 口播/访谈/带货 | 人声-音乐余量 ≥6dB，让位 10–14dB |
| `keep-all` | 原声全保留、BGM 更轻 | 纪录片/现场感 | 配乐电平再降 3dB，让位更浅 |
| `replace-bed` | 仅人声（中心声道近似分离） | 环境声脏、要换氛围 | 单声道素材直接拒绝（`separation_unavailable`） |
| `music-only` | 静音 | 纯音乐卡点片 | 必须显式 `allow_discard_original=true`，有人声时被 G-BGM3 阻断 |

## 5. 音频素材工程：作曲、曲库、分离

### 5.1 默认路径：自算作曲（`synth.mjs`，零第三方音源）

为什么自己算，而不是"接一个 AI 音乐 API 就完事"：

1. **许可干净**：不引入任何第三方样本/权重，商用交付无权利尾巴；
2. **时长可裁**：片子多长就写多长（不用"裁歌"破坏结构），短曲子循环铺满而不是硬剪；
3. **卡点可控**：BPM/节拍网格由配方与剪辑点共同决定，能给"卡点对齐"提供确定性输入；
4. **可复现**：同一配方 + 同一种子 → 同一份 PCM → 同一 sha256（可核验、可回滚）。

作曲口径：配方给 **调式 → 和弦级数 → 配器 → BPM → 结构比例**；内核按小节渲染
pad（情绪地基）/ bass（低频走向）/ pluck（推进感）/ kick·hat（只在主体段）/ bell（点缀），
输出 44.1kHz 16-bit 立体声 WAV（峰值归一化 -6dBFS 留混音余量）。

### 5.2 外部曲库（`library/bgm-library`，只登记不搬运）

- 曲库目录 + `tracks.json` 由客户/工位提供，工位**不下载、不转存**第三方音源；
- 每首登记：标题/作者/来源/许可/路径/BPM/时长/情绪/题材；
- 商用交付只检索 `commercialOk=true` 的曲目（**缺省即商用口径**），NC/ND 在检索阶段被过滤；
- 需署名的曲目自动产出 TASL 署名文件（`attribution_out`）。

### 5.3 人声分离（两档引擎，质量如实标注）

| 档位 | 引擎 | 质量 | 依赖 |
|---|---|---|---|
| A | `demucs` / `audio-separator` | `high`（深度学习） | 外部安装，不随仓分发 |
| B | `ffmpeg` 中心声道近似（`0.5L±0.5R`） | `approximate` | 工位自带 ffmpeg |

档位 B 只对立体声素材可用；单声道直接拒绝，不"假装分离"。所有分离结果都带
`engine + quality + qualityNote`，不允许把近似结果说成"AI 分轨"。

## 7. 配乐师的一天（标准工作流）

```
接收母版（剪辑师/调色师交付）
  ↓ 定调四问：题材？场景/主体？情绪目标？发哪个平台？
  ↓ bgmread.analyze：响度 / 人声活动段 / 静音窗口底噪 / 剪辑点 / 是否已有配乐
  ↓ bgmread.recipes 取配方（说明选型理由与"为什么是这个速度"）
  ↓ 定速：剪辑点反推 BPM（±25% 内采用），否则沿用配方 BPM 并说明冲突
  ↓ bgmwrite.compose：按片长合成 BGM（自算，零第三方权利）
  ↓ bgmwrite.mix：分层策略 → 侧链让位 → 卡点偏移 → 淡入淡出 → 两遍法 loudnorm
  ↓（需要时）bgmwrite.separate：人声/伴奏分离（标注引擎与质量）
  ↓ 复检：响度 / 让位深度 / 人声-音乐余量 / 配乐可闻度 / 卡点达标率
  ↓ 交付：新成片 + bgm_track + bgm_report（含波形对比、指标、哈希、署名）
```

## 8. 交付标准（不达标不算完成）

1. 成片哈希（sha256）+ 使用的 BGM 标识（配方/曲目 + 许可 + 哈希）；
2. 响度实测：配乐前后 integrated LUFS / 真峰值 dBTP / LRA；
3. 让位深度（人声窗口 vs 无对白窗口的 BGM 电平差，目标 ≤ -6dB）；
4. 人声-音乐余量（目标 ≥6dB；<3dB 由工具直接拒绝出片）；
5. 配乐可闻度（无对白窗口相对原片的提升，目标 ≥3dB；不足则由工具拒绝出片）；
6. 卡点达标率（±80ms 落拍数/总数 + 平均误差 + 采用 BPM 与依据）；
7. 前后波形对比图；
8. 署名文件（如使用需署名曲目）。

## 9. 与上下游的接口

| 对手方 | 配乐师接收/交付什么 | 冲突时的裁决 |
|---|---|---|
| 渲染师 | 接收镜次；发现对白削波/底噪过大 → 退回上游并标注不可修复 | 上游素材质量优先于后期补救 |
| 剪辑师 | 接收定稿母版；**在母版上配一次**，不参与剪辑决策 | 剪辑决定节奏，配乐决定情绪 |
| 调色师 | 接收已调色母版（音频链路后置，画面不重编码） | 画面调色与音频配乐互不阻塞，管线顺序 color → bgm |
| 发布运营 | 交付已配乐母版 + 平台派生建议 | 变体不重新混音 |
| 合规/品牌 | 曲库许可与署名文件；品牌主题曲变更走 G-BGM1 | 合规优先 |

## 10. 质量指标（用于绩效与考试院）

| 指标 | 目标 | 数据来源 |
|---|---|---|
| 一次通过率 | ≥85% 首次人审通过 | G-BGM1/审批记录 |
| 人声-音乐余量 | 交付全部 ≥6dB | `bgm_report.levels.speechToMusicMarginDb` |
| 配乐可闻度 | 交付全部 ≥3dB（且无"配了像没配"） | `bgm_report.levels.musicPresenceDb` |
| 响度达标率 | 100% 落在 -14 ±1.5 LUFS | `bgm_report.loudness.after` |
| 卡点达标率 | ≥60% 剪辑点落拍（±80ms） | `bgm_report.alignment` |
| 许可合规率 | 100%（无 NC/ND/未标注入片） | `bgm_report.license` + 署名文件 |
| 返工归因准确率 | 100% 标注"选型错/参数错/上游素材" | 返工表 |

**考试院题目方向（建议）**：① 口播片把 BGM 电平设到 -14dB 会发生什么、怎么修；
② 素材报告"已有连续配乐"时该不该再配、依据是什么；③ 卡点达标率 33% 时先改什么；
④ 一首 CC-BY-NC 曲目客户坚持要用的正确处理；⑤ 单声道素材要求"只留人声"的处置。

## 11. 边界（本岗位不做什么）

- ❌ 不做剪辑决策、不改叙事结构、不改字幕与画面（只处理音轨；视频轨恒 copy）；
- ❌ 不做 HDR/空间音频/杜比全景声（第一版口径，遇到按"超出交付口径"上报）；
- ❌ 不重新生成 AI 视频（只处理已成片素材）；
- ❌ 不负责对外发布（发布是发布运营的职责，走 G9）；
- ❌ 不用配乐掩盖上游缺陷（对白削波、底噪过大、单声道分离限制 → 如实上报）；
- ❌ 不搬运第三方音源（工位只读客户已授权的本地文件，凭据留在客户侧）。

## 12.5 选段：外部曲目"取哪一段"（2026-09-22 补强）

外部曲目动辄 2–3 分钟，片子只有 15–60 秒——**"裁哪一段"和"配什么曲子"同等重要**。本版补上这条链路：

| 能力 | 落点 |
|---|---|
| 曲目结构识别 | `bgmread.structure`：解码 8kHz 单声道 PCM → 逐窗 RMS 能量包络 → 分位数三档分段（intro/verse/build/drop/breakdown/outro/flat）+ 起音包络自相关估 BPM + 高潮/铺垫候选打分 |
| 片子高潮判定 | `filmClimaxTime`：剪辑密度成簇 → 非对白段能量峰 → 音频总能量峰（对白占比 <35%）；**口播片不拿台词峰值当高潮** |
| 自动选段 | `bgmwrite.mix --section auto|climax|calm|full` 或显式 `section_start_sec/section_end_sec` |
| 落点对齐 | 取 `drop` 段并把段内能量峰值对齐到片子高潮时刻；片子高潮更早则向前裁片头（回执写明裁了多少） |
| 滑窗兜底 | 选出的段比片子还长 → 段内以能量最高处为中心取 片长×40% 的窗口；曲子平坦则从曲头取 |
| 边界纪律 | 边界优先吸结构边界、其次吸节拍（BPM 置信度 low 时不吸）；两端 120ms 微淡；选段后重新量片段电平再定增益 |
| 证据 | `section-picked.png`（上=曲目波形+红框，下=片子波形+高潮红框）、`report.section`（模式/片段/理由/是否对齐） |

**诚实边界**：结构识别是**规则式**（分位数 + 走向 + 起音密度），不是深度学习结构识别，也不是乐谱级主歌/副歌标注；
它能稳定回答"哪段最响、最密、最适合当高潮"。找不到可靠高潮点时**如实返回 `basis: "none"` 并跳过峰值对齐**——
宁可不对齐，也不把音乐高潮对到片头第一秒。

真机验证（`structure.test.ts`，真实 ffmpeg）：人造"安静→高潮→安静"曲子，8–20s 高潮段被识别为 drop、拍速落在 120BPM；
人造"三连切+更响"的片子，高潮按剪辑密度判定；自动选段出片后落点误差 ≤1.5s 且复检全绿。

## 13. 设计边界与遗留

1. **画面不参与配乐决策**：当前版本只看音轨与剪辑点（scene 检测），不做视觉情绪识别；
   需要"画面理解驱动配乐"时，应由导演/剪辑在配方选型阶段给出情绪标注。
2. **人声判定是频段能量活动**，不是语音识别；它支撑"要不要让位、让多少"，不支撑"说了什么"。
3. **档位 A 分离引擎不随仓分发**：仓内只登记仓库/许可/降级路径；是否内置由产品所有者决定。
4. **`provides.connectors` 登记了配乐连接器资产**（进签名索引），而调色连接器（`color-bridge`）历史上未登记，
   属既有遗留；建议后续单独任务卡把 color-bridge / visual-bridge 也纳入索引，避免两套口径。
5. **两隔离副本（growthtest / growthmatrix）** 的规格来源是各自仓内文档；本能力向它们的移植按产品所有者指令执行，
   移植后需以各自仓的回归口径重新验证（不以本仓验收结论代表它们）。
