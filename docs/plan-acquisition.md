# WorkLoom GEO 获客系统升级方案

> **版本**：v1.0（对焦稿） · 2026-08-25
> **定位升级**：从「社媒短视频营销 × GEO 双域经营系统」→「**B 端获客经营系统**」
> **落地路径**：以酒店行业为首场景打磨，沉淀行业模板后横向复制

---

## 一、获客的本质：先对焦认知，再谈系统

调研了 2025-2026 年 B2B/B2C 获客方法论与酒店行业实证案例后，获客的精髓可以收敛为一句话：

> **在对的地方，用对的内容，接住有意图的人，并且每一环都能度量到钱。**

拆开是四个要素，缺一个获客就不成立：

| 要素 | 内涵 | 酒店行业的实证 |
|---|---|---|
| **精准人群** | 不是广撒网，是找到"正在为这个问题找答案的人"。搜索词、query、评论区提问，全是意图信号 | 90后/00后不认识老牌酒店，他们的认知来自小红书/抖音/AI 搜索——人在哪，内容就要在哪 |
| **触达手段** | 内容平台种草（抖音/小红书）+ AI 搜索截流（GEO）+ 私域承接，三线并进 | 上海外滩悦榕庄 2 场直播卖 500 万预售券；北戴河董思雨 30 天 200 场直播卖 3000 万；**42% 住客已通过生成式 AI 查询住宿信息**——AI 搜索是刚爆发的新入口 |
| **转化路径** | 看见 → 兴趣 → 询盘 → 留资 → 成交 → 复购/转介。每环要短、要轻、要可追踪 | 通兑券"先囤后约"把决策做到极致轻量化；直播实时看房消除信息不对称，预订转化率提升 45% |
| **可归因度量** | 每条线索知道从哪来、值多少钱、哪一环漏了 | OTA 佣金 15-25% 是酒店的切肤之痛——自建获客渠道的核心动力就是**把佣金变利润** |

**关键判断**：我们现有的系统已经把「触达手段」（短视频+GEO 双域内容工厂）做到了行业罕见深度，但**获客链条在"询盘"处就断了**——询盘之后没有承接、没有转化、没有成交度量。这是当前系统与"获客系统"之间最核心的差距。

## 二、现状盘点：我们有什么，缺什么

### 2.1 已有的家底（不需要重造）

| 能力 | 现状 | 获客视角的评价 |
|---|---|---|
| 双域内容工厂 | 一次生产两处变现：短视频（社媒）+ AI 答案版（GEO），4 条管线 | ✅ 触达环已很强，行业领先 |
| GEO 能见度监测 | 豆包/DeepSeek/元宝/ChatGPT 四平台，query 集/SOV/首推率 | ✅ AI 搜索截流的度量基础有了 |
| 双入口询盘打标 | 社媒入口 vs AI 搜索入口，北极星=双入口有效询盘数（月） | ⚠️ 只到"询盘"，是半程北极星 |
| 一客一档 v2 | 七模块客户档案（B 端客户） | ⚠️ 是"服务客户"的档案，不是"经营线索"的档案 |
| C 端服务前台（service-c） | 知识库/对话/工单/统计四包 + webc 端 | ⚠️ 是客服服务台形态，不是营销承接形态 |
| 围栏/事件链/验链 | 17 条双域围栏、五元事件、哈希链审计 | ✅ 底线纪律是差异化竞争力，直接复用 |
| 数码员工编制 | 16 员 + 2 指挥官，五组分工 | ⚠️ 缺"承接转化"职能组 |

### 2.2 缺什么：获客链条上的四个断点

```
看见 ──→ 兴趣 ──→ 询盘 ──✂──→ 留资 ──✂──→ 成交 ──✂──→ 复购/转介
(已有)  (已有)   (已有)   断点①    断点②     断点③      断点④
```

| 断点 | 问题 | 后果 |
|---|---|---|
| ① **承接断** | 评论/私信靠人看，无 7×24 自动应答+留资能力；夜间/高峰询盘流失 | 调研显示评论区"怎么订/多少钱"类提问 30 分钟内无响应，流失率 >70% |
| ② **线索断** | inquiry 只是打标对象，没有分级（A/B/C）、没有跟进 SOP、没有归属人 | 询盘进了系统就"躺平"，没人跟、不知道谁该跟 |
| ③ **成交断** | 度量到询盘为止，不知道哪条线索成交了、成交额多少、哪个渠道带来的 | 无法算 ROI，内容策略没有"钱"的反馈信号，只能凭感觉优化 |
| ④ **复购断** | 没有客户资产沉淀（会员/私域），没有复购与转介绍运营 | 获客成本永远降不下来——没有老客杠杆 |

### 2.3 行业化短板

- 酒店 Bundle 目前是**运营域**（定价/巡检/差评/对账），不是**获客域**——两套人马两件事，尚未打通；
- **没有外部连接器**：酒店获客必须接 PMS（房态/订单）、抖音本地生活（团购券核销）、OTA（评论/价格监测）、企微（私域）——目前一个都没有；
- 场景包/对象模型里没有酒店获客的特有对象（房态日历、团购券 SKU、预订单、住客档案、POI 门店）。

## 三、升级蓝图：获客五环

把系统从「内容经营」升级为「获客经营」，核心是在现有双域内容工厂的前后各接一环、中间补两环，形成完整闭环：

```
┌─────────────────────────────────────────────────────────────────┐
│                        获客五环（行业无关底座）                      │
│                                                                   │
│  ① 人群洞察环 ──→ ② 触达环 ──→ ③ 承接环 ──→ ④ 转化环 ──→ ⑤ 复盘环 │
│  （新增·意图挖掘）  （已有·强化） （新增）    （新增）    （强化·到钱） │
│       ▲                                                    │      │
│       └────────────── 反哺内容策略 ─────────────────────────┘      │
└─────────────────────────────────────────────────────────────────┘
```

### 环① 人群洞察环（新增）——回答"给谁做内容"

> 获客的起点不是内容，是意图。把散落在各处的意图信号收敛成"人群-意图库"，反向指挥内容生产。

**数据源**：评论区提问（已有评论采集）→ 意图聚类；私信关键词；query 集搜索词；竞对账号评论区；OTA 差评关键词（酒店场景）。

**新增对象**：`audience_segment`（人群分层）、`intent_signal`（意图信号：什么人在问什么、热度、对应内容缺口）。

**新增员工**：`audience-researcher`（人群洞察分析师）——每周产出《意图雷达报告》，直接作为内容组选题输入（接入现有 intel-fusion 管线头部）。

### 环② 触达环（已有·强化）——双域之外补两个酒店刚需

现有双域内容工厂保留不动，补两个获客强化件：

1. **矩阵账号编排**：主账号+门店账号+员工 IP 账号的内容协同排期（酒店实证：单账号天花板明显，矩阵是放大器）；
2. **直播/团购内容形态**：直播脚本+切片二次分发、团购券口播话术模板（酒店行业第一转化形态是直播卖券）。

### 环③ 承接环（新增·最大增量）——7×24 接住每一个意图

> 这是当前系统最大的缺口，也是获客系统的心脏。

**四路承接通道**：

| 通道 | 承接方式 | 落地形态 |
|---|---|---|
| 评论区 | "怎么订/多少钱/在哪"类提问 → 自动识别意图 → 标准话术回复+引导私信 | 扩展现有评论四档分流（G10a-d），新增"获客意图"档 |
| 私信 | AI 接待员 7×24 自动应答 → 答问题→发资料→留资（电话/微信）→ 分级 | 新增 `ai-receptionist` 员工（复用 service-c 对话引擎，营销口径改造） |
| 落地页 | 内容挂链接 → 落地页留资表单 → 线索入库 | 轻量落地页生成器（一客一档 v2 已有官网口径） |
| AI 搜索 | GEO 内容里植入"行动锚点"（预约口令/优惠券码/门店 POI）→ 可归因留资 | 扩展现有 geo-content-planner 的输出模板 |

**新增对象**：`lead`（线索：来源渠道/入口/意图/分级/归属/跟进状态）、`lead_event`（线索跟进留痕，走五元事件链）。

**新增围栏**：
- `G-ACQ1`（review）：AI 接待涉及**价格承诺/优惠承诺**必过人审——AI 不许私自报价；
- `G-ACQ2`（block）：留资信息（手机号/微信号）**脱敏存储+访问留痕**，客资红线（R4）的延伸；
- `G-ACQ3`（review）：自动回复外发内容与品牌口径一致性校验（复用 G-GEO2 事实红线机制）。

### 环④ 转化环（新增）——从线索到钱

**线索分级 SOP**：
- **A 级**（明确时间+明确需求，如"国庆 3 天 2 晚两大一小"）→ 1 小时内人工/AI 电话跟进，推送专属报价；
- **B 级**（有需求无时间）→ 进入培育池，每周定向内容触达+优惠唤醒；
- **C 级**（泛兴趣）→ 私域沉淀，长期内容喂养。

**转化对象**：`conversion`（成交：关联线索 ID/成交金额/渠道归因）、`coupon`（团购券/预售券 SKU——酒店第一转化形态）。

**归因规则**：每条 lead 强制携带来源链（社媒-视频 ID / AI 搜索-query 词 / 私域-渠道码），成交时回写——**至此北极星可以从"询盘"升级为"归因成交额（月）"**。

### 环⑤ 复盘环（强化）——度量到钱，反哺到内容

现有复盘分析师 + 数据看板官扩展三个新报表：

1. **获客漏斗日报**：曝光→互动→询盘→留资→成交→复购，六级转化率，哪环漏了一目了然；
2. **渠道 ROI 账本报**：每条渠道的 获客成本（含内容制作分摊+投放）vs 归因成交额——告诉客户"抖音团购花了 X，赚了 Y，OTA 省了 Z 佣金"；
3. **内容-成交关联榜**：哪条视频/哪篇 GEO 内容带来的成交最多——**直接反哺环②的选题策略**，闭环完成。

## 四、酒店垂直化：hotel-acquisition Bundle

按「底座零改动，能力经 Bundle 注入」的既定纪律，酒店获客能力落为新 Bundle，与现有 hotel（运营域）、geo-growth（通用双域）并存。

### 4.1 酒店获客对象模型（新增 8 类）

| 对象 | 说明 |
|---|---|
| `room_calendar` | 房态房价日历（接 PMS 同步）——内容排期要跟房态联动（满房不推、淡季猛推） |
| `coupon_sku` | 团购券/预售券 SKU（通兑券"先囤后约"）——酒店获客第一转化品 |
| `booking_order` | 预订单（直连预订/PMS 回传）——成交度量单元 |
| `guest_profile` | 住客档案（入住偏好/历史/会员等级）——复购与转介的基础 |
| `poi_store` | POI 门店（抖音本地生活门店绑定）——内容挂载点 |
| `ota_channel` | OTA 渠道监测（携程/美团价格与评论）——既要监测也要"薅"差评里的意图 |
| `live_campaign` | 直播场次（脚本/切片/战报）——直播卖券是实证最强形态 |
| `member_asset` | 会员资产（私域沉淀量/复购率/转介绍率） |

### 4.2 酒店获客编制（新增 6 员，复用底座 16 员）

| 员工 | 职责 |
|---|---|
| `hotel-content-curator` 酒店内容店长 | 房态联动的内容排期（满房停推/淡季加推/节假日套餐策划） |
| `live-planner` 直播策划 | 直播脚本/排期/切片分发/战报复盘（对标董思雨模式） |
| `ai-receptionist` AI 接待员 | 四路承接总入口：评论/私信/落地页/AI 搜索 7×24 应答留资 |
| `coupon-operator` 团购运营 | 券 SKU 设计/上架/核销对账/库存红线 |
| `guest-success` 住客运营 | 入住前确认/住中关怀/离店好评引导/复购唤醒/转介绍激励 |
| `channel-watcher` 渠道哨兵 | OTA 价格评论监测+竞对内容监测+AI 搜索酒店词能见度 |

### 4.3 酒店特有围栏（新增 4 条）

| 规则 | 级别 | 说明 |
|---|---|---|
| `G-HOTEL1` | block | **价格承诺红线**：AI 接待/内容文案报价必须与房价日历一致，超口径一票否决 |
| `G-HOTEL2` | block | **券库存熔断**：团购券售罄/下架后，相关内容自动停投+AI 接待话术切换（防超卖投诉） |
| `G-HOTEL3` | review | **差评响应升级**：OTA/评论区差评 2 小时内必出响应方案，重大差评（安全/卫生）直接 L4 |
| `G-HOTEL4` | block | **住客隐私红线**：住客信息不出系统边界，好评引导不得利诱刷分（平台合规） |

### 4.4 外部连接器（mock 先行，接口标准化）

按现有 publish-rpa 的适配器模式，新增 `hotel-connectors` 能力包：

| 连接器 | 方向 | 说明 |
|---|---|---|
| PMS（酒店管理系统） | 读：房态/订单回传 | 标准接口 + mock 驱动，先打通"内容-房态-成交"数据链 |
| 抖音本地生活 | 读：券核销/POI 数据；写：内容挂载 | 团购券核销是成交归因的关键数据源 |
| OTA（携程/美团） | 读：价格/评论监测 | 社媒聆听包的酒店版扩展 |
| 企微 | 写：私域承接 | 线索分配到企微侧边栏，服务顾问跟进 |

### 4.5 酒店获客主链路（端到端 Quest 管线）

`hotel-acquisition-loop`（酒店获客循环管线）：

```
意图雷达（竞对评论区+OTA差评+query）→ 内容排期（房态联动）
→ 双域生产（短视频+直播脚本+GEO 图文「XX市亲子酒店怎么选」）
→ 发布挂载（POI+券链接+行动锚点）→ 四路承接（AI 接待留资）
→ 线索分级（A 级 1h 跟进）→ 券成交/直连预订 → 核销归因
→ 住客沉淀（好评+复购+转介）→ 漏斗复盘反哺选题
```

## 五、北极星与商业模式的重新标定

### 5.1 北极星升级路径

| 阶段 | 北极星 | 含义 |
|---|---|---|
| 现在 | 双入口有效询盘数（月） | 半程指标——证明"能引来人" |
| P1 落地后 | **有效线索数 × 线索转化率** | 证明"能接住人" |
| P2 落地后 | **归因成交额（月）** | 终极指标——证明"能赚着钱"，这也是向客户收钱的底气 |
| 长期 | **获客成本 vs OTA 佣金节省额** | 酒店场景最锋利的价值主张："我们帮你把 15-25% 的 OTA 佣金变成利润" |

### 5.2 收费模式建议（随能力升级阶梯涨价）

| 版本 | 内容 | 建议定价 |
|---|---|---|
| 现在（内容工厂版） | 短视频+GEO 代运营 | 月费制 |
| P1（线索版） | +承接环/线索管理/漏斗报表 | 月费 + 线索量阶梯 |
| P2（成交版） | +券运营/成交归因/ROI 账本 | **月费 + 归因成交额抽成**（效果付费，最有说服力） |
| P3（行业版） | 酒店/餐饮/美业模板库 | 行业 SaaS 订阅 + 实施费 |

## 七、战略判断：为什么这条路是对的

1. **市场缺口真实**：GEO 行业 2026 年预计 942 亿规模（年增 122%），但市面上 GEO 服务商全是"帮你上榜"的灰帽玩法，没有一家做"内容→承接→成交"的全链路——**我们的差异化就是"敢度量到钱"**；
2. **酒店是最好的磨刀石**：决策链短（内容到预订可 24 小时内完成）、转化形态标准（团购券）、痛点尖锐（OTA 佣金）、数据可得（PMS/核销都有数字化基础）——获客闭环能最快跑通验证；
3. **底座完全撑得住**：围栏/事件链/员工编制/Quest 管线/C 端前台全部可复用，新增的是"获客域 Bundle"而不是重构——这验证了 Bundle 架构的扩展性；
4. **护城河加深**：灰帽 GEO 会被平台清理（G-GEO3 已熔断），而"合规内容+全链路归因"的能力越做越厚。
