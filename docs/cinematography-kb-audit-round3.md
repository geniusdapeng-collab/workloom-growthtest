## 三、根因与修复（逐条，含代码位置）

全部改动在 `bundles/ai-video/connectors/cine-kb-bridge/core.mjs`（下称 core.mjs），另有送审通路两处。

1. **命名角色没被当作主体**（①③⑥⑯⑰㉑㉒㉓㉔ 的共性根因）
   卡片写 `character: "陈卓"` 时，词面上下文只认"人/人物/她/他/人像" → 判定为"空镜" → 光圈兜底落到「打卡照 f/5.6」。
   修复：新增 `hasNamedSubject()`（core.mjs `detectContext()` / `injectionContext()`），
   **角色字段非空且未被否定**即为主体信号；`无 / 空镜 / 不需要 / 不出镜` 仍判空镜。
2. **主体意图 id 写错**：`hasPerson` 判定里写的 `single-portrait` 在 `APERTURE_INTENT_HINTS` 里**根本不存在**，
   真正的 `person / closeup-portrait / scene-portrait` 反而没算进去。修复：改回真实 id 集合。
3. **兜底一律"打卡 f/5.6"**：`recommendAperture()` 第 ③ 步没有主体分支。
   修复：加"主体类型 → KB §三 行"的偏好表（产品/婚礼/儿童/体育/航拍/棚拍/门店/办公室/医院/美食/微距/星空），
   并按**书写优先级**取行；仍无匹配才退回"环境人像（有人）→ 打卡"。
4. **§三 要点行解析过窄**：只认 `- 标签：**f/x**`，于是"星空银河：**用镜头最大光圈**（f/1.4–f/2.8）"
   与"微距景深天然极浅，**f/8–f/16** 起步"两行没进场景表（⑩⑬ 的第二轮遗留）。修复：放宽为"行内出现 f 值即收"，并保留标签/理由切分。
5. **蓝调时刻被"电影感夜景"抢位**（③⑯ 相关）：新增 `blueHour` 信号 + `LIGHT-002#蓝调时刻` 规则，且排在夜景规则之前。
6. **正午被当午后**（①）：新增 `noon` 信号 + `LIGHT-002#正午硬光（纪实/压迫）`；`day-slant` 只在明确写"上午/下午/早晨/清晨"时生效。
7. **光照规则互抢**（②⑪）："有意剪影 / 轮廓光"比"黄金时刻"更具体，原顺序让日落语境一律走黄金时刻。
   修复：顺序改为 **剪影 > 轮廓光 > 黄金时刻**，后两条各加互斥条件。
8. **无主体却选人像档**：空镜夜景巷子靠 2-gram 噪声被选成「环境人像」。修复：`!hasPerson` 时人像类行 −4 分。
9. **否定语境剥离过宽**（⑩ 隐藏坑）：旧规则对"无/不含/非"也剥 18 字，"**无光污染**的星空银河"整段被吃掉 → 星空规则不触发。
   修复：`stripNegatedContext()` 分两类——谓词否定（避免/不要/禁止）剥 18 字；限定词否定（无/不含/非）遇到"的/地"即停。
10. **"其他"里的"他"**被当成人物代词。修复：剥离时把"其他/其它"整体抹掉（`detectContext` / `injectionContext` / 光圈文本三处同口径）。
11. **专项意图画面语言照抄档位表**（⑩）：f/1.4–2.8 的档位效果词是"奶油般虚化、梦幻光斑"（人像语言），
    §3.5 对星空的原话是"求的是进光量而非景深"。修复：进光量优先的专项行改用行内理由做画面语言，避免模型画出大片光斑。
12. **雪景重复注入**（⑥）：同一知识行同时落 lighting 与 props。修复：同一 `topicId#intent` 只允许注入一次。
13. **镜面倒影触发词过宽**：`水` 即命中，"倒影"被注入到水下/冰面/产品白背景。修复：`mirrorWater` 要求
    "倒影/镜面/如镜/平静水面/无风水面/静水"且排除水下/冰/雪。
14. **注入上限 3 → 5**：字段级仍"一字段一条"，但全局上限 3 会让靠后的"材质/道具"永远被灯光/构图挤掉（真机"湖面倒影"因此从未注入）。

## 五、真机事故：送审抽帧过大 → 评审 413 → 监制悬空

- **现象**（`work/logs/p19-sc02-spacefix.log` 22:33）：`shot` 环节 `评审调用失败：HTTP 413 Request Entity Too Large` →
  fail-closed 判"监制不可用"，SC-02 既没通过也没被打回，成片以"带瑕疵 + 未复核"状态合成；
  终审 master 因此点名"需回查日志中 failed/degraded 环节"。
- **根因**：`full-chain-film.mts` 抽 4 帧评审，帧是 1080×1920 **PNG**（单张 ≈10MB），base64 后 ≈53MB；
  路由网关在 3 帧 ≈40MB 时还能过，加到第 4 帧即 413。**复用（RESUME）分支**当时仍在抽全分辨率 PNG。
- **修复**：
  1. 渲染分支与**复用分支**统一抽 **720 宽 JPEG**（`-vf scale=720:-2 -q:v 3`，单张 ≈100KB）；
  2. `producer-gate.ts` 加**按需压缩预算** `JUDGE_IMAGE_BUDGET_BYTES = 900_000`：超预算的送审图先用 ffmpeg 缩到 720 宽 JPEG，
     压缩不可用时按原图送审并**如实记日志**（不静默丢证据）；临时压缩图在请求结束后回收（finally）。
- **验证**：`producer-gate.test.ts` 新增"送审图超预算时自动压缩后再送审（防 413 让监制悬空）"，断言请求体 < 400KB 且含压缩图指纹；
  视频工位 99 项单测全绿（见第七节）。
