# 原生客户端场景复验

本说明适用于本隔离副本的原生客户端与研发试运行包。图形界面、窗口几何和运行记录必须来自与修复提交相符的实际包；单元测试和整窗截图不能独自证明真实舞台已经显示。正式签名、公证及 Windows 原生运行分别验证。

## 产品行为

经营主页的职场与汇报舞台保留完整团队数据。较大团队每批最多显示 18 名员工，每 12 秒轮换；团队总编制与当前可见人数分别记录，员工档案仍使用完整岗位身份。3D 汇报舞台固定 440px 高度，让画布填满自身容器。职场常驻任务牌优先显示两个有任务、待放行、异常或完成的岗位，其他员工悬停后显示，员工本体与任务牌仍进入原有档案和任务详情。

`?render=vector2d` 显式选择 2D 职场与汇报舞台，适合无法使用 WebGL 的环境。2D 舞台中的岗位点击区域随容器布局，保持在场景内；团队轮换与总人数语义相同。

织伴在经营主页没有本机形态偏好且内容区宽度不超过 1760px 时，默认使用角落小球；其他页面继续使用 880px 内容区阈值。用户显式展开或收起优先。任务完成通知保留当前形态，使用语音、字幕和右栏提示，不会把收起偏好改写为展开。布局恢复按当前页面与视口重新选择默认形态。

## 可运行回归

在现有仓库依赖准备完成后，从仓库根目录运行：

```sh
node --test apps/desktop/electron/bootstrap.test.cjs apps/desktop/electron/bootstrap-startup.test.cjs apps/desktop/electron/render-smoke.test.cjs
node node_modules/vitest/vitest.mjs run --config apps/web/vitest.config.ts apps/web/src/components/loommate/LoomMate.scene.test.tsx
```

渲染冒烟单测运行真正的 `main.cjs`，以受控 renderer 验证短画布、遮挡、纯黑场景和场景裁剪反例。织伴测试运行真正组件，验证默认形态、通知与显式偏好。两者均属于本地夹具证据，实际原生窗口仍需复验。

原生包的应用自有冒烟由 `WORKLOOM_RENDER_SMOKE=1` 启用，使用新的 `WORKLOOM_SUPPORT_DIR` 和独立的服务端、网页、PostgreSQL、NATS 端口。`WORKLOOM_SAFE_RENDERING=1` 使用安全渲染通道。应用本身走正式欢迎/跳过、引导关闭、职场与汇报切换，并负责退出；不要另启控制脚本与其争抢输入或退出生命周期。普通产品窗口仍保持默认后台节流；自有冒烟关闭后台节流以提交持续图形帧。

每个场景必须满足：已存在且完整处于窗口内；3D 画布宽高至少覆盖场景尺寸的 95%；没有可见模态引导；5×5 实际命中采样的场景可见比例至少 90%；真实场景裁剪像素不是纯黑或纯色。判定同时写场景矩形、画布矩形、当前/总人数、任务牌、遮挡、像素健康、整窗与场景截图。失败先保存场景 JSON 再返回非零，不能用导航栏的亮色像素代替舞台像素。

## 独立复验与边界

独立会话须在干净完整提交上核对包内受控源码与 Electron 源码字节，再使用独立支持目录、数据库、端口和日志。普通产品模式的实际点击使用电脑操作工具；只读诊断与应用自有冒烟分别注明来源。首次启动、同库重启、安全渲染、桌面与移动宽度都记录真实结果。

持续运行从实际 UI 就绪开始计时。内存与句柄判定使用同一进程身份的连续采样，不能把重启后的低内存拼接到旧进程序列。两小时观察只能支持此次稳定性结果，不证明 24 小时计划执行、7 日或 28 日经营结果。模拟模型、合成任务和研发包不计入真实经营自主交付率。
