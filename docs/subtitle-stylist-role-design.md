# 字幕师岗位设计（ai-video 行业包 · 后期文字链路）

> 建档：2026-09-23 ｜ 岗位 preset：`bundles/ai-video/presets/subtitle-stylist.yml` ｜ 任务：`[T-2026-0922-0048]`
> 定位：把"给成片配字体和字幕"从一句口头要求，变成**有档案、有配方、有工具、有围栏、有证据、可复现**的岗位职责。
> 本文同时回答产品侧最关心的那个问题：**标题字幕方案到底怎么落到成片里，怎么保证不是"看着差不多"？**
> 来源：供应商方案包 `font-library v1.1`（29 款开源/免费商用字体 + 五维打标档案 + 字号/版式策略 + 选型 Agent + 渲染管线）。

## 0. 先给结论（四句话）

1. **字体不是"挑个好看的"，是"先排除不可能的，再在可能里排序"**：场景与语言先硬过滤，许可不在白名单直接出局，
   再按 作品类型 30 / BGM节奏 20 / 粗细×场景 20 / 艺术气息×调性 15 / 气质关键词 15 加权。
2. **字号是算出来的**：`短边 × 场景基准比 × 粗细修正 × 平台字号倍率`，描边与安全边距同表推导；
   竖屏字幕必须上抬（抖音/快手 18%）避开点赞栏与底部文案区——压上去等于没交付。
3. **"看起来没问题"不算交付**：六项复检（时间轴回读 / 字幕可现度 / 版式体检 / 字体解析 / 分辨率 / 音轨）任一不过，
   工具直接删产物（do-no-harm）。
4. **字体不进仓库，档案与引脚进仓库**：29 款约 128MB，进仓库会让每次克隆、CI 与桌面载荷都背这份体积；
   因此仓库保存**打标 + 许可 + sha256**，工位按 `kit/fonts-pin.json` 逐文件校验后安装（OFL 再分发要求随许可文本落盘）。

## 1. 为什么字幕值得单设岗位

| 理由 | 说明 |
|---|---|
| 它是**信息传达的第一载体** | 同一句话，字体、字号、描边、位置换一下，观众读到的信息量完全不同；竖屏上压住 UI 就是看不清。 |
| 它有**硬技术面** | 字号占短边比、行宽、安全区、对比度、时间轴精度、字体解析——每一项都有客观验收线。 |
| 它跨所有内容类型 | 口播/美食/旅拍/科技/美妆/亲子/汽车/房产/促销/纪录/高端品牌/剧情/悬疑/综艺，每类的字体语言不同。 |
| 它踩**版权红线** | 字体是外部权利最密集的素材之一：商用交付用错许可、把字体文件随包分发、子集化后改名不合规，都是风险。 |
| 它决定**观感与合规能不能过** | 字号过小、字幕压 UI、中英混排断行难看，会直接影响完播与投诉。 |

## 2. 岗位卡

| 项 | 内容 |
|---|---|
| 官衔 | 字幕师（`preset_key: subtitle-stylist`） |
| 定位 | 成片后期的文字负责人：选型 → 版式 → 烧录 → 复检 → 出证据包 |
| 上级/协作 | 上游：剪辑师（无字幕母版 + SRT）、调色师（已调色母版）；下游：BGM 配乐师（消费已烧字幕成片）、发布运营 |

| 产物 | 成片（新文件）+ `subtitle_track`（字幕轨/版式方案）+ `subtitle_report`（字幕报告）+ 证据帧（标题/首条字幕/末条字幕） |

## 4. 核心问题的正面回答：标题字幕怎么落地到成片

上游交付的是**无字幕母版**（画面已定稿、已调色）+ 一份 **SRT**（听译/转写产物）。字幕师的工作分四段：

```
无字幕母版 + SRT
  ↓ ① 诊断：抽帧量化字幕带背景（亮度/细节密度），查平台遮挡区命中
  ↓ ② 选型：场景×语言硬过滤 → 五维加权 → 账号视觉锤优先 → Top-N + 理由 + 字号
  ↓ ③ 版式：字号=短边×基准比×粗细修正×平台倍率；描边/底衬由实测决定；标题与字幕分层
  ↓ ④ 烧录：SRT→ASS（PlayRes=实际分辨率）→ ffmpeg libass（扁平字体目录）→ 六项复检
  ↓ ⑤ 扩展轨（按需）：弹幕（滚动/固定 + 密度熔断）· 贴纸花字（200ms 弹入）· 卡拉OK（\kf 逐字）· 双语第二行
  ↓ 交付：新成片 + subtitle_track + subtitle_report + 证据帧 + sha256
```

**为什么字幕在调色之后、配乐之前**：
- 调色会改像素，字幕必须先落地在**已定色**的画面上，否则字幕颜色也会被 LUT 改掉；
- 配乐只动音轨（视频轨恒 copy），放在字幕之后可以一次成片，不需要重复编码画面。

**为什么强调"字体真的被用上"**：libass 的 `fontsdir` 不递归子目录。工位字体目录是 `cn/`、`en/` 两层时，
直接把根目录交给 ffmpeg 会**静默回落系统字体**——报告里写着"霞鹜文楷"，成片里其实是苹方，而所有指标都"看起来正常"。
本能力因此在渲染前把字体目录摊平成临时单层目录，并在渲染后解析 `fontselect` 日志，出现系统字体路径即判失败。

## 5. 字体档案工程（打标八维 + 字号/版式策略）

档案事实源：`library/font-catalog/font_db.json`（v1.1，29 款：中文 13 + 英文 16）。

| 维度 | 用途 |
|---|---|
| 语言 / 场景 | 硬过滤（中文内容必须支持中文；草书不得进字幕） |
| 风格标签 / 气质关键词 | 语义命中（含上游文生视频提示词的全文命中） |
| 适合作品类型（14 类） | 题材匹配（生活vlog/产品/宣传片/知识/国风/游戏/影视混剪…） |
| 艺术气息 1~5 / 字体粗细程度 0.5~5 | 与调性、场景的适配度计算 |
| 适配BGM节奏 慢/中/快 | 与片子节奏匹配 |
| 许可 / sha256 / 来源 | 商用白名单判定与文件核验 |

策略同档案：`size_policy`（字号基准比/描边比/安全边距比）、`layout_policy`（六平台版式 + **遮挡区矩形**）、
`account_persona`（锁定字体与艺术气息区间示例）。

## 7. 字幕师的一天（标准工作流）

```
接收无字幕母版（剪辑师/调色师交付）+ SRT（听译）
  ↓ 四问：给谁看？在哪看（平台）？看多久（时长/节奏）？片子什么调性？
  ↓ subtitleread.health：确认引擎、libass、字体在位（缺字体先装，绝不"缺字也发"）
  ↓ subtitleread.analyze：字幕带亮度/细节密度、遮挡区命中、抽帧证据
  ↓ subtitleread.fonts：场景×语言过滤 → 五维打分 → Top-N + 理由（账号锁定字体优先）
  ↓ subtitleread.recipes：平台版式 + 题材配方（含禁忌）
  ↓ subtitlewrite.plan：出 ASS 方案 + 版式体检（字号/行宽/安全区/对比/墨迹实测/fontselect）
  ↓ subtitlewrite.burn：烧录字幕（+ subtitlewrite.title 出片头标题）
  ↓ 六项复检：时间轴回读 / 可现度 / 版式 / 字体解析 / 分辨率 / 音轨
  ↓ 交付：新成片 + subtitle_track + subtitle_report + 证据帧 + sha256
```

不确定时先跑 `subtitlewrite.best`：候选池（字体 × 描边策略）各渲染一帧打分，赢家再出正式成片；
若素材**已经带硬字幕**或本就没有字幕内容，如实报"无需加字幕"并停手。

## 8. 交付标准（不达标不算完成）

1. 成片 sha256 + 使用的字体（id / 家族 / fullname / 文件 sha256 / 许可）；
2. 版式体检：字号占短边比、行宽、安全区（实测墨迹外接框 × 遮挡区）、对比度；
3. 字幕可现度：加字前后字幕带的边缘能量/亮度增量（Δ ≥ 0.004；不足则工具拒绝出片）；
4. 时间轴回读：ASS 事件与源 SRT 逐条一致（条数 + 起止）；
5. 字体解析：`fontselect` 全部命中工位字体目录（无系统字体回落）；
6. 分辨率与音轨保持：与母版一致（音轨 copy）；
7. 证据帧：标题帧 + 首条字幕 + 末条字幕（PNG，带 sha256，按产物名打前缀）；
8. 扩展轨（用到时）：弹幕密度与抽稀条数、贴纸停留时长与落点、卡拉OK 逐字时长误差与口径（显式/均分）、双语两行版式体检。

## 9. 与上下游的接口

| 对手方 | 字幕师接收/交付什么 | 冲突时的裁决 |
|---|---|---|
| 剪辑师 | 接收无字幕母版 + SRT；时间轴问题退回上游，不手改时间轴 | 剪辑定节奏，字幕只做文字层 |
| 调色师 | 接收已调色母版；字幕在调色之后烧 | 画面先定色，文字后上（字幕色不被 LUT 改） |
| BGM 配乐师 | 交付已烧字幕成片（音轨 copy） | 音画互不阻塞，顺序字幕 → 配乐 |
| 发布运营 | 交付成片 + 封面标题建议 + 平台变体 | 变体不重排字幕 |
| 合规/品牌 | 字体许可、品牌视觉锤变更（G-SUB1） | 合规优先 |

**考试院题目方向（建议）**：① 竖屏 1080×1920 下 22 字长句怎么处理；
② 浅色雪地背景上白字看不见怎么改；③ 抖音字幕为什么必须上抬 18%；
④ 客户指定方正字体但拿不出授权；⑤ 母版已带硬字幕、客户要求"再叠一层中英双语"的处置；
⑥ `fontsdir` 给了根目录时会发生什么、怎么发现。

## 11. 边界（本岗位不做什么）

- ❌ 不做剪辑决策、不改叙事、不改台词内容（只处理文字层）；
- ❌ 不动音频（音轨恒 copy），不做混音与配乐；
- ❌ 不做 HDR/杜比视界字幕（第一版口径，遇到按"超出交付口径"上报）；
- ❌ 不重新生成 AI 视频（只处理已成片素材）；
- ❌ 不负责对外发布（发布是发布运营的职责，走 G9）；
- ❌ 不做字体子集化、不改字体文件、不随产品分发字体二进制；
- ❌ 不用描边/底衬掩盖素材问题（过曝无安全区、已有硬字幕、画面抖动 → 如实上报回退上游）。

## 13. 设计边界与遗留

1. **画面理解只是"文字带统计"**：亮度与细节密度足以决定描边/底衬/上抬，但不做语义理解（不知道画面里是脸还是字幕区）；
   需要"内容语义驱动选型"时，应由剪辑/导演在简报阶段给出调性与关键词（本能力已优先吃 `视频生成提示词`）。
2. **"已带硬字幕"的检测依赖上游声明**：`subtitlewrite.best` 用 `has_burned_in_subtitles` 显式参数判定，
   没有做 OCR/版式反推（避免误判导致该加字幕时停手）。
3. **遮挡区是本仓工程取值**：依据附件版式的「位置说明」落成矩形；平台 UI 改版时需要按同一口径更新并回归。
4. **字体已随仓分发，上游直链只作升级比对**：`fonts-pin.json` 把实测逐字节一致的直链标 `verifiedAt`，
   其余条目仅用于升级比对（升级时必须先下载核验 sha256 再回填，不得直接替换随包字体）。
5. **两隔离副本（growthtest / growthmatrix）** 的移植按产品所有者指令执行（见任务回执），
   移植后以各自仓的回归口径重新验证，不以本仓结论代表它们。
