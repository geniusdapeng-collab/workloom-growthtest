# 设计需求分析（Design Brief）

## 触发
任何视觉任务开工前。禁止拿到一句话就直接排版。

## 方法
1. 六问澄清（能自行推断的先推断并标注假设，方向性冲突才回问客户）：
   - 给谁看（受众画像与场景）？
   - 发在哪（平台/尺寸/投放方式）？
   - 要什么行动（到店/私信/下单/收藏）？
   - 成功标准（点击/到店/询盘，口径可量化）？
   - 必须出现与必须不出现（品牌锚点/价格/合规红线）？
   - 交付规格（画布/格式/数量/截止）。
2. 产出 `brief.json`（字段固定，写入一客一档）：
   `{audience, channel, objective, success_metric, must_include[], must_avoid[], assets_available[], specs{width,height,format}, deadline, assumptions[]}`
3. 把"素材从哪来"写进 brief：客户实拍 > 正版图库 > AI 生图（优先级与授权说明）。

## 输出契约
- brief.json + 一句设计目标陈述（"让 X 人群看到 Y 后做 Z"）；
- 人（客户/运营负责人）确认后才进入 art-direction。

## 边界
- 不替客户编造价格/资质/参数；缺失信息列入 assumptions 并显式标注"待确认"；
- 方向性冲突（如既要求"高端克制"又要求"大促叫卖"）必须澄清，不得同时塞进一张图。

## 工艺判据（条件 → 做法 → 判据 → 来源）

| 条件 | 做法 | 判据 | 来源 |
|---|---|---|---|
| 收到任何视觉任务 | 先跑六问澄清（受众/渠道/行动/成功标准/必含与禁含/交付规格） | 六问答案齐备或列入 `assumptions[]` 标"待确认" | KB:本套件 §方法 1 |
| 输出 brief | 固定字段写 `brief.json`（含 `specs{width,height,format}` 与 `deadline`） | 字段不可缺；写入一客一档 | KB:本套件 §方法 2 |
| 素材来源 | 写明优先级：客户实拍 > 正版图库 > AI 生图 | 未写明来源即视为未完成 | KB:本套件 §方法 3 |
| 成功标准 | 必须可量化（点击/到店/询盘口径） | 出现"效果好/高大上"等不可量化表述即打回 | KB:本套件 §方法 1·④ |
| 方向性冲突 | 必须澄清（如"高端克制"×"大促叫卖"） | 未澄清即开工判流程缺陷 | KB:本套件 §边界 |
| 进入下一步 | 人（客户/运营负责人）确认 | 未确认不得进 `art-direction` | KB:本套件 §输出契约 |

## 参数边界

1. `brief.json` 必填字段：`audience / channel / objective / success_metric / must_include[] / must_avoid[] / assets_available[] / specs / deadline / assumptions[]`——缺任一即视为未完成。
2. `success_metric` 必须可量化；不可量化的表述一律打回。
3. `must_avoid[]` 至少包含合规红线（极限词、医疗金融承诺）与品牌禁区。
4. 缺失信息只能进 `assumptions[]` 并标"待确认"，**不得用行业默认值静默补齐**。
5. 未获人确认的 brief 不得进入排版与渲染（防止白做）。

## 失败模式（症状 → 检测器 → 处置）

| 症状 | 检测器 | 处置 |
|---|---|---|
| 拿到一句话就直接排版 | `brief.json` 缺失检查 | 停下补 brief；补不齐就问，不得硬做 |
| 成功标准无法量化 | `success_metric` 校验 | 打回并给出可选量化口径 |
| 规格缺失导致反复改尺寸 | `specs` 必填校验 | 补齐画布/格式/数量后再开工 |
| 方向性冲突被塞进同一张图 | brief 内部一致性检查 | 澄清择一；记录裁决理由 |
| 用默认值补齐缺失信息 | `assumptions[]` 标注检查 | 改为显式"待确认"，并回问客户 |
| 未确认就开跑导致返工 | 人确认记录检查 | 补确认；返工成本记入复盘 |
