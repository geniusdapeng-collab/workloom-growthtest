# 交付包与多风格变体

## 一、为什么要有这一套

镜头生成（Seedance 渲染）是整条链路里**唯一贵且慢**的环节；剪、调、配、加字幕、出封面全是本地算力。
既然用户"最后可能不满意"，就不要让他拿着一支片子来回怼，而是**一次给几个风格明显不同的版本让他挑**：
服务方多花的是本地几分钟，省下的是"整片重生成"的 token 与等待。

三句话口径：

1. **镜头只生成一次**，变体只在后期派生（本套件所有产物都记录 `tokenCostDelta: 0`）；
2. **母版永远不烧字**，字幕以旁挂文件交付（要带字幕的片子与不要字幕的片子，从同一支干净母版派生）；
3. **没有清单就不是交付**：用户要能看见"有哪几个版本、差在哪、每个文件是什么"。

## 二、一次交付包里有什么

| 产物 | 路径口径 | 说明 |
|---|---|---|
| 干净母版 | `master/master-clean.mp4` | 拼接后未调色未配乐未烧字的母版；后续返修的地基 |
| 旁挂字幕 | `subtitles/<项目>.zh.srt`/`.zh.ass`/`.vtt` + `subtitle-manifest.json` | 不烧进画面；ASS 与烧录同源（同一字体选型/版式），VTT 供平台后台上传 |
| 变体成片 | `variants/<变体>/<变体>.mp4` | 该风格的成片（无字幕轨） |
| 软字幕轨版 | `variants/<变体>/<变体>.softsub.mp4` | 字幕作为**可开关字幕轨**；实际视频/音频 copy；源 SHA、普通流元数据与字幕轨回读 |
| 硬字幕副本（可选） | `variants/<变体>/<变体>.burned.mp4` | 仅在明确要硬字幕时产出；母版仍不烧 |
| 封面 | `variants/<变体>/cover.png` | 按变体的封面版式与文案渲染（字体同源） |
| 文案包 | `variants/<变体>/copy.md`/`copy.json` | 标题/钩子/正文/话题/CTA + 四条校验（标题长度、钩子、话题数、CTA） |
| 音频回执 | `variants/<变体>/audio.json` | 曲目、署名、请求配方、源与输出摘要；质量指标未测时为 null |
| 交付清单 | `delivery-manifest.json` | 全部产物 sha256、实际规格、声明配方、处理结果和成本口径 |
| 工程文件 | `film-project.json` | 层结构（镜头/拼接/调色/音频/文字/封面/文案）+ 产物血缘，**返修的输入** |
| 人看版说明 | `delivery-report.md` | 变体对照表、已执行配方、返修路径、真实处理错误；品质差异未测 |

`project.quality` 为 `hd`（缺省）或 `uhd`。按已请求画布归一化并回读实际输出；不因源分辨率不足自动调用 AI 增强或建立成功素材品质否决。原始字节、实际处理与导出画布记录在清单；请求处理失败明确报错。

## 三、五个风格轴（按请求声明配方）

| 轴 | 取值来源 | 用户能感知什么 |
|---|---|---|
| 调色 | `library/color-recipes` + `library/luts`（profile/LUT × intensity） | 冷暖、浓淡、质感 |
| BGM | `library/bgm-library*`（情绪/曲风 × 电平 × 分层策略） | 情绪与节奏感 |
| 转场节奏 | `hard` 硬切 / `fade` 慢入慢出 / `xfade` 交叉溶解 | 片子的呼吸 |
| 封面 | 抽帧时刻 × 版式 × 标题钩子 | 点击率 |
| 文案 | 标题模板/开场/收尾/CTA/话题（口吻包） | 说什么、怎么说 |

内置三个明显拉开距离的默认变体（`library/style-variants/`）：

| 变体 | 定位 | 一眼能看出的差别 |
|---|---|---|
| `warm-story` 暖调故事版 | 情感/文旅/民宿 | 暖调胶片 + 慢转场 + 木质原声 + 留白题签 |
| `clean-tech` 干净科技版 | 产品/科技/知识 | 冷净调 + 硬切 + 极简律动 + 参数卡封面 |
| `bold-promo` 强推促销版 | 带货/本地生活 | 高对比 + 交叉溶解快切 + 高燃曲 + 促销横幅 |

## 四、声明配方与真实处理回执

- 校验请求配方不同并执行真实处理；记录实际文件、源摘要和导出规格。
- 不自动抽帧、测像素差、LUFS 或峰值作品质投票；`qualityReviewPerformed=false`、差异实测未执行。
- 成功素材默认采用，黑帧、服装、动作、口型、台词或主观差异不触发拒收、重渲、模型/人工评审。
- 实际缺文件、输入改变、混音/字幕/封面/导出失败仍停止；不能用文件存在冒充请求已完成。

## 五、成本口径（写进清单，不许口头说）

```json
{ "shotGeneration": "reused（本包未生成任何新镜头）", "tokenCostDelta": 0,
  "note": "多风格变体只吃本地算力：镜头生成费只付一次，风格差异零 token" }
```

返修场景下这条更值钱：换字幕/换曲/换调色/换封面都不重生成镜头（详见 `delivery-revision-ops`）。

## 六、不达标怎么办（do-no-harm）

| 情形 | 处置 |
|---|---|
| 请求的配乐处理失败 | 记录真实错误并停止；不自动降 3dB 重试、不静默改为原声 |
| 旧品质或多版本差异评审不通过 | 保留历史行，成功原片仍默认采用；用户明确反馈后再按授权修改指定后期层 |
| 母版被外部改动（哈希与工程文件不一致） | 返修时如实标注"被外部改动过"，不当作复用 |
| 字体/曲目/文缺少件 | 报错并指名缺什么（不回退系统字体、不静默换曲） |

## 七、与上下游的接口

| 对手方 | 接收/交付 | 冲突裁决 |
|---|---|---|
| 渲染师 | 接收逐镜成功任务与本地原片字节 | 默认采用成功素材；新镜头必须由用户明确授权新增范围与预算 |
| 字幕师 | 交付旁挂字幕文件与软字幕轨 | 文字层由字幕师定版式，本工位只负责"怎么装进交付包" |
| 调色师 / 配乐师 | 单次执行声明配方 | 实际处理错误停止，不作品质评分或自动候选重试 |
| 发布运营 | 交付变体 + 封面 + 文案 + 软字幕轨 | 变体差异由本工位保证，发布策略由运营定 |
| 剪辑师 | 交付 `film-project.json`（工程文件） | 返修走剪辑师的本地重合成，不重生成镜头 |

## 八、质量指标（用于绩效与考试院）

| 指标 | 目标 | 数据来源 |
|---|---|---|
| 请求配方执行与回执完整率 | 100% | 声明配方、输出摘要、处理结果；品质差异未测 |
| 母版零烧字率 | 100% | `manifest.master.subtitles = none` + `subtitle-manifest.json#burnedIn=false` |
| 旁挂字幕时间轴回读一致率 | 100% | `subtitle-manifest.json#timeline.readback` |
| 软字幕画面零改动率 | 100% | 实际 copy 命令、源 SHA、流元数据与字幕轨回读 |
| 文案四检通过率 | ≥ 95% | `copy.json#checks` |
| 变体一次性被选中率 | 观察指标（≥ 60% 首次选中） | 用户选择事件 |
| 返修免重生成率 | ≥ 80%（本地重合成解决的比例） | `revision.json#impact.localOnly` |

**考试院题目方向**：① 用户说"想要更高级一点"，应该改哪几个轴、为什么不该重生成镜头；
② 如何区分声明配方重复、实际处理失败与未执行的品质差异评审；
③ 客户要"发布版不带字幕、内部审看带字幕"，一支母版怎么办；
④ 实际混音失败为何应停止而不能自动降音量或交付无配乐版本；
⑤ 交付包里少了 `film-project.json`，下一轮返修会多花多少代价。
