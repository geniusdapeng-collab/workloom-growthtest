# 题材×场景调色设计

## 一句话

**颜色不是审美口味的自由发挥，是内容意图的翻译。** 先回答"这支片子要让观众产生什么感受、发到哪个平台"，再决定冷暖、对比、饱和。

## 一、定调四问（每次开工先答完，缺一不许动手）

1. **题材是什么**（产品广告 / 人物访谈 / 美食 / 科技 / 户外 / 夜景 / 美妆 / 亲子 / 汽车 / 房产 / 节日促销 / 纪录片 / 高端品牌）
2. **场景与主体是什么**（棚拍还是实景？有人脸吗？商品本色是品牌资产吗？）
3. **情绪目标是什么**（可信 / 诱人 / 冷静 / 热烈 / 克制 / 有故事感）
4. **发到哪个平台**（抖音、小红书、视频号、B站、官网……小屏要高对比，官网要克制）

答案 → 配方 id → 参数。**禁止跳过配方库自己拍脑袋调参**。

### 先答第零问：**这片子真的需要调吗？**

拿到的是**已调色的成片母版**（平台交付版、外包已调色版、或画面本身已达标的素材）时，正确答案常常是**不动**：

- 判据（用 `colorwrite.best` 自动跑）：候选池里没有任何方案比原片高 2 分以上 → 输出"无需调色"，**不产出文件**；
- 需要调的是**未调色的相机原片 / log 素材 / 生成视频**，或确实存在缺陷（偏色、欠曝、发灰、多镜不一致）；
- **给已经很好的画面上妆，只会把它弄坏**——这是本岗位最容易犯的错。

## 二、配方库检索（唯一选型来源）

```bash
color-cli recipes --list                        # 看全部题材
color-cli recipes --genre 美食                   # 按题材匹配
color-cli recipes --platform 小红书 --keyword 美妆 # 按平台+关键词匹配
color-cli recipes --id food-appetite            # 取具体配方
```

**配方直接喂给择优**（推荐姿势）：先判定题材，再让候选池围绕该配方生成——

```bash
color-cli best --in clip.mp4 --out graded.mp4 --genre 美食      # 配方驱动：题材决定方向，画质分决定力度与动不动
color-cli best --in clip.mp4 --out graded.mp4 --recipe food-appetite
```

工具侧对应 `colorwrite.best` 的 `genre` / `recipe_id` / `platform` 参数：候选池会围绕该配方的 look 与建议强度（±0.2 三档 + 配方 LUT）生成，再与通用候选一起打分择优。

工具：`colorread.recipes`（返回 profile / LUT 绝对路径 / 建议强度 / 目标区间 / 平台 / 避免事项）。
返回的 `targets` 已经包含该题材对 YAVG/SATAVG 的**收窄覆盖**（例如美食允许 55–85 的饱和、纪录片只允许 35–60）。

## 三、情绪 → 色彩映射（配方不覆盖时的兜底依据）

| 想要的感受 | 色温 | 对比 | 饱和 | 手法 |
|---|---|---|---|---|
| 可信、专业 | 中性偏冷 | 中 | 中低 | 保白平衡准确，少风格 |
| 温暖、亲密 | 暖（+8~15 mired） | 中 | 中 | 提黑位、暖高光 |
| 诱人、冲动 | 暖 | 中高 | 高 | 红黄推进，高光通透不爆 |
| 冷静、精密 | 冷 | 中高 | 低 | 阴影偏青蓝，高光微冷 |
| 戏剧、故事 | 冷暖对冲 | 高 | 中 | 阴影青、高光橙（青橙） |
| 高级、克制 | 冷灰 | 中 | 低 | 去饱和 + 保留高光层次 |

## 四、平台适配（同一支片子，不同平台只改表达不改事实）

- **抖音/快手**：小屏、强竞争 → 对比 +5~10%，饱和 +5%，暗部略提（手机在户外看）；
- **小红书**：审美导向 → 干净、低对比、肤色自然，忌脏黄；
- **视频号**：中老年受众多 → 亮度略高、对比略低，字幕对比度必须够；
- **B站/官网**：屏幕大、可看细节 → 保留层次，避免过度风格化；
- **平台变体从已调色母版派生**：不重新调色，只做画幅/时长派生。

## 五、禁忌清单（命中即回退）

- ❌ 一个项目用两套 look（同一支片子里风格跳变 = 观众出戏）
- ❌ 用饱和度掩盖白平衡问题（先修白平衡）
- ❌ 商品/品牌色相偏移（车漆、口红、食品本色属品牌资产）
- ❌ 肤色被推到橙红或灰绿（美妆/访谈尤甚）
- ❌ 高光爆掉却宣称"电影感"（信息丢了就是丢了）
- ❌ 夜景硬按白天下限提亮（噪点被放大，反而更廉价）

## 六、输出

选型必须落成可核验的一段话：**题材 + 场景 + 情绪 + 配方 id + profile/LUT + 强度 + 目标区间 + 本片特例**，并随调色报告归档（证据链，便于返工时定位是"选型错"还是"执行错"）。

## 失败模式（症状 → 检测器 → 处置）

| 症状 | 检测器 | 处置 | 案例 |
|---|---|---|---|
| 同一支片子里风格跳变（前后两套 look） | 调色报告的 profile/LUT 标识是否唯一 | 统一到一套 look；平台变体只能从**已调色母版**派生，禁止二次调色 | — |
| 画面"更艳"但偏色没修（用饱和掩盖白平衡） | `neutral_patch` 中性物残差 + 肤色 hue 复检 | 先修白平衡再谈 look；回退本次 look 重跑 | FC-COL-002 |
| 品牌资产色相被推偏（车漆/口红/食品本色） | 与档案 confirmed 色值/参考帧比对色相差 | 该 look 判失败，降强度或换 profile；品牌色优先于风格 | — |
| 高光爆掉却宣称"电影感" | 裁切率（>1% 报警、>3% 回退） | 回退该候选，降强度或换更保守 profile | — |
| 美妆/访谈被推成橙红或灰绿 | 强度表（美妆 ≤0.5）+ 肤色 hue 20–40° | 降强度重跑；肤色偏差优先修光源与白平衡 | — |
| 给已调色母版"上妆"，成片反而不如原片 | `colorwrite.best` 候选池无方案超过原片 +2 分 | 输出"无需调色"，**不产出文件**（do-no-harm） | FC-COL-006 |
