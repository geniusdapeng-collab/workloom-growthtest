# 题材×场景调色设计

## 一句话

**颜色不是审美口味的自由发挥，是内容意图的翻译。** 先回答"这支片子要让观众产生什么感受、发到哪个平台"，再决定冷暖、对比、饱和。

## 一、定调四问（每次开工先答完，作为选型说明，缺省按请求上下文推断并记录）

1. **题材是什么**（产品广告 / 人物访谈 / 美食 / 科技 / 户外 / 夜景 / 美妆 / 亲子 / 汽车 / 房产 / 节日促销 / 纪录片 / 高端品牌）
2. **场景与主体是什么**（棚拍还是实景？有人脸吗？商品本色是品牌资产吗？）
3. **情绪目标是什么**（可信 / 诱人 / 冷静 / 热烈 / 克制 / 有故事感）
4. **发到哪个平台**（抖音、小红书、视频号、B站、官网……小屏要高对比，官网要克制）

答案 → 配方 id → 参数。**禁止跳过配方库自己拍脑袋调参**。

### 已声明调色请求直接执行

成功源镜头默认采用。根据题材和用户参数选定一个配方，实际处理一次；不以“原片是否好看”决定是否出文件。`colorwrite.best` 兼容入口执行声明配方，候选为空、评分为 null，不跑原片 +2 分、肤色、像素或清晰度准入票决。

## 二、配方库检索（唯一选型来源）

```bash
color-cli recipes --list                        # 看全部题材
color-cli recipes --genre 美食                   # 按题材匹配
color-cli recipes --platform 小红书 --keyword 美妆 # 按平台+关键词匹配
color-cli recipes --id food-appetite            # 取具体配方
```

**配方直接喂给执行入口**：先判定题材，再执行一套声明配方——

```bash
color-cli best --in clip.mp4 --out graded.mp4 --genre 美食      # 配方驱动：题材决定默认方向，按请求执行一次
color-cli best --in clip.mp4 --out graded.mp4 --recipe food-appetite
```

工具侧对应 `colorwrite.best` 的 `genre` / `recipe_id` / `platform` 参数：按该配方的 look/LUT 与建议强度执行一次，不自动抽帧比较候选。

工具：`colorread.recipes`（返回 profile / LUT 绝对路径 / 建议强度 / 目标区间 / 平台 / 避免事项）。
返回的 `targets` 已经包含该题材对 YAVG/SATAVG 的**收窄覆盖**（例如美食允许 55–85 的饱和、纪录片只允许 35–60）。

## 三、情绪 → 色彩映射（配方不覆盖时的兜底依据）

| 想要的感受 | 色温 | 对比 | 饱和 | 手法 |
|---|---|---|---|---|
| 可信、专业 | 中性偏冷 | 中 | 中低 | 保白平衡准确，少风格 |
| 温暖、亲密 | 暖（+8~15 mired） | 中 | 中 | 提黑位、暖高光 |
| 诱人、冲动 | 暖 | 中高 | 高 | 红黄推进，高光通透不爆 |
| 冷静、精密 | 冷 | 中高 | 低 | 阴影偏青蓝，高光微冷 |
| 戏剧、故事 | 冷暖对冲 | 高 | 中 | 阴影青、高光橙（青橙） |
| 高级、克制 | 冷灰 | 中 | 低 | 去饱和 + 保留高光层次 |

## 四、平台适配（同一支片子，不同平台只改表达不改事实）

- **抖音/快手**：小屏、强竞争 → 对比 +5~10%，饱和 +5%，暗部略提（手机在户外看）；
- **小红书**：审美导向 → 干净、低对比、肤色自然，忌脏黄；
- **视频号**：中老年受众多 → 亮度略高、对比略低，字幕对比度必须够；
- **B站/官网**：屏幕大、可看细节 → 保留层次，避免过度风格化；
- **平台变体从已调色母版派生**：不重新调色，只做画幅/时长派生。

## 五、设计建议（用于选型与明确反馈，不作成功素材准入）

- ❌ 一个项目用两套 look（同一支片子里风格跳变 = 观众出戏）
- ❌ 用饱和度掩盖白平衡问题（先修白平衡）
- ❌ 商品/品牌色相偏移（车漆、口红、食品本色属品牌资产）
- ❌ 肤色被推到橙红或灰绿（美妆/访谈尤甚）
- ❌ 高光爆掉却宣称"电影感"（信息丢了就是丢了）
- ❌ 夜景硬按白天下限提亮（噪点被放大，反而更廉价）

## 六、输出

选型必须落成可核验的一段话：**题材 + 场景 + 情绪 + 配方 id + profile/LUT + 强度 + 目标区间 + 本片特例**，并随调色报告归档（证据链，便于返工时定位是"选型错"还是"执行错"）。

## 执行与反馈

记录题材、配方与实际参数，原片只读，源/产物 SHA 和实际输出元数据回读。没有品质诊断时不声称肤色、裁切或画质已验证；不以设计建议拒收、删文件、重渲或要求模型/人审。

用户明确反馈风格、偏色或强度时修改指定调色层；新增镜头生成另走事前授权与预算。路径、LUT、磁盘或 ffmpeg 真实错误仍停止并留痕。

## 工艺执行与参数边界

1. 输入必须是当前项目授权的本地原片；读取普通元数据与 SHA256，实际调色前保留源路径与摘要。源文件缺失、越界或字节变化立即失败，不用旧品质意见决定采用。
2. 选定声明配方、profile/LUT 和强度，先校验配方与 LUT 文件真实存在。强度须在入口声明的有限数值范围内；不得把缺 LUT 当作 `natural` 或静默换配方。
3. 执行一次请求的 grade/match/denoise 配方，输出新文件；必须回读实际输出时长、画布、音轨与摘要。`best` 的选择理由来自声明配方，候选数为零，评分为 null。
4. 配方中的 YAVG/SATAVG、肤色与裁切目标是设计建议；没有显式诊断时不得宣称达标。`match` 未测 residual 时为 null，不能格式化为零或假精度。
5. 用户明确要求改风格时复用源字节，只修改已授权调色层。禁止自动复评、删除成功产物或重新生成镜头；真实 ffmpeg/磁盘错误保留失败。

## 失败模式（症状 → 原因 → 处置）

| 症状 | 首查原因/检测器 | 处置 |
|---|---|---|
| 指定配方或 LUT 无法加载 | 配方 id、声明路径、文件摘要与许可 | 报缺失项并停止；补同一授权资产后重试，不自动换 look |
| 源文件在执行前后变化 | 输入 SHA256 与已记录路径 | 返回输入变化错误；不得把旧回执用于新字节 |
| ffmpeg 退出、磁盘满或输出不存在 | 实际退出码、stderr、输出文件与普通元数据 | 返回处理失败，保留日志；修复工具或存储后执行同一请求 |
| 报告显示 NaN/虚构匹配精度 | residual/metrics 的 null 状态与 CLI 展示 | 如实显示未测；不能凭空补分或改为成功品质认证 |
| 用户反馈色调不合意 | 已声明配方、强度和用户指定层 | 按反馈改调色层并保留历史；不触发镜头重渲或默认品质模型 |
