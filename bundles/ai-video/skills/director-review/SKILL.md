# 导演评审（6 问 5 维）

## 适用场景
- 提示词包交付前的导演级评审（G6 审批卡评分附件）
- 营销片事实红线阻断闸（`truth-check`，位于创意主题之后、业务需求对齐之前）
- 跨集/跨镜头连贯性校验与硬阻断

## 触发条件
- 每个镜头包在 G6 前必评；营销片另需在创意主题定稿后单独过一次事实红线闸
- 复跑只重跑某一段时，必须复核该段涉及的镜头与门，不能沿用旧裁决（`mode=recheck`）

## 决策原则（含阈值与失败关闭）
1. **硬阻断优先于评分**：造型无理由不一致 / 总时长不符 / 台词重复 / 事实红线命中 → 直接打回，不进入"平均分协商"。（来源：KB:`docs/pipeline-stages-and-gates-2026-09-24.md` §一·判据）
2. **五维任一不过线即整体不通过**：禁止用平均分掩盖单维短板；报告必须逐维给分与理由。（来源：KB:同前 §一·`continuity` 硬阻断 + 五维评分）
3. **事实红线以档案 confirmed 字段为准**：与 confirmed 字段矛盾的表述/创意前提即命中；reported 需标注不确定；inferred 不得作为事实陈述。事实红线未接线或未执行时，必须显式标注"未执行/降级"，不得默认放行。（来源：KB:`bundles/ai-video/pipelines/marketing-film.yml` step `truth-check` + `presets/director.yml` 约束）
4. **时长口径唯一权威源是 PRD**：台词字数按 3.5 字/秒反推；超带即重写台词，不指望后期硬剪。（来源：KB:`bundles/ai-video/presets/scriptwriter.yml`）
5. **打回必须可执行**：定位到字段/镜头，写清"改什么、改成什么、为什么"；禁笼统批语（如"再优化一下"）。（来源：KB:`presets/director.yml` + 本仓监制门纪律）
6. **软信号必须写进报告**：时段倒退 / 方向相反 / 道具消失 / 缺收束镜属软信号——不阻断，但漏报视为评审不完整。（来源：KB:`docs/pipeline-stages-and-gates-2026-09-24.md` §一）
7. **评审输入必须含正文**：只给路径清单会导致"无正文可核验"的误杀；正文按预算送入（单文件 ≤1600 字、总量 ≤12000 字）。（来源：KB:同前 §三·4 真机案例）

## 打法库（场景 → 动作序列 → 判据）
- **主线（单镜头包评审）**：确定性硬闸（空内容/占位符/字数/语速/朝向互斥/时长）→ 6 问 → 5 维评分 → 裁决 → 留痕。判据：报告含 6 问结论 + 5 维分数 + 阻断项 + 可执行修复指向。
- **分支 1（跨集/跨镜连贯性）**：角色形象 → 镜头方向 → 道具在场性三线逐条比对（`cross-episode-validator`）。判据：每条比对给出"一致/不一致 + 证据镜头号"。
- **分支 2（事实红线专项）**：创意前提逐条对照档案事实基线（能力清单/使用前提/能力边界/官方口径/禁用宣称）→ 命中即打回创意，不进洞察与 PRD。判据：输出冲突条目 + 对应档案条目编号。
- **分支 3（时长越带）**：先按 3.5 字/秒算台词字数缺口 → 决定"删句/删镜/升时长"，并回写 PRD 口径。判据：修改后字数与时长带自洽，且 PRD 版本同步。

## SOP（每步带触发/回执/失败路径）
1. 触发：镜头包/创意稿送达 → 动作：确定性硬闸（空内容、`NaN`/`[object Object]`/占位符、字数、语速、朝向互斥、时长）→ 回执：硬闸结论（打回或放行）→ 失败：命中即打回且不调用模型（省额度、可复算）。
2. 触发：硬闸通过 → 动作：6 问评审（叙事/情绪/商品真实/时长/平台适配/合规）→ 回执：6 问结论 → 失败：任一问不成立 → 打回并注明对应镜头。
3. 触发：6 问通过 → 动作：5 维评分 + 事实红线检查 → 回执：评分报告（含 `via`=deterministic/llm/fallback 与模型标识）→ 失败：任一维不过线或红线命中 → 打回，不进入 G6 审批。
4. 触发：报告完成 → 动作：作为 G6 审批卡附件提交 → 回执：门事件（`gate/stepKey/checks/verdict`）落 `stages.jsonl` → 失败：门事件缺失视为未评审。
5. 触发：复跑某段 → 动作：`mode=recheck` 复核该段与相邻镜头的连续性 → 回执：复核结论 → 失败：复用旧裁决未复核 → 判为流程缺陷。

## 关键指标（含基准与护栏）
| 指标 | 基准/参考值 | 阈值/护栏 | 来源 |
|---|---|---|---|
| 硬阻断漏检 | 0 | 漏检即整包打回 | KB:pipeline-stages §一 |
| 五维报告完整性 | 5/5 维 + 6/6 问 | 缺维视为评审不完整 | 本套件决策原则 2 |
| 打回可执行率 | 100% 定位到字段/镜头 | 笼统批语视为不合格评审 | KB:presets/director.yml |
| 事实红线执行 | 每次营销片必跑 | 未执行必须显式标 degraded | KB:marketing-film step truth-check |
| 评审输入正文 | 单文件 ≤1600 字 / 总 ≤12000 字 | 无正文 → 不得出"通过"结论 | KB:pipeline-stages §三·4 |
| 门事件留痕 | 每次裁决 1 条 | 无门事件 = 未评审 | KB:gate-ledger.ts |

## 失败模式（症状 → 检测器 → 处置）
| 症状 | 检测器 | 处置 |
|---|---|---|
| 只给路径没给正文 → 评"无正文可核验" | 评审输入检查（正文预算） | 按预算补送正文后重评 |
| "先侧身再转身"被误判朝向矛盾 | 否定剥离 + 顺序词识别（先…再/随后/最后） | 降级为提示，不阻断 |
| "发丝随转头轻摆"被当成回眸 | 关键词收敛（只认 回眸/回头/回望） | 修正信号词，避免误注入 |
| 平均分掩盖单维不合格 | 逐维过线检查 | 打回并要求重做该维 |
| 打回无定位，创作者反复试错 | 可执行性检查 | 退回评审并补齐定位 |
| 事实红线未接线却显示"通过" | 执行证据检查（冲突条目/档案编号） | 判为纸门，按 P0 处置 |

## 输出契约
- 输出：评审报告（6 问结论 + 5 维分数 + 阻断项/修复建议 + 事实红线结论 + `via/model/degraded` 留痕）。
- 打回必须给出可执行的修复指向（到字段/到镜头），禁笼统批语。
- 无工具回执的关键数字标「未核实」，不得宣称完成（L3.6/E3.7）。

## 边界
- 不替代 G6/G7/G8/G9 的人审；本技能产出的是审批材料与建议裁决。
- 不写镜头、不改提示词（属提示词工程师/美术岗）；只指出问题与修复方向。
- 不对无基准图的视觉产物下"像/不像"结论（只能判画质与纪律，并写明依据）。
