# 营销 Brief 解析

## 适用场景
- 客户 Brief 结构化解析与要素校验
- 创意主题生成前的输入规范化（G2 确认门前置；上游是 G1 已确认的情报档案）

## 触发条件
- 接到营销片派活、且情报档案已过 G1（无档案时先走"无档案分支"，见打法库分支 3）
- Brief 出现要素缺失、要素互相矛盾、或卖点与档案不一致时，必须先澄清再进入创意

## 决策原则（含阈值与失败关闭）
1. **卖点 ≤3 且用户共识优先**：核心卖点上限定为 3 条；官方主打 ≠ 用户认账，优先取"用户共识/原话矿"里有证据的卖点；官方宣称与用户共识必须分区标注。（来源：KB:`vendor/.../engines/data-mining-engine/SKILL.md` §五·brief_card）
2. **inferred 不得作核心卖点**：档案里 inferred 级条目只能出现在"待验证观察"，进入核心卖点必须升级到 confirmed/reported；升级不了就删。（来源：同上 §一·铁律 2）
3. **缺口只反问不假设**：任一要素（商品/人群/卖点/平台/时长/预算/禁区）缺失 → 列缺口清单反问；禁止用行业默认值补齐后继续。
4. **时长与结构铁律**：前 2–3 秒为钩子窗口且商品或冲突必须在场；卖点 ≤3 且每镜至多承接 1 个卖点花字；尾镜 CTA 强制在场；镜头时长由分配器产出，禁止手写均分。（来源：KB:`vendor/.../skills/marketing-brief/index.js` · 结构铁律 1/2/3/8）
5. **合规三级预扫**：L1 中文极限词 → L2 英文欺骗性宣称 → L3 平台规则（各平台广告与内容规范）；命中即回写禁区清单，不进入创意。
6. **英雄照未绑定即显式标注**：`productHero.heroImageId` 缺失时输出「⚠️ 渲染前必须补齐」，不阻塞解析、但阻塞渲染（G8 前必须闭环）。
7. **一个 Brief 一套口径**：同一商品多平台投放时，平台差异写在"平台适配"字段（标题字数/话题/合集/封面比例），不得把一套文案复制到所有平台。

## 打法库（场景 → 动作序列 → 判据）
- **主线（完整 Brief）**：抽取七要素 → 对照档案校验卖点 → 合规三级预扫 → 生成 Brief 确认单 → 驱动 12 字段创意主题 → 交 G2。判据：每个卖点可回溯档案条目编号；确认单含要素 + 缺口 + 合规预检结果。
- **分支 1（一句话 Brief）**：只有商品名或一句需求 → 用档案补齐人群/场景候选（标注来源）→ 缺口清单只问必须人定的项（预算/平台/时长/禁区）→ 反问后不得自行开跑。
- **分支 2（服务/B 端、无实物）**：以"服务链路 + 资质 + 履约边界"替代商品参数；演示场景必须是可复现的真实场景（门店/线上流程），禁止编造服务能力。
- **分支 3（无情报档案）**：明确标注"本次无档案支撑"，卖点只能来自客户原始 Brief；所有卖点标 reported，且不得使用绝对化承诺，交 G2 时提示人工重点关注。

## SOP（每步带触发/回执/失败路径）
1. 触发：Brief 文本/工单到达 → 动作：要素抽取（产品/人群/卖点/平台/时长/预算/禁区 + CTA/英雄照/竞品参照）→ 回执：结构化 Brief 草稿 → 失败：文本不可解析（缺商品主体）→ 退回并要求补充商品名，禁止猜商品。
2. 触发：要素抽取完成 → 动作：缺口检查（七要素 + CTA + 英雄照）→ 回执：缺口清单 → 失败：关键要素缺失 → 反问并挂起，不进入创意。
3. 触发：卖点候选就绪 → 动作：对照档案定级（confirmed/reported/inferred）+ 共识优先排序 + 裁剪到 ≤3 → 回执：卖点—证据映射表 → 失败：卖点全为 inferred → 标注"无可用核心卖点"，回退到客户确认。
4. 触发：卖点定稿 → 动作：合规三级预扫（L1 极限词 / L2 英文欺骗词 / L3 平台规则）→ 回执：合规预检结果 + 禁区清单 → 失败：命中红线 → 改写或打回，不得带病进入 G2。
5. 触发：合规通过 → 动作：生成 Brief 确认单并驱动 12 字段创意主题 → 回执：确认单 + 主题字段草稿 → 失败：档案版本过期（>30 天）→ 先走档案复跑/确认，不得用过期情报直接生成。

## 关键指标（含基准与护栏）
| 指标 | 基准/参考值 | 阈值/护栏 | 来源 |
|---|---|---|---|
| 核心卖点数 | ≤3 | 超限即裁剪并按证据强度排序 | KB:marketing-brief · 铁律 2 |
| 卖点溯源率 | 100% 可回溯档案条目编号 | 任一无编号即退回 | KB:data-mining §五·brief_card |
| 要素完整率 | 七要素 + CTA + 英雄照全覆盖或列入缺口 | 缺口未澄清不得进 G2 | 本套件 SOP 2 |
| 钩子窗口 | 前 2–3 秒商品/冲突在场 | 不满足即重写开场 | KB:marketing-brief · 铁律 1 |
| 合规预扫覆盖 | L1/L2/L3 三层全跑 | 任一层未跑视为未完成 | 本套件决策原则 5 |
| 平台规格 | 每个投放平台一套规格 | 一套文案多平台复用视为缺陷 | KB:marketing-brief · 确认单字段 |

## 失败模式（症状 → 检测器 → 处置）
| 症状 | 检测器 | 处置 |
|---|---|---|
| 卖点列了 5–7 条 | 卖点数 >3 检查 | 按证据强度裁到 3，其余转"可选补充" |
| 用官方宣称当卖点、用户根本不认 | 档案分区标注（claim_nature: official/user） | 换成用户共识卖点或标 reported 并降权 |
| 把 inferred 当事实写进 Brief | 置信度标签检查 | 删除或先补证据升级 |
| 时长缺失，下游用默认值开跑 | 要素完整率检查 | 挂起反问（时长属必填） |
| CTA / 英雄照缺失无人提示 | 必填项检查 | 输出显式缺口，渲染前必须闭环 |
| 极限词漏检导致发布被平台拦 | 合规三级预扫 | 补扫并把该词写入禁区清单 |

## 输出契约
- 输出：Brief 确认单（要素字段 + 缺口清单 + 合规预检结果 + 档案引用 + 平台适配）。
- 每个卖点必须可回溯到档案条目编号。
- 无工具回执的关键数字标「未核实」，不得宣称完成（L3.6/E3.7）。

## 边界
- 不生成创意主题与脚本（属创意策划/剧本师；本技能只负责输入规范化与预检）。
- 不替代 G2 人审：确认单是审批材料，不是审批结果。
- 不改写档案内容；发现档案与 Brief 冲突时上报冲突，不自行裁决。
