# 摄影知识库调用（Cinematography KB）

## 一、这个库解决什么

镜头提示词里最关键的不是"写得长"，而是**关键细节对不对**：光圈决定景深与质感、焦距决定空间关系、
光位决定皮肤有没有塑料感、色调决定气质。这些以前靠模型自由发挥，同一个题材能出十种风格。
本技能让 Agent 在落字段前**先去库里走一圈**，按当前场景取"最适合的那一行"，把参数意图翻译成画面语言。

> 库的总则（必须遵守）：**视频生成模型不认技术参数（F 值/ISO/快门数值），只认视觉效果描述。**
> 所以：参数进 trace（给监制复核），提示词正文只写画面语言。

## 二、库的结构

- 位置：`bundles/ai-video/library/cinematography-kb/`（19 篇 + `_INDEX.md`）
- 统一九章式：核心概念 → 分类速查 → 分场景实战 → 视频特有规则 → 常见误区 →
  ⑥ 意图→提示词映射表（核心调用区，中英双语）→ 提示词模板 → 决策树 → 关联知识
- 主题：OPTICS-001 光圈 / 002 焦距视角 / 003 快门运动模糊 / 004 ISO 画质；
  CINE-001 运镜 / 002 景别；LIGHT-001 光位质感 / 002 时段色温 / 003 夜景人工光；
  COLOR-001 色调配色 / 002 影调；PHYS-001 流体粒子 / 002 材质纹理；
  SCENE-001 天气氛围 / 002 人群空间；STYLE-001 风格谱系 / 002 镜头节奏；
  HUMAN-001 人像全案；NARR-001 情绪→画面配方（配方层/收口层）

## 三、怎么调用（工具）

| 工具 | 用途 |
|---|---|
| `cineread.index` | 全库索引 + 缺篇体检（缺篇必须显式报出，不许静默） |
| `cineread.search` | 按意图检索（返回可直接落字段的中英写法） |
| `cineread.aperture` | **按场景推荐光圈档**（f 值 → 画面语言；依据 OPTICS-001 §三 场景表 / §八 决策树） |
| `cineread.recipe` | 情绪配方（NARR-001）：先取整条配方，再按配方回查各专题细节 |
| `cinewrite.enrich` | 把知识条目注入镜头卡字段，**必须带溯源 trace** |

命令行同口径：`node bundles/ai-video/connectors/cine-kb-bridge/cli.mjs <health|index|search|aperture|recipe|enrich>`

## 四、注入纪律（写进提示词的规矩）

1. **数量**：每镜最多 3 条（外加光圈顾问 1 条），一条只落一个字段（`depth_of_field`/`lighting`/
   `composition`/`camera_movement`/`color_palette`/`props`/`baseline`/`makeup`）。
2. **矛盾闸**：时段/天气/风格矛盾的知识一律不许注入——日景不配"逆光日落剪影"、
   白天巷口的灯笼不算夜景、传统水乡不配"赛博霓虹"。
3. **不重复**：卡片已写景别时不叠加别的景别；卡片已写景深时只补光圈顾问的画面语言。
4. **可溯源**：每次注入都写 `cine-kb trace`（命中主题/行名/注入文本/建议参数/缺篇），
   供监制复核"这句画面语言是从哪条知识来的"。
5. **只增不改**：知识库是产品资产，升级靠新增版本与条目，禁止就地覆盖或删除。

## 五、边界

- 只管"镜头语言与质感"，不改叙事、不改事实、不决定时长与镜头数量（那是剧本/剪辑环节）。
- 库未覆盖的题材要如实说"库里没有对应条目"，不要拿近似条目硬凑。
- 检索不到合适条目时，允许结论是"本镜不需要额外知识注入"——宁可不加，也不要加错。
