# 镜头提示词工艺（25/30 字段）

## 适用场景
- 逐镜提示词融合与三阶段精炼（G6 审核前置）
- 字段质检/修复迭代的规范基准

## 方法
1. 字段工艺：内容镜头 25 字段、片头 30 字段（+5 专属），schema 硬编码，字段标准化以 FieldStandardizer 为唯一真源。
2. 三阶段：融合（上游设计逐字段落位）→ 语义精炼（表达专业化）→ 字段内容精炼（去冗余保信息密度）。
3. 字符口径：理想 2470-3000，硬上限 3000，精炼后 ≥1200；规范值一律从 vendor 真源读取，不手写字面值。
4. 交付前必过 PromptDeliveryGuard：单镜校验 + 作品级 verifyPackage（片头在场/时长带/±15% 容差）。
   时长带以**供应商能力为上限**（媒体目录 `durationSec`；Seedance 2.5 真机实测 4–30s，2026-09-23），
   运行期由 `packages/video-studio/src/duration-rules.ts` 的口径清单统一校验（不允许只改一处）。
5. **镜头内音频纪律**（产品口径 2026-09-23）：生成的镜头只允许 ①台词人声 ②旁白 ③环境音效/动作音效；
   **禁止镜头外加的 BGM/配乐**（配乐统一在后期环节加）；**画面内实况声源不算配乐**——
   街头评弹、三弦/琵琶、店内音响等「画面里真实存在的声源」允许保留（产品所有者 2026-09-23 听检确认）。
   提示词必须带【音频纪律】子句 + `no background music` 负面词，且 `audio` 字段里的「背景音乐/配乐/音乐风格」
   指令会被清洗（否定式「无配乐」与实况音乐词保留）；缺标记 = 交付闸不合格。后期配乐由 BGM 配乐师岗位负责。
6. **环境真实性字段纪律**（真机事故 2026-09-27）：场景字段里出现「简约/现代/高级/通透/干净留白/商务空间」这类**空词**
   时，模型只能落回训练分布里那间**平均样板间**——这正是"AI 感"的定义。字段写法：
   `scene` 带**空间实指**（空间类型/年代/地段/尺度/朝向/时段 ≥3 项）与**材质 + 工艺/使用状态**
   （"胡桃木哑光打蜡 + 中央咖啡杯痕"，而不是"原木桌"）；`lighting` 必须含**场景内实用光源**（窗光/筒灯/台灯/屏幕光，带方向与色温），
   柔光箱/反光板只能作补充；`sceneDescription` 里留**使用痕迹**（指纹/水渍/卷边/划痕/薄灰）。
   片级事实源写在 shotlist 顶层 `sceneBible`（管线自动展开进每镜），字段规格见 `docs/environment-realism.md`。
7. **道具-人体交互纪律**（真机 badcase：手机屏幕朝观众）：被手持或被操作的器物（手机/平板/遥控器/键盘/鼠标/相机/麦克风/耳机）
   必须声明 `propInteraction`（`prop`/`orientation`/`operatedBy`/`contact`/`occlusion`），
   其中**屏幕类必须写"屏幕朝向使用者本人，观众只见机身背面或侧缘"**；静置道具不强制，但写了就要写全。
8. **首镜即是钩子**：0–3 秒的画面与台词由钩子卡决定（`shotlist.hook`，见 `docs/opening-hook.md`），
   首句 ≤18 字、与首镜画面同拍，钩子音落在 0–0.6s；首镜提示词不得把钩子写成"环境交待 + 人物入场"的慢热结构。
9. **设备口径硬约束**（产品所有者 2026-09-27）：场景里出现的电子设备（笔记本电脑、台式机、手机、平板、显示器、耳机、键鼠…）
   **全部使用 2024 年之后的 Apple 设备**，且**机型必须写进镜头卡** `devices[]`（`category` + `model`；裸词"笔记本电脑/平板"不算机型，
   纸本不算设备）。机型只能取自允许清单（`device-policy.ts#DEVICE_ALLOWLIST`，按 Apple 官网在售维护）；画面里不得出现其他品牌标识。
   完整口径、判据与写法见 `docs/device-standard.md`。

## 参数边界
1. 字符硬上限 3000：超限不得提交 G6，也不得靠截断正文过关（截断会丢字段信息）。
2. 精炼后下限 1200：低于该值回上游补设计，**不用形容词填充**。
3. 时长只认 `duration-rules.ts` 的口径清单；任何环节不得手写第二套字面值（时长带/上限/容差）。
4. 音频字段禁写"音乐风格/配乐段落/铺底音乐"；缺【音频纪律】标记 = 交付闸不合格。
5. 提交前必须过 PromptDeliveryGuard（单镜 + 作品级）；未过闸不得进入 G6 审批。

## 失败模式（症状 → 检测器 → 处置）
| 症状 | 检测器 | 处置 |
|---|---|---|
| 正文含 `[占位符]`/`NaN`/`[object Object]` | 交付闸退化哨兵 | 回融合阶段重建，禁止提交 |
| 字段缺号（如缺 P2 某字段） | FieldStandardizer 校验 | 补字段后重跑，不得留空转下游 |
| 字数不足 1200 | PromptDeliveryGuard 长度校验 | 回语义精炼补设计信息，不补形容词 |
| 镜头音频出现"配乐/背景音乐" | 音频纪律清洗 + 【音频纪律】标记检查 | 清洗后重跑，并在报告标注 |
| 台词与剧本蓝图不一致 | 逐字比对 | 以剧本蓝图为唯一事实源改提示词 |
| 商品外观与档案 confirmed 矛盾 | 外观字段比对 | 打回定妆照/提示词，禁止臆造外观 |
| 双重否定导致红线漏检 | 否定归一器 | 归一后复检，必要时人工复核 |
| 作品级时长越带 | verifyPackage（±15% 容差） | 回镜头时长分配整改，不靠后期硬剪 |
| 场景像"平均样板间"（无痕迹/匀光/一级名词材质） | `environment-realism-audit.mts`（渲染前，硬缺陷 fail-closed） | 补 `sceneBible`（空间实指/材质工艺/实用光源/使用痕迹）后重跑，硬缺陷清零再渲 |
| 道具与人的关系没声明（手机屏朝谁？） | `prop-interaction` / `prop-screen-orientation` 规则 | 补 `propInteraction`（朝向/操作者/承重/遮挡），屏幕类写"朝向使用者本人" |
| 开头三秒平平/钩子无兑现 | `openingHookChecks`（短平台缺钩子卡即硬失败） | 补钩子卡（类型/承诺/兑现镜/首镜模板/钩子音）后重跑 |
| 画面出现杂牌/旧世代电子设备 | `device-declaration` / `device-model` / `device-brand` 规则（渲染前，硬缺陷 fail-closed） | 按 `docs/device-standard.md` 补 `devices[]`（机型取自允许清单），文本里的其他品牌一律替换 |

## 输出契约
- 每镜输出：25/30 字段 JSON + 字符数校验快照 + 引用来源（场景卡/剧本/定妆照条目）。
- 台词字段与剧本蓝图逐字一致；商品外观只引用定妆照与档案 confirmed 字段。
- 音频字段只描述台词/旁白/环境与动作音效（含画内实况声源）；不得把"音乐风格/配乐段落/铺底音乐"写进镜头音频（那是后期职责）。
- 无工具回执的关键数字标「未核实」，不得宣称完成（L3.6/E3.7）。

## 边界
- 不做创意与叙事决策（属剧本师/创意策划）；本技能只保证字段工艺与交付闸。
- 不做后期配乐/调色/字幕（后期四工位负责）。
- 不改 vendor 字段规范；规范值一律从真源读取。
