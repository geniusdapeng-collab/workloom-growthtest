# 配乐定调（配什么、什么调性、什么速度）

## 适用场景
- 给成片铺一条与片子调性一致的音乐床（广告/口播/纪录/剧情/促销）
- 需要"配乐风格统一"而不是"每段随手换一首"
- 需要判断"这片子到底该不该配乐"

## 一、定调四问（先答完再动手）

### 一·〇、先读提示词（2026-09-23 新增，优先于四问）

配乐的输入源是**提交渲染的原始提示词**（`render_scripts.md` / `prompt_package` / 一句话 brief）。先跑：

```
bgmread.brief --prompt-text "夜幕下的城市霓虹，主角在雨中奔跑，结尾反转揭晓，快剪高能"
```

它会把提示词翻成配乐简报，四问里的答案往往已经在里面了：

| 简报字段 | 来源 | 用途 |
|---|---|---|
| `recipeId` / `genreTags` | 32 题材关键词表（中英双语，如 美食/探店/food、科技/AI/tech、口播/讲解/talking head、婚礼/wedding、体育/sports）；含反例词（人文/口播文本里的"运动会"不判 sports） | 锁定配方 |
| `energyLevel` + `bpmScale` | 情绪词（燃/快剪 → 高能；治愈/舒缓 → 低能；克制/高级感 → 低能） | 调 BPM 与力度 |
| `instrumentation.avoid` | 禁忌词（不要鼓点 → 去 kick/hat；保留现场声 → 走 keep-all） | 过滤候选、定分层 |
| `climax.position/atSec` | 高潮线索（结尾反转 → 85% 处；黄金三秒 → 8% 处；中段爆发 → 50% 处） | 选段对齐的依据 |
| `musicLevelDeltaDb` | "音乐要轻/要突出" | 微调配乐电平（±3dB） |
| `noMusic` | "不要背景音乐" | 直接判无需配乐（do-no-harm） |

命中不了题材时简报会如实给低置信度，此时**不硬编题材**，按片子自身能量与结构选曲。

1. **题材**：32 类——16 既有（产品广告/口播访谈/美食/科技/旅拍/夜景/美妆/亲子/汽车/房产/促销/纪录/高端品牌/剧情/悬疑/喜剧）+ T-15 新增（婚礼/体育/电竞/时尚/母婴/家居/新能源/财经/城市黄昏/节庆/科普/生活 vlog/情感故事/品牌宣言/宠物/健身）——决定风格族。题材未命中即 −30（T-05），不靠能量/BPM 翻盘。
2. **场景与主体**：棚拍白底、室内半身、菜品特写、屏幕演示、街拍空镜……决定配器厚薄（主体越细，配器越薄）。
3. **情绪目标**：干净可信 / 可信亲和 / 诱人温暖 / 冷静精密 / 开阔通透 / 戏剧现代 / 通透可信 / 明亮有温度 / 强劲精密 / 明亮通透 / 热烈紧迫 / 真实克制 / 克制质感 / 情绪推进 / 不安张力 / 轻快明亮——决定调式（大调/小调/多利亚/弗里吉亚）与力度。
4. **发哪个平台**：抖音/小红书/视频号/B站/YouTube——决定高频是否要更亮、低频是否要更收（手机外放）。

四问答不出来的，先按 `bgmread.recipes` 的速查表取一条最接近的配方，再说明"为什么是它、被否掉了谁"。

## 二、配方库用法

```
bgmread.recipes --list                     # 全部配方（16 条）
bgmread.recipes --genre 美食 --mood 诱人温暖   # 定向检索
bgmread.recipes --id food                  # 取单条（含禁忌与备注）
```

配方字段与含义：

| 字段 | 含义 | 用法 |
|---|---|---|
| `key` / `mode` | 调性 / 调式 | 决定"明/暗"：major 明亮、aeolian 内敛、dorian 冷静、phrygian 不安 |
| `bpm` | 配方基准速度 | 只作基准；真实速度还要看剪辑节奏（见第三节） |
| `chords` | 和弦级数进行 | 4 个级数循环；一/四级明亮、六级/小四级内敛 |
| `instrumentation` | 配器 | pad（地基）/ bass（低频走向）/ pluck（推进）/ kick·hat（节拍）/ bell（点缀） |
| `musicLevelDb` | BGM 在成片里的平均电平 | 口播 -26、广告 -22、促销 -19（数值越大越"站前台"） |
| `duckingDb` | 人声出现时的让位深度 | 口播/纪录 13–14、广告/促销 10–12 |
| `avoid` | 禁忌 | 违反即回退重做（例：口播片禁打击乐） |

## 三、速度决策：配方 BPM 还是剪辑点反推

卡点对不齐，九成是速度错了。两条规则：

1. **剪辑节奏优先**：相邻剪辑点间距 ÷ 一拍 = 整拍数，反推 BPM（`bpm_strategy=cut-driven`）；
   与配方 BPM 相对差 ≤25% 时采用反推值，否则沿用配方 BPM 并说明冲突。
2. **同一项目只用一个速度**：不要"开场 128、正片 96"，那听着像两条片子拼的。

对齐验收线：剪辑点到最近拍点的误差 **≤80ms 记落拍**；达标率 ≥60% 记 partial、100% 记 aligned（工具会把这几个数写进回执）。

## 三·二、选段：从曲子里挑"最合适的那一段"（含高潮段）

外部曲目往往 2–3 分钟，片子只有 15–60 秒——"裁哪一段"和"配什么曲子"同等重要。

```
bgmread.structure --in track.wav          # 看结构：intro/verse/build/drop/breakdown/outro + BPM + 高潮候选
bgmwrite.mix ... --section auto           # 自动选段（默认口径）
bgmwrite.mix ... --section climax         # 明确要高潮段
bgmwrite.mix ... --section calm           # 明确要铺垫段
bgmwrite.mix ... --section-start 62 --section-end 78   # 手工指定（秒）
```

**`auto` 的决策链（都会写进回执）**：

1. 先定片子的"高潮时刻"，依据按优先级取：**剪辑密度成簇（±2s 内 ≥2 个剪辑点）→ 非对白段能量峰（比非对白中位数高 ≥3dB）→ 音频总能量峰（且对白占比 <35%）**；
2. 找得到 → 取曲子的高潮段（drop），并把该段的能量峰值**对齐到片子的高潮时刻**；
3. 找不到（口播/访谈这类没有画面高潮的片子）→ **不硬对**，取曲子最有代表性的一段，从片头铺；
4. 选出来的段比片子还长（或曲子本身平坦）→ 在段内**滑窗**取 片长×40% 的窗口（以能量最高处为中心）；曲子本身平坦则从曲头取。

三条纪律：

- **不许把音乐高潮对到台词最响处**——口播片的高潮是画面/情绪，不是音量；所以片子高潮的判据里排除了"对白峰值"。
- **不许在乐句中间硬切**：片段边界优先吸到结构边界，其次吸到节拍网格（BPM 置信度 low 时不吸，避免乱吸）。
- **选不出来要说选不出来**：回执里 `filmPeakAlign.skipped` 会写明"片子未识别到明确高潮点"，而不是编一个高点。

结构识别的诚实边界：这是**规则式分段**（能量分位数 + 段内走向 + 起音密度），不是深度学习结构识别，
也不是乐谱级的主歌/副歌标注；它能稳定回答"哪段最响、最密、最适合当高潮"。

## 四、结构（片子多长就写多长）

| 段落 | 占比 | 配器 | 作用 |
|---|---|---|---|
| 前奏 intro | ~15% | 只留 pad + bass | 不抢开场第一句话 |
| 主体 body | ~73% | 加 pluck，必要时 kick/hat | 承担推进感 |
| 尾奏 outro | ~12% | 回落到 pad | 自然收束，不做硬切 |

**不用"裁歌"**：外部曲目短于片长时循环铺满（工位用 `-stream_loop`），不靠剪断一句旋律来对齐时长。

## 五、禁忌（违反即回退）

- 情绪与画面相反（婚礼片配悬疑底、悼念场景配促销节奏）；
- 一个项目混用多套配乐语言（调性/配器不一致）；
- 打击乐压在口播句读上（口播片默认不进 kick/hat）；
- 用配乐掩盖上游问题（对白已削波、底噪过大、单声道素材）——如实上报，不用音乐盖过去；
- 在"笑点/揭示/报价"这些关键信息前后加花抢注意力（该留白的地方留白）。

## 六、允许的结论：不配

以下情形应主动报"无需配乐"而不产出文件（`bgmwrite.best` 会给这个结论）：

- 素材疑似**已有连续配乐**（人声频段活动占比 ≥90% 且谱平坦度极低）；
- **没有安全窗口**：人声几乎铺满全片、环境底噪过高，任何电平的配乐都会压字或不可闻；
- 现场声本身就是内容（纪实、ASMR、烹饪原声），加了反而稀释。

报"不配"时要给出依据（活动占比、底噪、预估余量），不要只写一句"建议不配"。

## 输出契约

选型说明必须能回答四个问题：**什么题材、什么场景/主体、什么情绪目标、发哪个平台**，
并附：配方 id、调性/调式、BPM 及依据（配方/剪辑点反推）、配器清单、配乐电平、让位深度。

## 失败模式（症状 → 检测器 → 处置）

| 症状 | 检测器 | 处置 | 案例 |
|---|---|---|---|
| 卡点对不齐、越听越"漂" | 剪辑点反推 BPM 与采用值相对差（>25% 必须说明） | 改走 `bpm_strategy=cut-driven`，或写清沿用配方 BPM 的冲突理由 | — |
| 情绪与画面相反（婚礼片配悬疑底、悼念场景配促销节奏） | 配方情绪目标 vs 题材表比对 | 回退换配方；宁可"不配"也不要错配 | FC-BGM-001 |
| **题材未命中却仍被选中**（运动/电音曲配人文口播） | 回执 `match.reasons` 含"题材未命中"且该曲入选；T-05 起未命中记 **−30**、`veto` 策略直接出局 | 换题材贴合曲目；客户要求"宁可不配也不配错"时用 `genre_mismatch_policy=veto`（候选全出局→按在线/本地/自算三级兜底降级，不强行出片） | FC-BGM-001 |
| 打击乐压在口播句读上 | 口播/纪录类配方是否含 kick/hat | 去打击乐重跑；口播片默认不进打击乐 | — |
| 音乐盖住人声（听字不清） | 人声-音乐余量 ≥6dB + `duckingDb` 是否生效 | 加深让位或降 `musicLevelDb` 后重跑 | — |
| 音乐高潮对在台词最响处 | `filmPeakAlign` 命中对白峰值 | 重新选段（高潮判据排除对白峰值），或如实报"无明确高潮点" | — |
| 片段在乐句中间硬切 | 切点是否吸到结构边界/节拍网格 | 吸附到结构或节拍边界重切；BPM 置信度 low 时不吸 | — |
| 该留白的地方加花抢注意力（笑点/揭示/报价前后） | 关键信息点与配器密度对照 | 关键点前后留白；必要时降配器密度 | — |
| 现场声本身就是内容却仍加配乐 | 人声频段活动占比 ≥90% 且谱平坦度极低 / 无安全窗口 | 输出"无需配乐"（`bgmwrite.best` 结论），不产出文件 | — |
