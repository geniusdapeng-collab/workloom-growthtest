# 调色执行纪律

## 默认流程

已成功生成镜头默认进入正式后期。按请求 profile/LUT/强度/显式校正执行一次真实编码；默认无源画质或成品品质准入、候选评分、可见性阈值、缺陷拒收、模型/人工评审或自动重渲。

1. 读普通元数据、源 SHA，验证输出路径与 LUT 存在性。
2. 按实际色彩编码做所需转换；声明 LUT 与显式校正进入真实滤镜。
3. 单次编码，保留音频 copy，写 bt709 色彩标签。
4. 回读实际产物和标签、核对源 SHA 未变、写请求与处理回执。

`auto` 不再隐藏触发品质诊断；`best` 兼容入口执行一套声明配方，`candidates=[]`、`score=null`。参数及实际处理错误不能吞掉或用“无需调色”冒充完成。

## 正向设计建议

| 内容 | profile | 建议强度 |
|---|---|---|
| 叙事/情感 | warm-film | 0.7–0.85 |
| 科普/产品 | clean-bright/natural | 0.6–0.8 |
| 科技/暗场 | cool-technical | 0.6–0.75 |
| 悬疑/严肃 | moody-dark | 0.5–0.7 |
| 社媒/投流 | high-contrast-social | 0.7–0.85 |
| 复古 | vintage-fade | 0.6–0.75 |

建议用于未明确参数的配方选型，不评判成功源镜头，不因黑帧、人物肤色、过曝或低分辨率拒收。用户明确请求诊断时 `colorread.analyze`/`colorread.scope` 可量样本，报告未核实或缺陷，不自动改源或生成新镜头。

## 显式镜间匹配

`colorwrite.match` 的输入统计只用于计算用户要求的 reference→target 校正参数，标注 `requested-color-match-transform`。每目标执行一次，不做成品残差/直方图票决或自动重试；`after/residual=null`、品质未评审。参考与目标源 SHA 都保留。

## 回执与边界

原片只读（G-COL2），配额（G-COL4）保留；品牌 look 与关闭品质诊断不挂起默认后期（G-COL1/G-COL3）。回执含实际滤镜、LUT/强度、源/产物 SHA、普通元数据、色彩转换与输出标签；品质字段为 null/空值/`not-reviewed`，不得声称已测。

不存在 LUT、路径越界、磁盘、真实编码、源漂移或请求输出不符均明确失败，不自动降级、换滤镜、重渲或转模型。历史事故与目标区间保存在 `library/color-kb/`，供显式反馈后查阅。


## 实体级局部调色（镜头级之下第二层）

镜头级 LUT 不知道"同一个镜头里谁是谁"：同镜人物+食物时，食物需要暖黄，人像却被一起染黄（客户 2026-10-11 实测）。
实体级调色把两类实体分开，在本模块的纯函数里只做计划与滤镜图，不做审美判断：

- 人像 → 美白：提亮 + 略收饱和 + 去黄（`colorbalance rs=-0.02 / bs=+0.03`），只作用在**人物掩膜**内；
- 食物 → 暖黄：加暖 + 提饱和 + 提对比（`rs=+0.05 / bs=-0.055`），只作用在**食物掩膜**内；
- 同镜两类实体分别作用、互不串色；没有实例/人脸证据的"假人物掩膜"（俯拍食物镜的通用分割会把盘子当人）不美白。

实现：`connectors/color-bridge/entity-grade.mjs`（`planEntityGrade` / `buildEntityFilterComplex` / `summarizeEntityPlans`，
附单测 `entity-grade.test.mjs`）；掩膜生成（macOS Vision：人物实例分割 + 前景实例分类）与逐片段执行在视频剪辑管线负责。
