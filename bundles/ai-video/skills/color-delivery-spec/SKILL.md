# 调色交付规范

## 交付事实

| 项 | 要求 |
|---|---|
| 文件 | 新成片，真实存在，产物 SHA 与磁盘一致 |
| 配方 | profile/LUT 路径、强度、显式校正、实际滤镜链 |
| 色彩 | 输入转换依据与输出 bt709 标签普通元数据回读 |
| 音轨 | 原声 copy；无音轨仍可处理，不触发配音或重渲 |
| 血缘 | 原始源 SHA，处理前后原片未改变，版本只增不覆盖 |
| 结果 | 实际处理完成/错误码，品质未评审 |

默认没有 before/after 指标、scope 图、像素差、清晰度、肤色、模糊或裁切检查。未测项为 null/空数组/`not-reviewed`，不假报通过；低分辨率、黑帧、过曝或上游旧品质失败不阻止已成功镜头。

## 版本与围栏

G-COL2 原片保护与 G-COL4 配额保持；G-COL1/G-COL3 不把品牌观感或 `verify=false` 转成默认后期审批。实际 LUT、路径、源字节、磁盘、ffmpeg 和请求导出规格错误仍失败，保留错误回执。

每个用户要求的变体按声明配方执行，记录复用与重算。`best` 执行一套配方，不做候选票决；显式 `match` 输入统计用于计算变换，不做成品残差品质复核或重试。

## 用户反馈与诊断

用户明确反馈偏色、强度或参考镜时调整相应层；没有新增镜头授权不重生成。`colorread.analyze`/`scope` 是显式诊断入口，不能作为普通交付必需件，不能把历史目标区间当成功素材准入。

HDR/ACES/新编码请求按实际可执行参数处理；不支持时明确报错，不伪造处理完成。设计目标与历史案例可参考 `library/color-kb/`，不会覆盖默认采用和真实回执纪律。
