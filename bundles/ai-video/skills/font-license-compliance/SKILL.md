# 字体许可合规

## 一、白名单与判定

商用交付只允许这三类许可（`font_db.json#licensePolicy.commercialWhitelist`）：

| 许可 id | 名称 | 可商用 | 义务 |
|---|---|---|---|
| `ofl-1.1` | SIL OFL 1.1 | ✅ | 禁单独转售字体文件；修改后再发布必须改名；保留许可与著作权声明 |
| `apache-2.0` | Apache-2.0 | ✅ | 保留版权声明与许可文本（NOTICE） |
| `vendor-free-commercial` | 厂商免费商用授权（阿里妈妈/普惠体等） | ✅ | 登记时必须附**许可证明链接**；闭源分发前复核条款 |

**未登记许可 = 不合规**（fail-closed）。判定不靠印象：`subtitleread.fonts` 只返回白名单内的候选，
围栏 `G-SUB5` 在交付动作上再拦一道。

## 二、OFL-1.1 的四条实操结论

1. **成片、封面、贴纸里用字体渲染文字 → 不受限制**（输出作品不是字体再分发）；
2. **不得单独转售字体文件**：字体文件只能随工位/产品分发，不能当字体商品卖；
3. **子集化 = 修改**：subset 后的字体必须改名并标注来源，因此本能力**默认不做子集化**，
   直接使用原始字体文件——省掉改名与再发布义务，也让 sha256 核验保持意义；
4. **再分发要带声明**：`kit/install-fonts.sh` 会把 `LICENSES.md` 一并落盘到工位字体目录。

## 三、字体文件不进版本库

- 仓库只存**档案（打标 + 许可 + sha256）**与**引脚（上游地址 + 核验结果）**；
- 工位按 `kit/fonts-pin.json` 逐文件 sha256 校验后安装（`--from-dir` 离线导入 / `--download` 直链下载）；
- 29 款字体约 128MB：进仓库会让所有克隆、CI 与桌面载荷背这份体积，且每次升级都要推动二进制。

## 四、客户自备商用字体（方正/汉仪/华康/迷你简/造字工房……）

1. 由**客户**提供字体文件与授权证明（授权书/采购单/许可页链接），工位本地导入；
2. 在档案里登记：字体名 / 家族名 / 文件 / sha256 / 许可（`vendor-free-commercial` 或客户授权类型）/ 证明链接；
3. 未登记的字体**不进入选型候选**，也不接受"先用着，回头补授权"；
4. 客户素材与字体文件不上行；工作区只保留档案与许可证据。

## 五、留痕与复核

交付报告必须能回答四个问题（`subtitle_report`）：

1. 这条片子用了哪些字体（名称 + id + sha256）？
2. 每款的许可是什么、来自哪里、证明在哪？
3. 有没有修改过字体文件（答案必须是否——本能力不做子集化/改名）？
4. 品牌视觉锤（账号锁定字体）这次有没有变更（有则走 G-SUB1 人审）？

回答不上来 = 这条片子不能作为商用交付进入发布队列。
