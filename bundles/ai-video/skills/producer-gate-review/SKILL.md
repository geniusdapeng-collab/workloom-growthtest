# 监制门评审（Producer Gate Review）

## 适用场景
- 预生产内部准备门（G1 情报 / G2 主题 / G3 对齐 / G4 PRD / G5 定妆照 / G6 提示词 / G7 预生产收口）
- **G5 定妆照（T-2026-1031-9003）**：必须通过实际出图、四角度、文件字节和项目作用域核验；通过后由系统自动审批。
  机器像不像/监制结论仍只留证，不新增审美否决，也不触发自动重做。
- 新付费渲染前的剧本、连续性、提示词和关键帧准备；成功渲染后的镜头与后期使用事实性处理回执。

## 成功渲染后的默认采用

镜头成功并绑定真实任务、当前输入与原片字节后，直接正式后期。`shot/compose/color/subtitle/danmaku/bgm/sfx/cover/mux/master/deliver` 不调用品质模型或人工验收，不做身份、服装、动作、台词、口型、黑帧、原片精确规格或 canary 二次否决，也不因此 ASR、TTS 或重渲。模型预留成本为零，回执 `score=null`、`qualityReviewPerformed=false`；`approved=true` 仅表示实际处理资料存在且可用于当前操作，不能说“品质认证”。实际文件缺失/损坏、输入字节变化、供应商真实失败与导出错误仍停止。

## 方法
1. **先硬闸后模型**：空内容、`undefined`/`[object Object]` 占位、内容过短、定妆照 `completedPortraits=0`、
   预生产请求参数或授权不符 —— 命中即停在付费前，不调用模型。成功视频的实际时长/画幅/帧率/有无音轨交给正式后期归一化，不套用此品质门。
2. **再按环节要点评审**：用 `packages/video-studio/src/producer-gate.ts#PRODUCER_RUBRICS` 的标准；
   图像类评审必须把**待评审产物**与**基准图**一起给模型看（产物优先占配额，基准图最多 2 张）。
   关键帧准备仍使用下列制作要点；它们不再是成功 `shot/master` 的二次验收项：
   - **环境真实性**：空间是可指认的真实场所（不是平均样板间）——材质带工艺与使用状态、灯光含场景内实用光源、
     画面留有使用痕迹；判红"无痕样板间 / 一眼影棚 / 材质只写一级名词 / 空间空旷到与人物活动不符"（与
     `scene-bible.ts#environmentDefects` 同源，见 `docs/environment-realism.md`）；
   - **道具-人体交互逻辑**：被手持/被操作的器物必须有成立的物理关系——**屏幕朝向它的使用者**
     （观众只见机身背面或侧缘，不出现屏幕内容正对镜头）、有承重接触、手指正常；
     只在待提交的卡片与新付费前关键帧中核对操作/承重关系；成功 `shot/master` 不再跨帧复审或打回。
     出处：真机 badcase「手机屏幕朝观众」（`docs/badcases/BADCASE-2026-0927-phone-screen-toward-audience.md`）。
   - **设备口径**：待生成镜头的设备按冻结故事年代、显式品牌合同与 `devices[]` 核对；
     只在提交前卡片/关键帧中处理不符，成功 `shot/master` 不做跨帧、跨镜设备外观品质复审。
     允许清单见 `device-policy.ts#DEVICE_ALLOWLIST`、口径见 `docs/device-standard.md`。
3. **付费前准备门裁决三类**：放行（approved）/ 打回停线并如实上报（默认**不自动重跑**，是否重做由人决定）/ 需介入（模型不可用或超预算）。
4. **打回必须可执行**：写清"改什么、改成什么、为什么"——例如“待提交的关键帧缺少已授权参考，请补齐参考与操作关系后重新准备”；不得要求已有成功原片品质重渲。
5. **留痕**：每次裁决写 `gate`、`score`、`via`（deterministic/llm/fallback）、`model`、`issues`、`suggestions`，
   落五元事件账本；`degraded=true` 表示"模型不可用但硬闸全过"，必须显式可见。

## 输出契约
- 每次评审：`{approved, score, hardFailures, issues, suggestions, rerun, via, model, ms, reason}`
- 全链路运行：`<work-dir>/logs/stages.jsonl`（逐环节）+ `stage-summary.json`（汇总，含未调用/降级/复用计数）

## 边界
- 不替代花钱与对外门原有的质量、预算、发布包和敏感内容审查；仅取消人类审批等待。
- G5 系统自动审批必须绑定 `workloom.video-auto-approval/v1` 与实际图像证据；"像不像"仍只留证。
- 预生产模型不可用时保留真实失败；成功素材的正式后期无需品质模型，不把 `model=null/score=null` 标为降级或未完成。
- 不做"AI 自评自过"：定妆照与关键帧这类视觉产物必须带基准图比对；没有基准图时只能判画质与纪律，结论里要写明。

## 失败诊断（症状 → 检测器 → 处置）

| 症状 | 检测器 | 处置 |
|---|---|---|
| 监制只收到路径清单 → 判"无正文可核验" | 评审输入检查：正文预算（单文件 ≤1600 字、总量 ≤12000 字） | 按预算补送正文后重评；**不得凭路径清单出"通过"结论** |
| 模型不可用却给出"通过" | `via` 标记 + `degraded` 检查 | fail-closed 默认拒绝；仅显式 `HR_PRODUCER_FALLBACK_APPROVE=1` 时可放行且必须标 `degraded` |
| 硬闸被跳过、直接进模型评审 | 付费前准备检查（空内容/占位符/过短/`completedPortraits=0`/请求参数与授权） | 判流程缺陷：回退重评并登记；硬闸结论必须可复算 |
| 视觉产物无基准图却下"像/不像"结论 | 基准图在场检查（产物优先占配额，基准图 ≤2 张） | 只能判画质与纪律并写明；需要一致性结论时先补基准图 |
| 打回无定位，创作者反复试错 | 打回可执行性检查 | 退回评审，补齐"改什么 / 改成什么 / 为什么" |
| 裁决没有落账 | `stages.jsonl` 门事件（gate/score/via/model/issues/suggestions） | 视为未评审：重跑该门并补落账 |
| 超预算仍在评审 | 预算检查 | 转"需介入"，不烧额度继续评审 |
| 画面"符合镜头卡"但一眼不像实拍 | `env-realism` 机检（渲染前）+ 环境真实性 rubric | 判**卡片空词**（不是模型问题）：补待生成卡片的 `sceneBible` 后再提交，并登记环境 badcase；已有成功素材默认采用 |
| 屏幕内容正对镜头 / 道具漂浮穿模 | 付费前卡片/关键帧的道具交互规则 | 补待提交卡片的 `propInteraction`（朝向/操作者/承重/遮挡）；成功镜头不复审或重渲 |
| 出现杂牌设备 / 旧世代机型 / 非 Apple 标识 | 付费前卡片/关键帧的 `device-*` 机检 | 按冻结年代与显式品牌合同补待提交卡片的 `devices[]`；成功镜头与母版不再品质复审 |
