# 评论三级分流 SOP

## 适用场景
- 账号经营管线评论采集与回复外发（G10 分流门）
- 负面/危机评论的告警与人工接管

## 方法
1. 采集与分类：每 30 分钟采集评论，意图分类为 praise/thanks/consult/after_sale/negative/crisis/sensitive。
2. 三级分流：
   - 夸赞/感谢 → auto 自动回（仅限模板库内措辞，不即兴发挥）；
   - 咨询/售后 → review 审批后回，复杂售后转人工；
   - 负面/危机 → review + 告警；含投诉/维权/退款/骗子/举报关键词必走此档；
   - 政治敏感等 → block，只写「需介入」事件（L4.2 不确定不执行）。
3. 候选回复须附依据：引用评论原文 + 相关档案/商品条目。
4. 外发回执落账；发送失败即转人工，不重复发送。

## 输出契约
- 每条评论输出：意图标签 + 分流级别 + 候选回复（含依据）+ 外发回执。
- auto 档外发内容必须可回溯到模板编号。
- 无工具回执的关键数字标「未核实」，不得宣称完成（L3.6/E3.7）。

## 前置校验（外发前四查）

1. **分流级别**：praise/thanks → auto；consult/after_sale → review；negative/crisis → review + 告警；sensitive → block（只写「需介入」事件）。
2. **措辞来源**：auto 档措辞必须在模板库内且能回溯模板编号；超出模板库一律降为 review。
3. **回复依据**：候选回复必须能回溯到「评论原文 + 档案/商品条目」，不得承诺档案里没有的能力、价格或时效。
4. **关键词必审**：命中 投诉/维权/退款/骗子/举报 任一关键词，无条件升到 review + 告警档。

## 失败诊断（症状 → 检测器 → 处置）

| 症状 | 检测器 | 处置 |
|---|---|---|
| 投诉/维权类被误判成普通咨询 | 关键词必审表 + 二次判定 | 立即升级 review + 告警；误判记入错题本 |
| 自动回复超出模板库（即兴发挥） | 模板编号校验 | 拦截外发，改走 review 审批 |
| 回复与档案事实不符（夸大能力/价格） | 回复依据与档案 confirmed 字段比对 | 撤回或以新事件更正，并升级人工处理 |
| 外发失败（平台限流/网络/登录失效） | 外发回执探测 | 转人工接管；**不重复发送**（防重复评论） |
| 同一评论被回复多次 | 评论 id 幂等键 | 去重并留痕，保留首次有效回复 |
| block 档被尝试外发 | 围栏 G10 + 分流级别校验 | 拒绝外发，只落「需介入」事件 |

## 证据口径

1. 每条评论留痕：意图标签 + 分流级别 + 候选回复（含依据）+ 外发回执（成功或失败原因）。
2. auto 档外发内容必须可回溯模板编号；block 档只写事件、不外发。
3. 无回执不得宣称"已回复"；失败与去重都要落在事件账本上。
