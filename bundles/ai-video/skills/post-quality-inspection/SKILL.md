# 后期质检与交付放行

用户拿到的每一份文件都应能播放、规格和请求一致，并能追溯实际加工。调用者可能是 Codex、其它 AI 工作台、CLI 或 HTTP；岗位提示词帮助完整执行，最终放行由本仓确定性程序控制。

## 三个使用场景

| 场景 | 行为 | 不执行会发生什么 |
|---|---|---|
| 实拍原片制作多个版本 | 按母版和每个变体回读七个环节、原生画布和当前 SHA | 缺转场、字幕或音乐的版本可能被当作完整交付 |
| 已生成镜头制作快剪 | 对照实际源区间、1x声音、保护台词、实际切点与声明音效 | 名义短镜头可能仍整段使用，或加速说话伪装节奏 |
| 只改字幕/封面后重新打包 | 根据实际工程版本检查新产物，并验证中文名文件字节 | 旧文件/旧绿色报告可能混进新包 |

## 执行步骤

1. 读取目标仓指南、当前交付清单和工程，识别本次请求的变体、字幕模式、弹幕和目标画布。成功源只按任务、来源、授权和当前字节复用，保留历史意见。
2. 对实际包调用 `postread.quality`（参数 `delivery_dir`）或 `node bundles/ai-video/connectors/post-bridge/cli.mjs quality --delivery-dir <交付目录>`。CLI/HTTP重新回读，不把上一次成功当本次证据。
3. 核对报告 `schemaVersion=workloom.post-quality/v1`、`passed=true`、当前资产/加工文件哈希与每个环节的状态。七环节为 cover / bgm / subtitles / danmaku / transitions / color / resolution；不适用必须有具体请求理由。
4. 技术失败进入本地修复。按工程版本与 SHA 做影响分析，仅重算受影响层；来源被换或加工失败必须报错。失败不授权新付费生成。
5. 对修复、封面片头、弹幕和中文整理后的实际文件重新检查；release报告绑定最终字节，发布后改文件会使下次核验失败。
6. 单列艺术审片。真正看过和听过才能写观察；用观感说明肤色、食物色、轮廓光、景别变化、快慢段、呼吸点、声音层次与文字可读性。技术通过不证明这些全部优秀。

## 客观放行条件

| 项目 | 可复算依据 | 失败处置 |
|---|---|---|
| 母版与每个请求变体 | 非空文件、完整 SHA、ffprobe、全片 FFmpeg 解码 | 缺件/坏文件停止出口 |
| 原生分辨率 | 实测显示宽高，旋转已解释；每轴/画幅与目标一致 | 降采样须明确批准；换画幅须明确理由 |
| 转场 | 每刀的实际类型、时刻和窗口；硬切也是明确剪辑选择 | 不能用计划或任意JSON冒充已渲染 |
| 调色/实体/清晰度 | 真实色彩转换参数与输出SHA；实体 applied/skipped/原因 | 未支持转换明确失败；无可靠实体掩模安全跳过并留证 |
| BGM与声音 | 曲目来源SHA、实际混音策略；全编码成片响度/真峰值 | 默认report留实测，声明block合同按其阈值失败 |
| 字幕/弹幕 | 完整条目时间/文字、实际字体解析、软字幕流或烧字加工链 | 空、越片尾、错字体或缺请求形态失败 |
| 中文整理 | 文件绑定通过验收的当前源SHA，目标字节独立核对 | 旧硬链接、同名他人文件与改字节不得放行 |

加工凭证由实际引擎在操作前记录输入SHA，执行成功后绑定请求与输出SHA，并重新核对源片未变。主机本地凭证不能防止拥有任意文件系统写权限的恶意程序伪造证据，不作为加密远端证明。

## 优先级与边界

P0：完整产物、全片解码、来源/加工链、原生画布与文本时间轴。P1：逐帧实体掩模、真实节奏与声明音效、响度建议、返修与复制后复核。P2：有原始参考/分轨/明确标准时做系统化艺术审片与项目校准。

不自动重生成、不抹原字幕、不凭锐化恢复原始细节、不把BPM标签当实测节拍、不把技术报告当角色/经营效果证明，不自动对外发布。
