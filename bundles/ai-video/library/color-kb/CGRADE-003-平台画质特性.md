# 平台画质特性与调色预补偿（Platform Compression & Pre-Compensation）领域知识库

> **用途**：AI 视频生成与调色交付系统的调色知识库。供调色师 / 数字员工在"调色定调"与"平台变体派生"环节检索调用。
> **主题编号**：CGRADE-003　**版本**：v1.0　**更新日期**：2026-09-27
> **使用方式**：涉及"发到哪个平台、二次压缩、画质预补偿、变体派生"等议题时检索本主题。**重要纪律：本仓库的调色只做一次、落在母版；平台差异通过交付变体与"平台微调"承接，绝不按平台各调一遍**（与 `skills/color-delivery-spec` 口径一致）。文中标注"经验口径"的数值为行业经验值，非本仓库实测数据，禁止当作精确平台参数写入交付物。

---

## 一、核心概念

### 1.1 二次压缩是什么

平台不是被动播放器——每一支上传的视频都会被平台**重新编码（二压）**：转码到平台自己的码率档位、过一遍预处理滤镜（去噪、锐化、超分）、再分发到千差万别的终端屏幕。调色师面对的不是"我的成片长什么样"，而是**"我的成片被平台嚼过一遍之后长什么样"**。

> **调色交付的终点不是导出文件的那一刻，是观众手机屏幕上那一帧。** 二压是调色与观众之间必经的一道损耗，预补偿就是把这道损耗提前算进调色里。

### 1.2 二压破坏的三类高发区（经验口径）

| 破坏区 | 机理 | 典型后果 |
|---|---|---|
| **高饱和区域** | 平台编码的色度子采样（4:2:0）+ 码率分配偏向亮度，饱和度越高的色块越容易糊成色团 | 红/品红溢出、霓虹色"脏"掉、美食红变黄 |
| **细纹理 / 高频细节** | 降噪预处理 + 量化把细碎纹理当作噪声抹掉 | 胶片颗粒消失、织物/毛发变塑料、草地糊成一片绿 |
| **暗部** | 低码率下暗部被严重量化，加上平台为省电屏做的暗部提亮 | 暗部出色带（banding）、死黑、夜景噪点被放大 |

三条共同的反直觉结论：**越艳越吃亏、越细越吃亏、越暗越吃亏**。小屏信息流环境下"在监视器上刚好"的画面，上了平台往往"不够"——这就是预补偿存在的理由。

### 1.3 预补偿 vs 平台微调 vs 重新调色（本仓库的三分法，必须分清）

- **预补偿**：调母版时就预留余量（对比/饱和/锐化的预留量），属**调色决策的一部分**，一次完成。
- **平台微调**：交付侧对变体做的亮度/对比小幅调整（见 `color-look-design` 平台表），记录为"平台微调"，**不动 look、不动 profile/LUT**。
- **重新调色**：按平台各跑一遍调色——**本仓库明令禁止**（`color-delivery-spec` 第二章第 3 条：会造成同片不同色，且成本翻倍）。

> 三者边界是考试点：预补偿在"调一侧"做，平台微调在"交付一侧"做，重新调色在哪一侧都不许做。

## 二、分类速查：四大平台二压特性与风格偏好

> 说明：下表"二压倾向"列为**行业经验口径**（码率与预处理策略平台不公开且随时调整），用于指导预补偿方向，**不得写成精确平台参数**；"风格偏好"列与 `skills/color-look-design` 第四章平台适配表对齐。

| 平台 | 二压倾向（经验口径） | 破坏高发区 | 风格偏好（与 color-look-design 对齐） | 预补偿方向（经验口径） |
|---|---|---|---|---|
| **抖音** | 流量巨大、码率档位激进；预处理有可见锐化倾向；小屏强竞争环境 | 高饱和色团、暗部噪点、细纹理 | 高对比高饱和、暗部略提（户外看手机）；对比 +5~10%、饱和 +5% | 对比与饱和适度上探；暗部不要压到临界；颗粒类纹理预期会丢 |
| **小红书** | 封面流审美导向；对"脏"和"黄"的容忍度最低 | 暖黄偏色被放大成"脏黄"、肤色偏橘 | 干净、清新偏亮、低对比、肤色自然，忌脏黄 | 宁可收着调：白平衡务必中性，饱和宁低勿高，明度偏高 |
| **视频号** | 中老年受众多、终端亮度差异大；对字幕可读性最敏感 | 暗部死黑、字幕对比不足 | 亮度略高、对比略低，字幕对比度必须够 | 整体明度上浮、对比收敛；黑位不压死；字幕描边/底色留足对比 |
| **B站** | 屏幕大、观看时长长、可看细节；对风格化最包容 | 过度锐化显廉价、色带在大屏更明显 | 包容风格化，保留层次，避免过度风格化 | 预补偿最轻：保留高光/暗部层次，锐化少留（平台与终端都会再加） |

### 速查记忆法

- **抖音要"跳"、小红书要"净"、视频号要"清"、B站要"层"**——四个字概括四平台。
- 码率上限、转码档位等平台内部参数**本仓库不维护、不承诺**；交付物里引用平台参数时一律标注"经验口径，以实际上传结果为准"。

## 三、分场景实战

### 3.1 信息流短视频（抖音/小红书为主）

1. 母版按题材配方正常调（配方 id 见第九章），**预补偿只做余量不做风格**：抖音向的片子在配方 targets 区间内把对比/饱和往中上靠，但不许越界（如 `food-appetite` 的 SATAVG 上限 85 不许突破）。
2. 暗部：夜景题材按 `night-city` 纪律"暗部裁切 <3% 且留痕"——这恰好也是抗二压的暗部安全线，二压会把压死的暗部放大成色带。
3. 高饱和促销题材（`festival-promo`，SATAVG 60–90）：红/金区块是二压色团重灾区，交付前在平台真机上抽查一版；高饱和只给画面不给文字的纪律在平台上是**可读性红线**而非审美建议。

### 3.2 人物出镜（访谈/口播/美妆）

- 肤色是四平台共同的复检点（skinHue 20–40°、SATAVG ≤60，见 `talking-head` / `beauty-makeup`）。二压的色度子采样会让偏橘的肤色在小屏上"发荧光"，**肤色预补偿的方向是"宁淡勿浓"**。
- 小红书投放的美妆片：白平衡先修到中性（`beauty-makeup` notes），任何"美白式提亮"在平台二压后都会变成肤质失真。

### 3.3 夜景/都市

- `night-city` 允许 YAVG 低至 70，但"必须留痕"——**留痕就是抗二压**：完全贴黑的区域经平台暗部处理后只剩噪点。
- 霓虹高饱和（品红/青）按"高饱和区域必受损"的预期，母版阶段不要把霓虹推到裁切边缘，留出 5% 左右的饱和余量（经验口径）。

### 3.4 纪录片/高端品牌（低强度题材）

- `documentary-natural`（强度 ≤0.4）与 `luxury-brand`（黑位"深而不死"，暗部裁切 <1%）本身走克制路线，**预补偿同样克制**：B站投放几乎不加预补偿；若同片投抖音，通过交付侧"平台微调"提亮/提对比，不回母版加重风格。

## 四、视频特有规则

1. **母版只调一次，变体不重调**：调色落在干净母版；画幅（9:16 / 1:1 / 4:5）、时长、封面从已调色母版派生；平台适配只记录为"平台微调"（`color-delivery-spec` 第二章）。交付包的三个风格变体（`cool-tech` / `warm-film` / `punchy-social`，见 `deliver.ts` 的 `DELIVERY_VARIANTS`）是**风格选择**，不是平台适配——两者不要混为一谈。
2. **变体差异必须实测，不采信配方差异**：`assessVariantDistinctness` 以抽帧平均 RGB 的欧氏距离（0–441）为画面差异口径，**< 6 视为"画面测不出差别"**；音轨差（|LUFS 差|+|真峰值差|）**< 1.0 视为"音轨测不出差别"**；两者同时低于阈值 → G-DLV1 一票否决，交付包不放行。调色可见性另有 `≥4/255` visible / `2–4` subtle / `<2` 拒绝出片的口径（`color-delivery-spec` 证据包第 5 条）。
3. **竖屏 9:16 安全区与画质判断耦合**：竖屏派生时边缘裁切会切掉构图元素与字幕，**也会让调色师对曝光/对比的判断失真**——被裁掉的亮部（如窗外、灯牌）不再参与观感，主体区域的明度权重上升。判曝光、判字幕对比度时一律以 **9:16 安全区内的画面**为准，不看全幅。
4. **动态 + 二压双重衰减**：运动镜头的高频细节在平台降噪下消失得比静帧更快，依赖颗粒/纹理表达质感的题材（复古胶片、胶片颗粒 LUT）要预期"平台上颗粒感打折"，必要时在母版把质感做得略明显一点（经验口径）。
5. **真机抽查是最后的校验**：scope 与像素差度量都在母版/变体文件上做，二压损耗只有上传后才知道。重要投放前在目标平台用非公开/小号上传抽查，把实测结果回填经验库——**本仓库的平台知识以这种方式迭代，不靠抄网传参数表**。

## 五、常见误区

| 误区 | 纠正 |
|---|---|
| "把网传的平台码率表当精确参数用" | 平台转码策略不公开且随时变。本仓库不维护精确平台参数，行业数值一律标"经验口径"，以真机上传实测为准 |
| "抖音要高饱和，那把抖音版单独调艳一点" | 禁止按平台重新调色（`color-delivery-spec` 二.3）。平台差异走母版预补偿 + 交付侧平台微调，平台微调不动 profile/LUT |
| "二压会压画质，母版往死里加锐化/饱和对冲" | 过冲的锐化会被平台锐化叠出白边，过冲的饱和会变成色团。预补偿是"预留量"不是"加倍"，幅度以 targets 区间为界 |
| "压黑 = 电影感，暗部贴 0 才高级" | 贴黑的暗部经二压只剩色带与噪点。纪律是"留痕"：夜景裁切 <3%、高端品牌 <1%（recipes.json overrides 口径） |
| "变体文件都不一样，差异肯定够" | 配方不同 ≠ 观感不同。差异必须过 `assessVariantDistinctness` 像素差口径（画面 <6 且音轨 <1.0 → 雷同否决） |
| "竖屏版就是把横屏中间裁一块" | 边缘裁切改变构图、字幕安全与曝光判断基准；9:16 派生后必须以安全区内画面复检曝光与字幕对比 |
| "平台参数已经在 recipes.json 里配好了" | 现状：`platforms` 字段只是**声明性标签**（取值如 抖音/小红书/视频号/B站/官网/淘宝/美团 等），不参与参数计算；结构化平台微调参数是 T-14 任务（见第七章 roadmap） |

## 八、决策树

```
拿到调色/交付需求
  │
  ├─ 是"按平台各调一版"的请求？
  │     └─ 是 → 拒绝：违反派生纪律（color-delivery-spec 二.3）
  │           → 改为：母版调一次 + 平台变体派生 + 平台微调记录（模板 A）
  │
  ├─ 定题材配方（recipes.json，platforms 字段可辅助检索）
  │     └─ 检查配方 platforms 是否覆盖目标平台（声明性匹配，非硬性门槛）
  │
  ├─ 调母版（一次）：先校正后创作，intensity 叠加题材 look
  │     ├─ 预补偿判断：
  │     │     ├─ 抖音为主 → 对比/饱和向 targets 中上靠，暗部不压临界
  │     │     ├─ 小红书为主 → 收着调，白平衡中性优先
  │     │     ├─ 视频号为主 → 明度上浮、字幕对比复检
  │     │     └─ B站为主 → 基本不加，保留层次
  │     └─ 暗部留痕：夜景裁切 <3%，高端品牌 <1%
  │
  ├─ 派生变体（buildVariantPlan）：
  │     ├─ 画幅 9:16 → 安全区内复检构图/曝光/字幕
  │     └─ 跑 assessVariantDistinctness → 雷同 → G-DLV1 否决，加大差异重测
  │
  └─ 交付前：
        ├─ 可见性度量 ≥4/255（visible）方可宣称"已调色"
        ├─ 重要投放 → 目标平台真机抽查，结论回填经验库
        └─ 清单记录：母版 sha256 + 变体指纹 + 平台微调记录（经验口径标注）
```

## 九、关联知识

- **CGRADE-004 题材调色美学**（题材×情绪→look 的选型依据；平台偏好是在题材定调之后的第二层修正，不替代题材判断）
- **CGRADE-002 色彩空间**（交付口径 Rec.709 / 8-bit 的色彩空间依据；二压讨论全部建立在 SDR 交付口径上，HDR 属超出交付口径，按 `color-delivery-spec` 上报）
- **color-recipes 配方库**（`library/color-recipes/recipes.json`）：本文引用的真实配方 id——`food-appetite`（美食）、`talking-head`（访谈）、`beauty-makeup`（美妆）、`night-city`（夜景）、`festival-promo`（促销）、`documentary-natural`（纪录）、`luxury-brand`（高端品牌）、`kids-family`（亲子）；各配方 `platforms` 字段为声明性标签，`overrides` 承载目标区间收窄
