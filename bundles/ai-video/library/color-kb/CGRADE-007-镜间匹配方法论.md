# 镜间匹配（Shot Matching）方法论领域知识库

> **用途**：调色知识库。供调色师 / Agent 在多镜头、多机位、多批次素材统一影调时检索调用。
> **主题编号**：CGRADE-007　**版本**：v1.1　**更新日期**：2026-09-27
> **使用方式**：Agent 接收到涉及"镜头之间颜色不一致、多机位素材统一、接不上、跳色、批量匹配"等诉求时，检索本主题，按 color-shot-matching SKILL 的纪律执行：选参考镜 → `colorwrite.match` 逐镜派生校正 → 残差验收（ΔYAVG≤5、ΔUAVG/VAVG≤3）→ 超标处置。核心工具为 `colorwrite.match`（实现见 connectors/color-bridge/core.mjs 的 `match()` 与 `deriveMatchCorrections()`）。

---

## 一、核心概念

### 1.1 镜间匹配是什么

镜间匹配（Shot Matching）是**让同一场景 / 同一批次内的所有镜头看起来是"同一时间、同一台机器拍出来的"**——观众看到成片时，不应该察觉到镜头与镜头之间有任何亮度或颜色的跳变：

> **观众记不住单镜的漂亮，只记得跳变。同一支片子里两个镜头色温差 300K、肤色差一档，就会被感知为"业余"。多镜一致性的价值高于单个镜头的惊艳。**

- **匹配的目标不是"每个镜头都好看"，而是"镜头之间没有台阶"**——单镜可以妥协，跳变不能容忍。匹配是**相对**操作（以参考镜为锚点派生校正），锚点选错整批跑偏。
- 匹配是调色五步法（probe → analyze → correct → look → **match & verify**）的最后一步，在校正与 look 都完成之后进行。

### 1.2 为什么跳变比绝对偏差更刺眼（感知心理学依据）

人眼对颜色的判断是**相对和自适应**的，不是绝对测量仪器：

- **亮度适应**：人眼自动适应画面整体亮度，YAVG=95 和 YAVG=105 的镜头单看都"正常"；但连播时 10 级台阶立刻被感知为"闪了一下"。
- **色度恒常性**（color constancy）：大脑会自动"白平衡"当前场景，偏暖镜头单看没问题，切到中性镜头再切回来，偏色就暴露了。
- **突变检测优先**：视觉系统对"变化"的敏感度远高于"绝对量"。ΔYAVG=5 的渐变无人察觉，ΔYAVG=5 的硬切人人生疑。

因此验收判据必须按**镜头间差值**（Δ，目标 vs 参考）而不是按绝对区间来判定——这正是 ΔYAVG≤5、ΔUAVG/VAVG≤3 这组数字存在的原因。

### 1.3 匹配的工程实现（本仓口径）

`colorwrite.match`（core.mjs `match()`）的工作方式：

1. 对参考镜抽帧做 `signalstats`，得到参考汇总（YAVG/UAVG/VAVG/SATAVG）；
2. 对每个目标镜同样取汇总，`deriveMatchCorrections()` 派生校正：
   - 亮度差 → `eq=brightness`（clamp 在 ±0.12）；
   - 饱和比 → `eq=saturation`（clamp 在 0.7–1.4）；
   - U/V 差 → `colorbalance` 的 bm/bh、rm/rh（clamp 在 ±0.08）；
3. 应用校正后复检，输出每镜的 `residual`（与参考的均值残差 ΔYAVG/ΔUAVG/ΔVAVG + 直方图形状残差，T-24）与 sha256。

**派生量刻意保守（有 clamp 上限）**：一次只修一点，残差超标再迭代一轮，而非一次猛拉拉出噪点色块。

## 二、分类速查

### 2.1 匹配问题类型 → 成因 → 处置

| 问题类型 | 典型成因 | 处置 |
|---|---|---|
| **亮度台阶** | 不同镜头曝光参数不同；AI 生成批次间 seed 差异 | `colorwrite.match` 派生 brightness 校正，ΔYAVG≤5 收工 |
| **色温跳变** | 混合光源场景；不同设备自动白平衡结论不同 | 先各自做白平衡校正，再匹配 U/V 轴，ΔUAVG/VAVG≤3 |
| **饱和度漂移** | 不同机型色彩科学不同（手机浓艳 / 相机平淡） | 匹配派生 saturation 比值校正，clamp 0.7–1.4 |
| **肤色不接** | 有人脸镜头 hue 不在 20–40° 之间互跳 | 先修白平衡再动饱和；肤色优先于风格化 |
| **整批色偏** | 不同生成批次（不同模型/seed）的系统性偏差 | 属**已知系统偏差**，记录为配方备注，不每片临时调 |
| **分布不匹配** | 均值相同但直方图形状不同（如一个高对比一个灰平） | 直方图残差判据（T-24）自动识别：加权卡方 >0.12 告警/判负；超限镜仍须人工连播复核（见 4.3） |

### 2.2 参考镜三准则速查（SKILL 原文）

| 准则 | 判据 | 量化口径 |
|---|---|---|
| **完整曝光** | 直方图两端都不裁切，信息最全 | YAVG 落在 90–120 |
| **含人脸或已知中性物** | 有肤色可判，或有白墙/灰卡/白纸可判白平衡 | 肤色 hue 20–40°；neutral_patch 可取样 |
| **代表本片主体** | 主光条件最接近全片平均值 | 不是最戏剧化的那一镜 |

## 三、分场景实战

### 3.1 单机位同场景多镜头（最常规）

- 主镜头 / 英雄镜头（hero shot，叙事重心、信息最全的那条）优先作参考镜——它是观众记忆的基准，其他镜头向它靠拢。
- 逐镜 `colorwrite.match`，全部收进 ΔYAVG≤5、ΔU/V≤3 后连播一次主观确认。
- 修正先亮度后色度：亮度没对齐前色度判断不可靠（亮度影响人眼对饱和与色相的感知）。

### 3.2 多机位实拍（A 机 + B 机 + 特写机）

- 不同机型色彩科学差异是**系统偏差**：先各自基础校正（白平衡、曝光）磨平"机型性格"，再进匹配。
- 参考镜通常从 A 机（主机位）选——它承担最多叙事时长。
- 特写机往往因景深不同观感偏亮/偏艳，匹配后特别复查肤色 hue（20–40°）。

### 3.3 手机 + 相机 + 无人机混拍（最棘手）

- **第一步不是匹配，是统一色彩空间**：全部先转 Rec.709（见 color-grade SKILL 第 1 步 probe；疑似 log/HLG/PQ 素材先套转换 LUT，如本仓 `slog3-to-rec709`）。
- **禁止用创意 LUT 掩盖色彩矩阵差异**——LUT 是风格不是转换，矩阵没对齐就套 LUT 只会把差异烙进画面。
- 无人机素材常见高饱和蓝天 + 高对比，手机素材常见计算摄影的"浓艳平"——均值可能接近但分布迥异，收数字后必须连播人工复核。

### 3.4 AI 生成多批次素材

- 不同模型 / 不同 seed 批次的色偏属**已知系统偏差**：先批量统一，最后**对整批叠一次 look**（或对母版叠一次）。
- 批次间差异记录为配方备注，沉淀进 color-recipes，下一支片子直接复用，不重新踩坑。

### 3.5 只有一个镜头

- 跳过匹配，直接按配方调；仍要出前后指标与 scope 留痕（SKILL 失败与回退表第 3 条）。

## 四、视频特有规则

### 4.1 匹配顺序纪律：先亮度，后色度，再饱和度

**为什么不能一步到位**：

1. **先亮度（YAVG）**：亮度是观感的地基。亮度差 10 级时人眼无法可靠比较色度，且 `eq=brightness` 会间接改变饱和与色相的呈现。
2. **再色度（U/V）**：亮度对齐后，白平衡 / 偏色差异才暴露。U 轴蓝-黄，V 轴红-绿，分开判。
3. **最后饱和度**：必须在"底色"（亮度 + 色相）对齐后调，否则出现"饱和对齐了颜色还是不对"的假匹配。

工程上 `colorwrite.match` 一次派生全部三类校正，但**clamp 刻意保守**（brightness ±0.12、saturation 0.7–1.4、colorbalance ±0.08）——残差超标就再迭代一轮，每轮都在收敛后的新状态上重新判断，等效于"先亮度后色度"的人工节奏。

### 4.2 验收判据的工程含义（ΔYAVG≤5、ΔUAVG/VAVG≤3）

| 判据 | 通过线 | 感知含义 |
|---|---|---|
| ΔYAVG（目标 vs 参考） | ≤ 5 | 8-bit 亮度 255 级中的 5 级 ≈ 2%，恰在"渐变不敏感、硬切刚起疑"的阈值之下 |
| ΔUAVG | ≤ 3 | 蓝-黄轴 3 级 ≈ 色温一两百 K 的观感差，连播不可辨 |
| ΔVAVG | ≤ 3 | 红-绿轴 3 级，肤色与绿植 hue 不打架 |
| 肤色 hue | 20–40° | 有人脸镜头的附加判据，优先于一切风格 |
| 主观跳变 | 连播无感知 | **最终以连播为准，数字只是下限** |

这组数字的定位是**"必要不充分"**：过了数字关不代表观众看不出问题，不过则一定有问题。

### 4.3 残差判据的局限（均值陷阱）

YAVG/UAVG/VAVG 都是**均值**。两镜均值完全相同、直方图分布却迥异的情况是真实存在的：

- 镜头 A：阴天灰平，像素集中在中间调；
- 镜头 B：晴天高对比，暗部与高光两极分布；
- 二者 YAVG 可能都是 110，残差 = 0，连播却明显不接。

**直方图残差判据已落地（T-24）**：`match()` 在校正复检时，除均值残差外，另对参考镜与目标镜抽样帧提取 Y/U/V 三通道 64 bin 直方图（缩到 160 宽读 yuv420p 原始平面，不做 RGB 中转），计算对称卡方距离并按 0.6/0.2/0.2 加权（亮度权重最高——分布跳变的主犯是影调形状）。加权残差 > **0.12** 即判"分布不匹配"：合成素材标定为同片 ≈0、±10 级曝光差 ≈0.055、同均值异分布 ≈0.53，阈值两侧各留 ≥2× 余量。判据分级与均值判据对齐：默认 **warn**（写入 `residual.histogram.warning` 上报），`histogram_check=fail` 升级为该镜判负（`histogram_residual`），`off` 关闭。选卡方而非 EMD：EMD 对"分布整体平移"给近距离，恰恰会放过对比度差异这类跳变主犯。**注意：直方图判据仍是必要不充分，重要项目的连播人工复核不取消，只是从"唯一兜底"降级为"终审"**。

### 4.4 批次与断点纪律

- **逐镜处理、逐镜留痕**：每镜一条事件（前后指标 + 残差 + 哈希），中断可续。
- **同一批次不换 look**：先批量校正统一，最后统一叠一次 look（或对母版叠一次）。批次中途换 look 等于人为制造跳变。
- **一个项目一套 look**：look 是风格签名，中途换 look = 片子裂成两部。
- **跨批次 / 跨场景换 look 的过渡**：叙事上确有场次转换（如回忆段落转暖黄）时，换 look 应落在**场景切换的剪点**上，且给观众一个光线理由（开灯、出门、日出）；禁止同一场景内部渐变式换 look——那不是转场，是事故。

## 五、常见误区

| 误区 | 纠正 |
|---|---|
| "每个镜头单独调到最好看，再拼起来" | 恰恰相反。单镜惊艳、镜间跳变 = 业余。先定参考镜，所有镜头向锚点靠拢，牺牲单镜保全片 |
| "选最漂亮的那一镜作参考" | 参考镜要"曝光最正常、信息最全"，不是"最戏剧化"。最漂亮的镜头往往是光线最特殊的，以它为锚整批都会被拉偏 |
| "匹配就是一键对齐均值" | 均值对齐只是下限。分布不匹配（高对比 vs 灰平）均值残差为零也不接——直方图残差判据（T-24，加权卡方 >0.12 告警）已自动识别此类，超限仍须连播 + scope 复核 |
| "残差超标就加大校正力度硬拉" | 先怀疑参考镜选错，再怀疑目标镜本身裁切/欠曝。clamp 上限是保护：硬拉会出噪点和色块，信息丢了补不回来 |
| "欠曝/爆掉的镜头使劲提亮/压暗救回来" | 裁切与压死的像素没有信息，硬补必出噪点色块。退回上游重渲或标"不可修复"，不做假修复 |
| "多机位素材直接套同一个 LUT 就统一了" | LUT 是风格不是色彩空间转换。手机/相机/无人机先统一 Rec.709，再谈匹配和 look |
| "批次中间发现 look 不合适，顺手换一个" | 同批次不换 look。要换就整批换并重跑（工具幂等，成本可接受），不留一半一半的缝合怪 |
| "数字达标 = 完工" | 数字只是下限，最终以连播无感知跳变为准。验收报告必须包含连播结论 |

## 七、模板

### 模板 A：标准多镜批次匹配（同机型同场景）

```
1. 体检候选参考镜（每条跑 colorread.analyze）：
   - 淘汰 YAVG 越出 90–120 的（曝光不完整）
   - 淘汰无人脸且无中性物的（无法判白平衡）
   - 淘汰光线最戏剧化的（不代表全片主光）
   → 选定 hero.mp4，记录选择理由与被否候选的原因
2. 逐镜匹配：
   color-cli match --ref hero.mp4 --in a.mp4 --in b.mp4 --in c.mp4 --out-dir matched/
   （工具面 colorwrite.match：逐镜派生 曝光→饱和→色度轴 校正并复检）
3. 验收（每镜）：|ΔYAVG|≤5 且 |ΔUAVG|≤3 且 |ΔVAVG|≤3；有人脸追加肤色 hue 20–40°
4. 整批连播无感知跳变 → 统一叠一次 look（或留给母版统一叠）→ 收工
```

### 模板 B：残差超标处置

```
某镜残差超标（如 ΔYAVG = 8）：
  ├─ 第一步：怀疑参考镜选错
  │    → 复查三准则，不合格则重选参考、整批重跑（工具幂等）
  ├─ 第二步：怀疑目标镜裁切/欠曝（colorread.analyze 看 YMIN/YMAX 与裁切占比）
  │    → 信息已丢：不硬补（会出噪点/色块），退回上游重渲或标"不可修复"
  └─ 第三步：目标镜信息完整但仍偏差大
       → 手动补一轮校正（人/岗位永远可以压在自动之上），改完复检残差
```

### 模板 C：多机型混拍（手机 + 相机 + 无人机）

```
1. probe 全部素材：确认色彩空间 / transfer，标出疑似 log/HLG/PQ
2. 统一 Rec.709：log 素材先套转换 LUT（如 slog3-to-rec709），
   禁止在 log 上直接叠创意 LUT，禁止用 LUT 掩盖色彩矩阵差异
3. 各机型先做基础校正（白平衡 → 曝光 → 裁切 → 饱和），磨平"机型性格"
4. 从主机位（承担叙事时长最多的设备）选参考镜
5. colorwrite.match 逐镜匹配 → 残差验收（ΔYAVG≤5、ΔU/V≤3）
6. 混拍均值陷阱高发：直方图残差判据（T-24）已自动兜底，超阈值镜头仍须连播 + scope 直方图人工复核
```

### 模板 D：统计参考（无合格实拍参考镜时）

```
1. 全部镜头先逐镜 colorread.analyze，取全片指标中位数作为"统计参考"
2. 报告中必须写明：本批使用统计参考（非实拍参考），原因是____
3. 按统计参考派生校正，验收判据不变（ΔYAVG≤5、ΔU/V≤3）
4. 连播复核权重上调：统计参考没有实拍锚点的"画面可信度"
```

## 八、决策树

```
多镜头批次到达
  │
  ├─ 只有一个镜头？
  │     └─ 是 → 跳过匹配，按配方调；仍出前后指标与 scope 留痕
  │
  ├─ 素材跨机型 / 跨色彩空间？（手机+相机+无人机 / 含 log）
  │     └─ 是 → 先统一 Rec.709（log 先转换 LUT），各自基础校正，再进匹配流程
  │
  ▼
选参考镜（三准则）
  ├─ 完整曝光（YAVG 90–120，直方图两端不裁切）
  ├─ 含人脸或已知中性物（肤色 / 白平衡可判）
  └─ 代表本片主体（主光最接近全片平均，非最戏剧化的一镜）
  │
  ├─ 有合格候选 → 选主镜头/英雄镜头优先，记录理由与被否原因
  └─ 无合格候选 → 全片指标中位数作"统计参考"，报告注明
  │
  ▼
逐镜匹配（colorwrite.match）
  顺序纪律：先亮度（YAVG）→ 再色度（U/V）→ 后饱和度
  工具一次派生、clamp 保守；逐镜留痕（前后指标 + 残差 + 哈希），中断可续
  │
  ▼
验收（每镜）
  ├─ |ΔYAVG| ≤ 5 且 |ΔUAVG| ≤ 3 且 |ΔVAVG| ≤ 3？
  ├─ 有人脸镜头：肤色 hue 20–40°？
  └─ 整批连播：无感知跳变？（数字是下限，连播是终审）
  │
  ├─ 全部通过 → 统一叠一次 look（同批次不换 look）→ 出报告收工
  │
  └─ 残差超标 →
        ├─ 先怀疑参考镜选错 → 复查三准则，重选则整批重跑（幂等）
        ├─ 再怀疑目标镜裁切/欠曝 → 信息已丢则退回上游重渲或标"不可修复"，不硬补
        ├─ 目标镜信息完整 → 手动补一轮校正，复检残差
        └─ 数字达标但连播仍跳（分布不匹配，均值陷阱）
              → 直方图残差判据（T-24）默认已告警；按 warning 提示复查参考镜 + scope 直方图 + 人工曲线微调
```

## 九、关联知识

- **CGRADE-005 示波器**（波形/矢量/直方图读法）：匹配验收的"分布级复核"依赖 scope 判读，均值陷阱下直方图对比是人工兜底手段；对应工具 `colorread.scope`。
- **CGRADE-004 题材美学**：look 选型与强度按题材定（叙事片 warm-film、社媒 high-contrast-social 等），但**同批次不换 look** 的纪律优先于题材偏好——题材决定"用哪套"，批次纪律决定"一套用到底"。
- **color-shot-matching SKILL**（bundles/ai-video/skills/color-shot-matching/SKILL.md）：本主题的官方执行纪律来源——参考镜三准则、验收判据表、批次与断点纪律、失败与回退路径，一切以 SKILL 原文为准。
- **color-grade SKILL**：五步法母流程（probe → analyze → correct → look → match & verify），镜间匹配是最后一步；目标值表（YAVG 80–140、UAVG/VAVG≈128±6、SATAVG 40–80、肤色 hue 20–40°）是匹配前的单镜健康基线。
- **工程实现**：connectors/color-bridge/core.mjs 的 `match()`、`deriveMatchCorrections()`（校正派生与 clamp）、`analyze()`（signalstats 诊断）。
- **T-24 已落地**：直方图残差判据（Y/U/V 64bin 直方图 + 对称卡方 0.6/0.2/0.2 加权，阈值 0.12，默认 warn、可 `histogram_check=fail` 升级）补上了均值残差的漏检盲区；4.3 节的人工复核从"唯一兜底"降级为"终审"。同任务还接入可选 hqdn3d 降噪（`denoise` 显式开启 + 噪点代理命中才在校正前插入，`luma_spatial≤2.0`）。

> 执行镜间匹配任务时，建议 CGRADE-007 与 color-shot-matching SKILL、CGRADE-005 联合检索；涉及 look 选型时与 CGRADE-004 联合检索。
