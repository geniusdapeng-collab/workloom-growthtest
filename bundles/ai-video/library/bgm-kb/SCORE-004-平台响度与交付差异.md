# 平台响度与交付差异（Loudness Normalization & Delivery）领域知识库

> **用途**：配乐工位的响度工程知识库。供数字员工 / Agent 在配乐交付、平台变体派生、响度复检时检索调用。
> **主题编号**：SCORE-004　**版本**：v1.0　**更新日期**：2026-09-27
> **使用方式**：Agent 遇到"响度不达标、真峰值超标、平台要不同版本、手机上听不见低频"等问题时检索本主题。仓库内数值（-14 LUFS / -1.0 dBTP / [-15,-13] / 48k / AAC 192k）是工程口径，平台侧行为一律标注"经验口径"，禁止编造精确平台参数。

---

## 一、核心概念

### 1.1 响度不是音量

音量是电平（dBFS），响度是**人耳感知**（LUFS）。同一段音频，-20 dBFS 的低频轰鸣和 -20 dBFS 的人声，听起来响度完全不同——LUFS 通过 K 加权滤波（模拟人耳频响曲线）把"听着有多响"变成可计算的数字。

> **响度 = 观众的第一体感。内容决定观众"看什么"，响度决定观众"听不听得下去"。**

三个时间尺度的响度（EBU R128 定义）：

| 指标 | 窗口 | 回答的问题 |
|---|---|---|
| **Integrated（综合响度）** | 整段 | 全片平均有多响（平台归一化看这个） |
| **Short-term（短时响度）** | 3 秒滑动窗 | 这一小段有多响（让位/高潮段判断用） |
| **Momentary（瞬时响度）** | 400ms 滑动窗 | 这一瞬有多响（瞬态控制参考） |

### 1.2 真峰值（dBTP）与 LRA

- **真峰值 dBTP**：采样点**之间**可能出现的真实峰值（过采样测得）。AAC 等有损编码会进一步抬峰值，所以母版必须留天花板余量——本仓口径 **≤ -1.0 dBTP**。
- **LRA（响度范围，LU）**：全片响度的动态跨度。短视频 BGM 通常 LRA 不大（loudnorm 应用时本仓固定 `LRA=11`），动态过大的素材归一化后容易出现"高潮不够响、铺垫太吵"。

### 1.3 响度规范的来历

EBU R128（欧洲广播联盟，2010 年）把行业从"峰值表"时代带进"响度表"时代，配套 ITU-R BS.1770 算法。此后分化出三套口径：

| 口径 | 目标 | 场景 |
|---|---|---|
| 广电（EBU R128 / 国内 GY/T 282） | **-23 LUFS** | 电视播出，动态大、环境安静 |
| 播客 | **-16 LUFS**（经验口径） | 人声为主，耳机收听 |
| 流媒体/短视频 | **-14 LUFS**（YouTube 公开口径；主流短视频平台经验口径） | 手机外放、信息流混排 |

## 二、分类速查

### 2.1 本仓统一口径（recipes.json targets，工程真值）

| 项 | 取值 | 出处 |
|---|---|---|
| 综合响度目标 | **-14 LUFS**（合格带 [-15, -13]，复检容差 ±1.5） | `recipes.json: targets.lufsTarget / lufsIntegrated` |
| 真峰值上限 | **≤ -1.0 dBTP** | `recipes.json: targets.truePeakDbtpMax` |
| 采样率/声道 | **48kHz / 立体声**（与成片一致，不改声道布局） | bgm-delivery-spec |
| 成片音频编码 | **AAC 192k**；视频轨 **copy** 不重编码 | bgm-delivery-spec |
| 归一化方式 | **两遍法 loudnorm**，linear 模式 | core.mjs `normalizeLoudness` |
| 配乐可闻度 | ≥ **3dB**（无对白窗口相对原片的提升） | `targets.musicPresenceDb` |
| 人声-音乐余量 | 目标 **6dB**，3–6dB 记告警 | `targets.dialogueToMusicMarginDb` |

### 2.2 为什么选 -14 而不是 -16 或 -23

- **-23（广电）太轻**：信息流里你的片子比别人轻 9dB，观众划走前会先被"没声"劝退。
- **-16（播客）偏轻**：播客以人声为主、耳机收听；短视频是外放 + 混排，-14 是 YouTube 公开归一化目标，主流短视频平台经验口径也围绕这一带。
- **-14 是"不被平台再动手"的甜点位**：高于目标平台会向下压（可控），低于目标多数平台**不会**帮你抬（经验口径）——宁可压在 -14，不要交 -18 上去赌。

### 2.3 平台侧行为（全部经验口径，禁止写进参数）

| 平台 | 响度归一化行为（经验口径） | 链路上的坑（经验口径） |
|---|---|---|
| 抖音 | 有响度归一化，围绕 -14 一带；过响会压 | 上传后 AAC 重编码，峰值再上抬；外放小喇叭低频基本丢失 |
| 小红书 | 有归一化，行为与抖音类似 | 重编码同样存在；竖屏生活流场景外放为主 |
| 视频号 | 归一化存在，口径未公开 | 微信内播放链路长，重编码不可控 |
| B站 | 有响度归一化（经验口径偏宽松） | 用户可切音质档位，高码率下保留度更好；仍有重编码 |

> 四大平台的精确 LUFS 目标、压缩器参数均未公开——**以上是行业经验口径，只能指导"留余量"，不能当作验收数值**。验收只看本地实测（measure.mjs）。

## 三、分场景实战

### 3.1 手机外放小喇叭：短视频的第一收听环境

外放小喇叭的物理局限（经验口径）：

- **低频丢失**：200Hz 以下几乎不可闻——bass 铺得再厚，手机上只剩中频轮廓。配方里 `bass` 的作用是耳机/音箱场景的质感，不是响度来源。
- **中频突出**：1–4kHz 是小喇叭最有效率的频段——恰好与人声频段（本仓 200–4000Hz）高度重叠，BGM 的 pluck/bell 一旦抢中频，口播立刻糊。
- **实战结论**：外放可懂度靠"人声余量 + 让位"保证，不靠整体加响度；响度归一到 -14 只是入场券。

### 3.2 平台变体派生（只派生，不重混）

从已配乐母版派生各平台版本时：

- 画幅（9:16 / 1:1 / 4:5）、时长裁剪、封面：允许，属于派生；
- 整片响度归一（如某平台版本统一 ±1dB 内的微调）：允许，记为"平台派生"；
- 重新配乐、重调 `music_level_db`、重调让位深度、换配方：**禁止**——会造成同片不同响度/不同让位，且成本翻倍（bgm-delivery-spec 第二节）。

### 3.3 三遍听过关（交付前自检）

1. 耳机听：检查 bass 层次、让位是否自然；
2. 手机外放听：检查口播每个字能否听清、BGM 是否还"在"；
3. 信息流混排听（与其他热门视频连播）：检查响度是否明显偏轻或偏重。

## 四、视频特有规则

1. **两遍法 loudnorm，禁止一遍法**：一遍法（single-pass dynamic mode）按滑动窗实时调整增益，本质是动态处理器——遇到安静的铺垫段会往上抬、遇到高潮段往下压，产生可闻的 pumping（抽吸感）。两遍法先测量（`measureLoudness`：integrated LUFS / true peak / LRA / threshold），再把实测值回注给 `linear=true` 的第二遍做**整体线性增益**，全片音量曲线不动，只平移。
2. **真峰值要留余量**：loudnorm 的 TP 是"上限"不是"保证值"。本仓应用时把目标再压 0.5dB（`applyTruePeak = truePeak - 0.5`），且末尾有闭环修正（`trimMaster`：复检仍越界就整体下压再复测，只减不增）。交付口径仍是 ≤ -1.0 dBTP。
3. **AAC 编码会抬峰值**：48kHz 母版（pcm_s16le）达标后，封进 AAC 192k 的成片必须**再实测一次**——本仓复检对象就是最终成片（core.mjs `loudnessAfter`），不是中间 WAV。
4. **视频轨永远 copy**：响度问题在音频链路内解决，任何情况下不为了音频重编码画面。
5. **48kHz 不改采样率**：视频行业统一 48k（44.1k 是音乐发行口径），与成片保持一致避免重采样引入的相位与峰值问题；AAC 192k 立体声对 BGM + 口播的保真足够，更高码率在平台重编码后无意义。

## 五、常见误区

| 误区 | 纠正 |
|---|---|
| "响度越大越占便宜" | 平台归一化会把过响的片子压回目标，压缩过的素材压完反而更糊；交 -14 线性母版是最优解 |
| "用一遍法 loudnorm 省一半时间" | 一遍法是动态模式，pumping 直接毁掉铺垫-高潮的起伏设计；两遍法多花的一次解码是必付成本 |
| "真峰值 -1.0 贴边就行" | loudnorm 的 TP 不保证达标（本仓实测贴边设置后实测 -0.74dBTP），必须留 0.5dB 余量 + 闭环复测 |
| "每个平台单独混一版更贴" | 违反派生纪律：同片不同让位、不同响度，复核无基线。只允许整片级响度微调，且记为平台派生 |
| "手机上低频听不见，干脆把 bass 拉满" | 拉满 bass 只会让耳机/音箱场景轰头，小喇叭照样听不见。低频靠"存在感"不靠"音量"，见配方 avoid 项"低频轰鸣" |
| "平台参数网上能查到，照抄就行" | 四大平台精确口径均未公开，网传数值版本混乱。本仓只认本地实测（integrated / true peak / LRA），平台侧一律标经验口径 |
| "AAC 192k 太低，上 320k" | 平台上传后一律重编码，320k 的冗余在重编码后归零；192k 是"重编码前不拖后腿"的性价比点 |
| "响度达标 = 配乐合格" | 响度只是门票。可闻度 <3dB、人声余量 <3dB 照样判不合格（复检 fail-closed，产物删除不得交付） |

## 六、意图→参数映射表

> 规则：Agent 接到响度/交付相关意图时，按本表翻译成工程参数或 ffmpeg 关键词。仓库内数值直接用；平台侧数值一律带"经验口径"字样。

| 创作意图 | 中文写法 | 英文关键词/参数 |
|---|---|---|
| 交付标准响度 | 综合响度归一到 -14 LUFS，合格带 [-15,-13] | `target_lufs=-14`, `loudnorm=I=-14` |
| 真峰值不超标 | 真峰值 ≤ -1.0 dBTP，应用时留 0.5dB 余量 | `true_peak_dbtp=-1.0`, `TP=-1.5`（应用值） |
| 响度实测不改音频 | 先测一遍 integrated / true peak / LRA | `loudnorm print_format=json`, `measureLoudness` |
| 线性归一不动动态 | 两遍法、线性模式、回注实测值 | `linear=true:measured_I=…:measured_TP=…:measured_LRA=…:measured_thresh=…:offset=…` |
| 成片封装 | 48kHz 立体声，音频 AAC 192k，视频轨 copy | `-ar 48000 -ac 2 -c:a aac -b:a 192k -c:v copy` |
| 真峰值越界补救 | 整体下压再复测，只减不增 | `trimMaster`, `masterTrimDb` |
| 检查配乐存在感 | 无对白窗口可闻度 ≥3dB | `musicPresenceDb >= 3` |
| 检查人声清晰度 | 人声-音乐余量目标 6dB，3–6dB 告警 | `dialogueToMusicMarginDb=6` |
| 平台版本 | 从母版派生，只许整片响度微调，禁止重混 | platform derive, no re-mix |
| 手机外放优化 | 保人声频段余量，低频不堆量（经验口径） | voice band 200–4000Hz headroom, bass restraint |

## 七、模板

### 模板 A：母版响度归一（两遍法，本仓实现）

```
# 第一遍：测量（不改音频）
ffmpeg -i premaster.wav -vn -map 0:a:0 \
  -af loudnorm=I=-14:TP=-1.0:LRA=11:print_format=json -f null -
# → 解析 JSON 得 input_i / input_tp / input_lra / input_thresh / target_offset

# 第二遍：线性应用（TP 留 0.5dB 余量）
ffmpeg -i premaster.wav \
  -af loudnorm=I=-14:TP=-1.5:LRA=11:linear=true:\
measured_I=<i>:measured_TP=<tp>:measured_LRA=<lra>:\
measured_thresh=<thresh>:offset=<offset>:print_format=summary \
  -c:a pcm_s16le -ar 48000 -ac 2 master.wav

# 闭环：复测 master.wav，TP > -1.0 则整体下压（只减不增）再复测
```

### 模板 B：成片封装与复检

```
ffmpeg -i master.wav -i video.mp4 \
  -map 0:a -map 1:v -c:v copy -c:a aac -b:a 192k -ar 48000 -ac 2 \
  <项目>-<版本>-bgm.mp4
# 复检对象 = 成片本身：integrated ∈ [-15,-13]，true peak ≤ -1.0 dBTP
# 证据包附：配乐前后 integrated / true peak / LRA + sha256
```

### 模板 C：平台派生回执（允许的最小动作）

```
平台派生：douyin / 9:16 画幅裁剪 + 整片响度微调 -0.8dB
基线母版：<sha256>；派生产物：<sha256>
声明：未重新配乐、未调整让位与音乐电平（platform derive, no re-mix）
```

## 八、决策树

```
母版完成（48kHz WAV，两遍法 loudnorm 已归一）
  │
  ├─ 目标平台？
  │     ├─ 抖音 / 小红书 / 视频号 / B站：统一 -14 LUFS / -1.0 dBTP 口径（平台精确目标未公开，经验口径）
  │     └─ 海外（YouTube 等）：同一口径，-14 即 YouTube 公开目标
  │
  ├─ 响度校验（对成片实测，不是对中间 WAV）
  │     ├─ integrated ∈ [-15, -13] 且 true peak ≤ -1.0 dBTP → 进入派生
  │     ├─ integrated 超差 → 回到两遍法 loudnorm 重出母版（loudness_ok=false，如实上报）
  │     └─ true peak 超标 → trimMaster 闭环下压再复测；仍超标 → loudness_ok=false 不得交付
  │
  ├─ 派生变体（只派生不重混）
  │     ├─ 允许：画幅裁剪 / 时长裁剪 / 封面 / 整片响度微调（记"平台派生"）
  │     └─ 禁止：重新配乐 / 调 music_level_db / 调让位 / 换配方 → 发现即退回，按新任务立项
  │
  └─ 超标处置
        ├─ 响度不达标 → 重跑 loudnorm 两遍法
        ├─ 真峰值超标 → 闭环下压（只减不增）
        ├─ 可闻度 <3dB → 提电平或换更厚配方重出（不是响度问题，别拧 loudnorm）
        └─ 素材本身削波/底噪 → 不可修复，退回上游，不得用配乐掩盖
```
