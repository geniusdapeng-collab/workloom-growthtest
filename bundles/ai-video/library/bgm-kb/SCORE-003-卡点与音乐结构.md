# 卡点与音乐结构（Beat Alignment & Section Picking）领域知识库

> **用途**：AI 视频配乐系统的决策知识库。供配乐师 / Agent 在"选哪段音乐、按什么速度、怎么对齐剪辑点"时检索调用。
> **主题编号**：SCORE-003　**版本**：v1.0　**更新日期**：2026-09-27
> **使用方式**：Agent 拿到"曲目 + 成片剪辑点"后，按本主题的决策链执行：定 BPM → 选段 → 对齐 → 验收 → 超标处置。所有数值均来自仓内真实参数（bgm-bridge/core.mjs、tag.mjs、bgm-recipes/recipes.json、bgm-score-design SKILL），禁止凭感觉编数。

## 一、核心概念

### 1.1 卡点是什么，为什么对不齐会"说不出的难受"

卡点（Beat Alignment）是**让剪辑点落在音乐节拍上**。观众说不出来哪里不对，但会在前 3 秒就感到"这片子不专业"：

> **人耳对"音画同步偏差"的感知阈值远小于对音质的感知阈值。音质差一点没人发现，节奏错半拍人人都难受。**

原因在于大脑会自发把视觉事件（画面切换）和听觉事件（鼓点/拍点）绑定成一个感知对象。两者时间差在 **±80ms 以内**时，大脑自动"缝合"成同一事件——这是仓内 `toleranceMs: 80` 的感知依据：误差 ≤80ms 记落拍。超出这个窗口，大脑无法缝合，产生持续的"错位感"：不是某一下难受，而是整段都"漂"。

验收口径分两层（`alignBeatGrid`，core.mjs）：

- **单点层**：每个剪辑点到最近拍点的误差 ≤80ms 记落拍；落拍率 100% 记 `aligned`、≥60% 记 `partial`、其余 `unaligned` 如实上报。
- **均值层**：`recipes.json` 的 `targets.alignmentMeanAbsErrorMs = 60`——加权平均误差 60ms 内才算达标（代码注释口径：≤60ms 记 aligned、≤120ms 记 loose）。60ms 比 80ms 单点容差更严，因为均值代表整体"漂不漂"，个别大偏差可以由单点层兜住。

### 1.2 速度错了，怎么对都对不齐

卡点对不齐，**九成是速度（BPM）错了，不是对齐算法不行**。拍距（beatSec = 60/BPM）一旦与剪辑节奏不匹配，误差会逐拍累积，任何偏移搜索都救不回来。所以决策顺序永远是：**先定对 BPM，再谈对齐**。

### 1.3 选段和卡点同等重要

外部曲目往往 2–3 分钟，成片只有 15–60 秒。**"裁哪一段"决定了情绪弧线能不能对上画面**：把 verse 铺到片子高潮上，画面在燃、音乐在平，比卡点对不齐更致命。选段的依据是曲目的**结构识别**（能量包络分段）与片子的**高潮时刻**（三级判据），两者对齐靠**预卷相位**，见第三、四章。

## 二、分类速查

### 2.1 段落类型（analyzeStructure 的分段词表）

| 段类型 | 能量特征 | 配乐曲用途 |
|---|---|---|
| **intro** 前奏 | 低能量起步，只留 pad + bass | 铺垫段候选；不抢开场第一句话 |
| **verse** 主歌 | 中低能量，平稳 | 铺垫段候选；口播片的安全选择 |
| **build** 推进 | 能量爬升，起音变密 | 高潮前的过渡；不宜单独成段使用 |
| **drop** 高潮 | 全曲最响、最密 | **高潮段首选**（climax 候选第一名） |
| **breakdown** 回落 | 高潮后抽空 | 转折/反转后的缓冲 |
| **outro** 尾奏 | 能量回落收束 | 自然收尾，不做硬切 |
| **flat** 平坦 | 全曲动态过小，分不出段 | 如实标注"无高潮可挑"，从曲头取段 |

识别方法（诚实边界，必须写进交付说明）：解码为 8kHz 单声道 PCM，按 0.25s 窗口算 RMS 能量包络，用**能量分位数（p25/p75）三档 + 段内走向 + 起音密度**做规则式分段。这是规则识别，不是深度学习，也不是乐谱级主歌/副歌标注；它能稳定回答"哪段最响、最密、最适合当高潮"，仅此而已。

### 2.2 结构比例（自算曲的段落配比）

| 段落 | 占比 | 配器 | 作用 |
|---|---|---|---|
| 前奏 intro | ~15% | 只留 pad + bass | 不抢开场第一句话 |
| 主体 body | ~73% | 加 pluck，必要时 kick/hat | 承担推进感 |
| 尾奏 outro | ~12% | 回落到 pad | 自然收束，不做硬切 |

> 15/73/12 的含义：开场短（15% 内必须进主体，否则观众滑走）、主体长（73% 承担全部叙事）、尾奏短而完整（12% 自然衰减，避免"歌被剪断"的戛然而止感）。**片子多长就写多长，不裁歌**：外部曲目短于片长时循环铺满，不靠剪断一句旋律对齐时长。

### 2.3 选段模式（SECTION_MODES）

| 模式 | 行为 | 适用 |
|---|---|---|
| `auto` | 默认口径：找得到片子高潮就对齐高潮段，找不到取代表性段落从头铺 | 绝大多数成片 |
| `climax` | 明确取曲子高潮段（drop 优先） | 快剪、促销、高潮明确的片子 |
| `calm` | 明确取铺垫段（intro/verse 优先） | 口播、纪录、悬疑铺垫 |
| `full` | 整曲循环铺满，不选段 | 曲子短或曲子本身平坦 |
| `section-start/end` | 手工指定秒数区间 | 人工审过的精修片 |

## 三、分场景实战

### 3.1 速度决策链（先定 BPM，再谈一切）

按优先级从高到低：

1. **显式剪辑网格 `cutTimes` 优先**。成片方给出的真实剪辑点（如"每镜 5s 硬切"）是事实源，**优先于从音轨起音反推**（`detectCuts`）。2026-09-25 真机教训：快剪片里音频起音会把台词音节当成剪辑点（36 个 0.5s 级起音），BPM 反推全部落空、退回 100BPM 默认值，卡点指标对任何片子都报同一组数字、永远判未对齐。
2. **剪辑点反推**（`deriveTempoFromCuts`）：相邻剪辑点间距 ÷ 一拍 = 整拍数（2–16 拍），反推 BPM；间距 ≤0.25s 的剔除，候选限 40–200 BPM。
3. **音轨起音反推**（`estimateBpmFromOnsets`）：起音包络自相关，在 50–190 BPM 滞后范围内找最强周期；持续铺底 pad 拿不到稳定周期时返回 `confidence=low + null`，**绝不硬编一个 BPM**。
4. **八度折叠**（`canonicalBpm`）：自相关常见 2 倍/0.5 倍歧义（240 = 120 的双拍），一律折叠到 **55–165** 这个"人耳拍速"区间再入索引；原始值留在证据里，不隐瞒。

### 3.2 ±25% 阈值的含义（为什么不能为迁就音乐大改剪辑）

剪辑节奏优先：反推 BPM 与配方 BPM 相对差 **≤25%** 时采用反推值（`bpm_strategy=cut-driven`）；**超过 25% 沿用配方 BPM 并如实说明冲突**。

这条阈值的本质是：**剪辑是内容，音乐是包装**。相对差 >25% 意味着片子的剪辑节奏与题材配方根本不在一个世界里（比如口播片按 84 BPM 配方，剪辑点却反推出 140），此时正确答案不是把剪辑节奏拧向音乐（重剪内容），也不是把音乐拉到怪异的拍速，而是承认冲突、用配方 BPM、把理由写进回执。同一个项目只用一个速度——"开场 128、正片 96"听着像两条片子拼的。

### 3.3 auto 选段三级高潮判据（核心纪律）

`filmClimaxTime` 按优先级取片子的"高潮时刻"，**每级都要"确有峰"才采用，找不到如实返回 `basis: "none"`**：

1. **`cut-density` 剪辑密度成簇**：±2s 窗口内 ≥2 个剪辑点处——画面节奏的高点，最可靠。
2. **`non-dialogue-energy` 非对白能量峰**：非对白窗口里的能量峰，且比非对白窗口中位数高 ≥3dB——空镜/动作段的高点。
3. **`audio-energy` 音频总能量峰**：仅当全片对白占比 <35% 时才采信——对白稀少的片子才把它当高潮。

**为什么必须排除对白峰值**：口播片的高潮是画面/情绪，不是音量。台词最响处恰恰是最不该压音乐高潮的地方——鼓点砸在句读上，字全糊了。真机踩过的坑：0.25s 分析窗跨在对白起音上，被当成"安静段的能量峰"，于是音乐高潮精准地撞在台词开头。所以安静窗口判定要求"整窗落在静音段内、离人声边界至少 0.75s"。**选不出来要说选不出来**：回执里 `filmPeakAlign.skipped` 如实写明，而不是编一个高点。

### 3.4 高潮落点（brief.climax）与选段的配合

简报（`bgmread.brief`）给出的 `climax.position/atSec` 是选段对齐的目标锚点：结尾反转 → 85% 处；黄金三秒 → 8% 处；中段爆发 → 50% 处。执行顺序：

1. brief 有明确高潮位置 → 用它（或 `filmClimaxOverrideSec` 显式覆盖）；
2. 没有 → 走三级判据（3.3）；
3. 判据也找不到（口播/访谈类没有画面高潮）→ **不硬对**，取曲子最有代表性的一段从片头铺。

选段后把曲子高潮段的能量峰值对齐到该锚点，真机验收线：峰值实际落点与片子高点误差 ≤1.5s（structure.test.ts）。选出的段比片子还长（>曲子一半或 >片长×1.2）时，在段内**滑窗**：以能量最高窗为中心取 min(片长, 曲子 40%) 的窗口。

> **已落地（T-23，2026-09-27）·弧线偏好**：`bgmread.brief` 支持可选输入 `emotionArc`（分镜情绪标签序列，或引用 color_report/分镜摘要的字符串），由 `brief.mjs` 的 `arcPreferenceFromEmotionArc` 归纳成 T-22 六种能量弧线之一（flat-ambient / rising-steady / build-drop / wave-narrative / outro-resolve / front-loaded）并写入 `brief.arcPreference`。选曲打分时曲目 `arc:` 标签与偏好精确命中 +5、同族（低张力铺底族 / 高动态起伏族）+2、不符 +0（权重 5，从调性以外的既有维度协调，总分口径恒为 100）；无弧线输入时该维度不生效，曲目无 arc 标签记 0 不惩罚。

## 四、视频特有规则

1. **节拍网格对齐（`alignBeatGrid`）**：在 **[0, 一拍)** 区间内以 5ms 步长搜索偏移量，让所有剪辑点到最近拍点的**加权**平均误差最小（剪辑点带 score 时作权重）。只需一个偏移——网格相位平移不改变拍距。无剪辑点时退回 offset=0，如实标注"无参考点"，不做任何假装对齐的表述。
2. **预卷（preroll）相位旋转**：高潮对齐**禁止**把整条音乐床延后（`adelay`）。2026-09-24 真机事故：选段 9.5s、峰值在段内 1.5s、片子高点 27.233s，旧实现整条床延后 25.733s，30s 成片前 25.7s 是数字静音（-120dBFS），产品所有者反馈"听不到新合成的 BGM"。正确做法：把选段旋转 `phase = (anchor - peak) mod L` 秒后再循环铺满（`prerollPhaseSec`）——峰值仍落在片子高点，同时从 0s 起全程有音乐。回归判据（结果级）：混音减原片的前 3s 残差 RMS 必须 > -40dBFS，证明开头有配乐。
3. **边界吸附看 BPM 置信度**：片段切点优先吸到结构边界，其次吸到节拍网格；BPM 置信度 low 时**不吸**——低置信度的网格会把边界带到没有意义的位置，宁可不吸也不乱吸。
4. **循环铺满，不裁歌**：选段短于片长时按相位循环铺满；外部曲目短于片长用 `-stream_loop`。乐句中间硬切是禁忌。
5. **对白片默认降对齐期望**：口播/访谈片剪辑点稀少、无画面高潮是常态，`auto` 找不到高点时如实报 `skipped`，不要为了"有对齐结果"把音乐高潮怼到台词上。

## 五、常见误区

| 误区 | 纠正 |
|---|---|
| "卡点对不齐就调对齐算法" | 九成是 BPM 错了。先查速度决策链：cutTimes 有没有给、反推值与配方差是否 ≤25% |
| "为迁就音乐把剪辑节奏改匀" | 剪辑是内容，音乐是包装。相对差 >25% 沿用配方 BPM 并说明冲突，不动剪辑 |
| "把台词最响处当片子高潮" | 对白峰值必须排除。音乐高潮对到句读上 = 打击乐压字。三级判据里对白占比 ≥35% 直接否掉音频能量峰 |
| "高潮对齐 = 把音乐床整体延后" | 会造成前段静音事故。用预卷相位旋转：峰值落点对、0s 起有音乐 |
| "BPM 估不出来就编一个" | 置信度 low 时如实返回 null，退回配方 BPM；硬编的 BPM 会让边界吸附和卡点全部失效 |
| "估出 240BPM 就是 240" | 自相关有八度歧义，canonicalBpm 折叠到 55–165 再使用；原始值留证据 |
| "选段必须选在结构边界上，不惜乱吸" | BPM 置信度 low 时不吸附。乱吸的边界比不吸更糟 |
| "片子没高潮也要硬找一个对齐" | `basis: "none"` 是合法结论。取代表性段落从头铺，回执如实写 skipped |
| "把曲子剪断凑片长" | 循环铺满（stream_loop），不裁乐句。尾奏 ~12% 自然收束 |
| "80ms 内都对上了就是达标" | 单点 ≤80ms 只是落拍线；还要看均值 ≤60ms（alignmentMeanAbsErrorMs）才算 aligned |

| 节拍网格对齐 | [0,一拍) 内搜偏移，加权误差最小 | `alignBeatGrid({bpm, cuts, stepMs: 5})` |
| 高潮对齐不静音 | 预卷相位旋转后循环铺满 | `prerollPhaseSec({sectionDurationSec, anchorOffsetSec, filmPeakSec})` → `mode="preroll-loop"` |
| 卡点验收 | 单点 ≤80ms 落拍、均值 ≤60ms 达标 | `toleranceMs: 80`, `targets.alignmentMeanAbsErrorMs: 60` |

## 七、模板

### 模板 A：快剪促销片（显式剪辑网格 + 高潮段）

```
输入：30s 促销切片，剪辑方给出网格 cutTimes=[0,2.5,5,7.5,...]，brief 含"结尾报价"。
1. bgmread.brief --prompt-text "..." → recipeId=festival-promo, climax≈85%（25.5s 附近）
2. BPM：cutTimes 优先 → deriveTempoFromCuts(cuts, baseBpm=128)
   → 间距 2.5s ≈ 4 拍 → 反推 96？差 25%？→ 按阈值裁决，写进回执
3. 选段：--section auto → 片子有高点 → 取 drop 段，峰值对齐 25.5s
4. 对齐：alignBeatGrid(bpm, cuts) → offsetSec 搜出，验收 meanAbsErrorMs ≤60
5. 落点：prerollPhaseSec 旋转相位 → preroll-loop，前 3s 残差 >-40dBFS 回归通过
```

### 模板 B：口播访谈片（无画面高潮，诚实不硬对）

```
输入：60s 访谈，全程对白，剪辑点稀少。
1. brief → recipeId=interview，bpm=84，avoid 含"打击乐"
2. BPM：配方 84（剪辑点不足，反推无候选 → source="recipe"）
3. 选段：--section auto → 三级判据：无剪辑成簇 / 非对白峰不足 3dB / 对白占比 ≥35%
   → basis="none" → 取代表性段落从片头铺，filmPeakAlign.skipped 如实写明
4. 对齐：无密集剪辑点 → alignBeatGrid 报 no_cuts 或仅作参考，不假装 aligned
5. 电平与让位按 SCORE-001 口径（musicLevelDb -26, duckingDb 14）
```

### 模板 C：旅拍混剪（音轨起音反推 + 边界吸附）

```
输入：45s 旅拍，无显式网格，空镜为主。
1. cuts = detectCuts（无 cutTimes 时的回退源）
2. BPM：deriveTempoFromCuts(cuts, baseBpm=104) → 采用或说明冲突
   交叉验证：analyzeStructure 的 estimateBpmFromOnsets → canonicalBpm 折叠到 [55,165]
3. 选段：--section auto → cut-density 成簇处为高潮 → drop 段峰值对齐
4. 切点吸附：BPM 置信度 medium/high → 吸到结构/节拍边界；low → 不吸
5. 验收：落拍率 100% 报 aligned；≥60% 报 partial 并附每个剪辑点 errorMs
```

## 八、决策树

```
拿到曲目 + 剪辑点
  │
  ├─ 1. 定 BPM
  │     ├─ bpmOverride 有值 → 用之（explicit）
  │     ├─ cutTimes 有值 → 显式网格（事实源）
  │     │     否则 detectCuts 从音轨起音反推（警惕台词音节冒充剪辑点）
  │     ├─ deriveTempoFromCuts：间距÷整拍 → 候选 BPM
  │     │     ├─ 与配方差 ≤25% → 采用反推值（cut-driven）
  │     │     └─ 差 >25% → 沿用配方 BPM，回执写明冲突
  │     └─ 交叉验证：estimateBpmFromOnsets（自相关）
  │           ├─ confidence=low → 如实 null，退回配方值
  │           └─ canonicalBpm 折叠到 55–165
  │
  ├─ 2. 选段（chooseSection）
  │     ├─ brief.climax / filmClimaxOverrideSec 有锚点 → 用之
  │     ├─ 否则三级判据找片子高潮：
  │     │     cut-density（±2s ≥2 剪辑点）
  │     │     → non-dialogue-energy（≥中位数+3dB）
  │     │     → audio-energy（对白占比 <35% 才采信）
  │     ├─ 找到 → 取 drop 段；段太长 → 段内滑窗（能量最高窗为中心）
  │     └─ 找不到 → basis=none，取代表性段落从头铺，不硬对
  │
  ├─ 3. 对齐（alignBeatGrid + preroll）
  │     ├─ [0,一拍) 内 5ms 步长搜 offset，加权平均误差最小
  │     ├─ 高潮对齐：prerollPhaseSec 相位旋转 + 循环铺满
  │     │     （禁止整条床 adelay——前段静音事故）
  │     └─ 切点吸附：BPM 置信度 low 不吸，否则吸结构/节拍边界
  │
  ├─ 4. 验收
  │     ├─ 单点：误差 ≤80ms 记落拍；100% aligned / ≥60% partial / 其余 unaligned
  │     ├─ 均值：meanAbsErrorMs ≤60 达标（≤120 仅 loose）
  │     ├─ 落点：peakLandedAtSec 与片子高点误差 ≤1.5s
  │     └─ 回归：前 3s 残差 RMS > -40dBFS（开头不许静音）
  │
  └─ 5. 超标处置
        ├─ 均值 60–80ms → 重搜 offset 无效则换选段（换更贴拍距的段）
        ├─ 落拍率 <60% → BPM 可疑：回第 1 步查 cutTimes/反推链
        │     仍不行 → 换曲（拍速与剪辑节奏根本不合，别硬拧）
        └─ 结构性无解（剪辑自由节奏、无拍可卡）→ 接受现状，
              verdict 如实报 unaligned 并上报，不编造对齐结果
```

## 九、关联知识

- **SCORE-001 配乐电平与让位**：卡点对齐之后，音乐"站多前、人声让多深"的口径（musicLevelDb、duckingDb、对白-音乐余量 ≥6dB、-14 LUFS 母版）。
- **SCORE-002 配乐风格决策**：选哪条配方（16 题材配方）、调式/配器/禁忌——本主题解决"选哪段、怎么对"，SCORE-002 解决"选哪首、什么调"。
- **bgm-score-design SKILL**：本主题的工程口径来源——速度决策（±25% 阈值）、auto 三级高潮判据、15/73/12 结构比例、卡点 80ms 验收线的原始定义。
- **bgm-recipes/recipes.json**：`targets.alignmentMeanAbsErrorMs=60` 及全部混音目标值的事实源。
- **bgm-bridge/core.mjs**：`deriveTempoFromCuts` / `alignBeatGrid` / `chooseSection` / `prerollPhaseSec` / `filmClimaxTime` 的实现与真机事故注释（2026-09-24 预卷修复、2026-09-25 显式 cutTimes 优先）。

> 卡点问题先查速度、再查选段、最后才是对齐算法；涉及电平与人声让位时与 SCORE-001 联合检索，涉及配方选型时与 SCORE-002 联合检索。
