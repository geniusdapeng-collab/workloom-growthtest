# 断点根因闭环套件

## 适用场景
- 无人酒店/自助酒店八大断点（订单异常/身份验证失败/复杂需求/投诉/维修派单/异常查房/夜间设备故障/安全事件）的复盘与收敛；多店复制前的运营成熟度评估

## 触发条件
- 任一断点事件处置完成（三级兜底：AI→远程→现场，任一级结案即触发）；每周一 04:00 断点率周报

## 输入数据
- 断点事件全链留痕（触发条件/响应级别/处置过程/结果）、一店一档 incident_profile（设备清单/应急联系人三级树/报警联动方式）、awareness 高频检测数据

## 方法
1. 根因强制四分类：结案时必须归类——①数据缺失（一店一档信息不全导致 AI 无法处理）②规则未覆盖（无对应围栏/SOP）③能力边界（Skill 边界外，需人工或硬件）④真随机（不可预防）。未分类不许结案。
2. 根因-优化动作映射：①→ 补一店一档字段（给出具体缺失字段清单）；②→ 生成围栏规则/SOP 草稿进审批流（F2.4 生命周期）；③→ 登记为「人工保留区」或提 Skill 扩展需求；④→ 接受并标注，纳入应急演练剧本。
3. 固化联动：同类根因断点周均 ≥3 次 → 自动产出固化建议（awareness AWARENESS_WEEKLY_THRESHOLD 机制），店长一键确认后生成触发器/SOP/技能草稿。
4. 三级兜底审计：每个断点评估「本可由更低级别处置吗」——远程解决的能否沉淀为 AI 规则？现场应急的能否沉淀为远程 SOP？推动处置层级持续下沉。
5. 断点率周报：断点总量/分类分布/平均处置时长/层级下沉率/收敛曲线（逐周断点率应单调下降；连续两周上升 → 告警店长）。

## 输出动作
- 根因分类记录/优化动作工单/固化建议/断点率周报/应急演练剧本更新

## 对接系统
- 五元事件库、awareness 意识系统、一店一档 incident_profile、围栏生命周期（F2.4）、IM 班组

## 围栏绑定
- 分类与报告 auto；生成围栏草稿 → F2.4 审批流（draft→pending_approval）；安全事件类断点只告警+联动报警，AI 绝不自行处置（R10 安全禁区 block 红线）

## 验收用例
- 正常路径：身份验证失败断点结案 → 根因分类「数据缺失」→ 产出「补录入住人证件有效期字段」工单 → 次周同类断点归零
- 异常路径：夜间门锁失灵 → 现场应急结案 → 根因「能力边界」→ 登记人工保留区 + 更新应急预案 → 周报呈现
- 围栏触发：同类断点周均 4 次 → awareness 固化建议自动生成；安全事件断点尝试自动处置 → R10 block 并即时告警

## 证据口径（无回执不算完成）

1. 根因分类记录 + 优化动作工单（含责任人/截止）
2. 断点率周报（含口径与数据源）；固化建议版本号
3. 围栏草稿引用 F2.4 审批流状态（draft→pending_approval）；安全事件按 R10 只告警
