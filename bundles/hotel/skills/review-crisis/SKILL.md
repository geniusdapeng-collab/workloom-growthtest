# 差评危机公关

## 适用场景
- 各渠道评价实时监控（事件驱动，评价发现 <1 小时）
- 差评应急处理（一律挂起待审，R6）；严重差评升级店长

## 触发条件
- 各渠道评价发布事件实时触发

## 输入数据
- 各渠道评价内容、客人历史（guest.history.read）、投诉类型分类、一店一档 SOP 与 compensation_policy

## 方法
1. 先读档案品牌规范与禁用承诺（forbidden）。
2. 差评分级：轻微（单点不满）/中等（多维度不满）/严重（涉安全/欺诈/媒体曝光风险）。
3. 根因分析：按维度归因（房间/卫生/服务/位置/设施），同类差评反复出现 → 根因报告。
4. 回复结构：致歉 → 事实核实 → 已采取的动作 → 改进承诺；不甩锅、不辩解。
5. 整改闭环：生成整改清单 24h 内派单对应岗位（客房/前台/维修），72h 完成并回链差评事件。
6. 补偿口径：不承诺档案之外的补偿金额；涉及退款的转对账Agent / 人工。
7. 严重差评（涉安全/欺诈）→ block 级，店长亲自处理；媒体曝光风险 → 启动危机公关话术库。

## 输出动作
- 好评自动回复；中性评价生成草稿待审；差评=分级+回复草稿+整改清单+补偿方案

## 对接系统
- OTA（API+AI 浏览器评价读取/回复）、CRM（客人历史）

## 围栏绑定
- R6（差评≤3分必审 review）；严重差评按 R10 同源逻辑 block

## 输出契约
- 回复草稿附依据事件编号；差评回复必须经审批手势后才发布（M5）。

## 验收用例
- 正常路径：差评发布 → 30 分钟内生成回复草稿+整改清单 → 店长确认发布 → 整改 72h 回链
- 异常路径：监控渠道失效 → 重试 → 失败写 P0 事件不静默
- 围栏触发：严重差评涉安全 → block 级转店长亲自处理 + R6 必审

## 证据口径（无回执不算完成）

1. 好评自动回复回执；中性评价草稿版本与审批记录
2. 差评分级记录 + 回复草稿 + 整改清单 + 补偿方案；R6 审批卡引用
3. 严重差评按 R10 只告警并留联动记录，不得自行处置
