# 入住退房全流程套件

## 适用场景
- 客人到店/退房事件驱动全流程（有人酒店辅助人工；无人酒店辅助自助机+远程兜底）

## 触发条件
- 客人预计到店前 2 小时 / 到店 / 退房事件

## 输入数据
- PMS 订单与房态、客人画像（偏好/历史/会员等级）、一店一档 operations.room_check_items

## 方法
1. 入住前核查：目标房间清洁/设施/耗材达标；未达标自动派单客房并追踪。
2. 智能排房：按客人画像（历史/会员/特殊需求）+ 房间状况（楼层/朝向/噪音/相邻房）生成建议，避开问题房。
3. 入住辅助：自动录入 PMS/同步渠道/生成房卡；信息 ≤1 分钟同步。
4. 自动查房：按检项核对（清洁/损坏/丢失/minibar）；AI 无法判断 → 人工查房。
5. 费用结算：房费/minibar/其他消费自动结算，押金退还，账单生成。
6. 发票开具：电子发票 ≤2 分钟发送客人邮箱/微信。

## 输出动作
- 排房建议/入住记录/查房结果/结算账单/发票

## 对接系统
- PMS/自助机/门锁/支付/发票系统

## 围栏绑定
- 结算 auto；退款 ≥500 → R4 review；赔偿事项 → R14 review

## 验收用例
- 正常路径：退房 → 查房达标 → 自动结算 → 押金 <5 分钟退还 → 发票开出
- 异常路径：自助机身份验证失败 → 远程店长视频核实 → 留痕
- 围栏触发：发现损坏索赔 → R14 review 挂起；大额退款 → R4 review

## 证据口径（无回执不算完成）

1. 排房建议/入住记录/查房结果/结算账单/发票逐项回执（含时间戳与操作人）
2. 退款 ≥500 元引用 R4 审批卡；赔偿事项引用 R14 审批卡
3. 发票号与账单号可对账；房态与账单不一致时必须写差异，不得静默平账
