# 意图雷达（intent-radar）

> 获客五环①人群洞察。获客的起点不是内容而是意图——谁在问什么，决定了下周拍什么、写什么。

## 四个意图矿源

| 矿源 | 采什么 | 价值 |
|---|---|---|
| 竞对评论区 | 热问/吐槽/求购信息 | 对手的客户在问什么，就是你的选题 |
| OTA 差评 | 差评关键词聚类 | 对手的差评就是你的卖点（「隔音差」→ 拍静音实测） |
| query 搜索词 | 「杭州亲子酒店怎么选」类 | AI 搜索时代的意图金矿，直接喂养 GEO 内容 |
| 本店评论私信 | 高频提问 | FAQ 缺口与内容缺口同步发现 |

## 信号评分模型

```
意图热度 = 频次 × 0.4 + 增长速度 × 0.3 + 商业意图浓度 × 0.3
商业意图浓度：含「订/价格/优惠/怎么选/推荐」= 高；含「好玩吗/远吗」= 中
```

## 输出：《意图雷达报告》（每周一 07:00）

- TOP20 意图信号：主题/热度/来源样本（可溯源原文）/内容缺口/建议打法；
- 直接路由：高热信号 → content-agent 选题会；query 类信号 → hotel-geo-content 词集更新；
- 连续 2 周升温的信号 → 建议店长拍板是否做专题 campaign。

## 纪律

- 只采集公开数据，频次自律 ≥3s、遵守 robots；
- 信号必须带可溯源样本，无源不入库；
- 只读员工（L9.1），不执行任何经营动作。

## 前置校验

1. 只采集公开数据：频次自律 ≥3s、遵守 robots；不登录、不绕反爬
2. 每条信号必须带可溯源样本（原文 + 来源 + 抓取时间），无源不入库
3. 只读员工（L9.1）：只产出报告与路由建议，不执行任何经营动作


## 失败诊断（症状 → 检测器 → 处置）

| 症状 | 检测器 | 处置 |
|---|---|---|
| 某信号找不到来源原文 | 无源检查（样本缺失） | 剔除该信号，不入报告；记缺口 |
| robots/频次限制命中 | 采集纪律检查 | 立即停止该源采集，换公开接口或记「未覆盖」 |
| 只有一周数据就想建议 campaign | 连续升温判据（≥2 周） | 只登记观察，不产出 campaign 建议 |


## 证据口径（无回执不算完成）

1. 报告 TOP20 每条带可溯源样本（原文 + 来源 + 抓取时间），无源不入库
2. 周报事件 ID 与路由记录（→content-agent 选题会 / →hotel-geo-content 词集更新）
3. 信号评分的三项输入（频次/增速/商业意图浓度）可复算
