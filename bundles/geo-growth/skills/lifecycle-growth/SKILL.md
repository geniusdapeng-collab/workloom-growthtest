# 生命周期增长

## 适用场景
- 非酒店行业包、多店多品牌跨渠道客户、或 guest-success 容量超限时，经营跨渠道客户资产与 LTV；
- 设计复购/转介计划并对结果负责。

## 触发条件（三选一，经 L4 激活）
1. 非酒店行业包落地；
2. 出现多店多品牌跨渠道客户；
3. guest-success 容量或职责超限。

## 输入数据
- 客户资产与会员等级、历史复购与转介记录、触点频次与合规约束、LTV/毛利数据。

## 方法
1. **生命周期地图**：新客→首购→复购→转介，逐段算留存与流失，找最大杠杆点。
2. **去重边界**：住客体验与住客复购归 guest-success；本岗只做跨渠道/跨场景，先查触达记录再编排，禁止重复触达。
3. **复购设计**：分层唤醒（高价值/沉睡/流失预警），优惠与频次合规，效果进实验账本。
4. **转介计划**：激励设计 + 防作弊（G-GROW5：自荐/设备撞库/异常批量熔断），转介率与成本进增长账本。
5. **LTV 总账**：分渠道/分客群算 LTV 与回收周期，反哺预算组合（G-GROW1）。

## 边界（什么不做）
- 未激活（context.p2_activated != true）时一切写动作被 G-GROW7 阻断；
- 价格/承诺/现金激励类一律 L4（G-GROW2）；客资脱敏与数据边界（G-GROW6）。

## 决策原则（含阈值与失败关闭）
1. **P2 三条件之一 + L4 激活**：非酒店包 / 多店多品牌 / guest-success 超限；未激活一切写动作被 G-GROW7 阻断。
2. **去重边界**：住客体验与住客复购归 guest-success；本岗只做跨渠道/跨场景，先查触达记录再编排。
3. **激励防作弊**：自荐/设备撞库/异常批量命中 G-GROW5 熔断并转人审。
4. **频次合规**：同客触达频率与退订/投诉联动；投诉即降频并复核计划。

## 打法库（场景 → 动作序列 → 判据）
- **主线·生命周期地图**：新客→首购→复购→转介逐段留存/流失 → 找最大杠杆点（判据：每段有量化与动作）。
- **分支·转介计划**：激励设计 + 防作弊 → 转介率与成本进增长账本（判据：作弊拦截率 100%）。
- **分支·LTV 总账**：分渠道/客群 LTV 与回收周期 → 反哺预算组合（判据：与预算方案口径一致）。

## SOP（每步带触发/回执/失败路径）
1. 触发（激活后/季度）→ 地图与杠杆点 → 回执：计划版本；失败：未激活立即退出流程。
2. 触达编排 → 去重与频次校验 → 回执：触达记录；失败：撞库即取消该次触达。
3. 账本结算 → LTV 与转介结果 → 回执：总账更新；失败：作弊嫌疑单转人审。

## 关键指标（含基准与护栏）
| 指标 | 口径 | 基准/阈值 | 类型 |
|---|---|---|---|
| 转介率 | 转介成功/老客 | 月度上升 | 滞后 |
| 复购率 | 复购客户/存量客户 | 月度上升 | 滞后 |
| LTV/CAC | 分客群 | >3 | 质量 |
| 触达投诉率 | 投诉/触达 | <0.5% | 护栏 |

## 失败模式（症状 → 检测器 → 处置）
| 症状 | 检测器 | 处置 |
|---|---|---|
| 未激活先动作 | G-GROW7 阻断计数 | 阻断并复核激活条件 |
| 重复触达 | 触达撞库 | 取消并整改编排 |
| 激励被薅 | G-GROW5 熔断计数 | 熔断 + 人审 + 规则收紧 |
