# 多规格变体（Variant Forge）

## 适用场景
- 同一主视觉要覆盖多平台（小红书 3:4 / 抖音 9:16 / 朋友圈 1:1 / 公众号 2.35:1）
- 投流素材需要「钩子 × 规格」矩阵做 A/B 测试

## 方法
1. 定义变量矩阵：`hooks[]`（疑问/冲突/利益）× `specs[]`（平台规格）；
2. 用同一 recipe 模板批量渲染，保持字体、色板、品牌锚点一致，仅换文案与画布；
3. 命名规范：`题材_钩子_版本_规格`，写入一客一档时记录来源成片/素材链；
4. 输出变体清单 JSON（变体 id、规格、钩子、sha256），供投放侧绑定；
5. 淘汰复用：连续低效的钩子进「低效钩子库」，不重复生产。

## 输出契约
- N×M 变体成品 + 变体清单 + 回执；同一变体可复现（recipe + 素材哈希）。

## 边界
- 变体只改表达不改事实；价格/权益变体必须来自已确认口径；
- 单租户日渲染受 G-VIS3 配额约束，超限转人审。

## 参数边界

1. 变体之间**只改表达**（文案/画布/钩子），字体、色板、品牌锚点必须一致。
2. 价格/权益类变体**必须来自已确认口径**；不得自行组合出未确认的折扣。
3. 单租户当日渲染 **≤50 张**（G-VIS3）；超限熔断并告警。
4. 每个变体必须可复现：`recipe + 素材哈希` 缺一不可。
5. 变体清单必须含 `sha256`；缺哈希的变体不得进入投放绑定。

## 失败模式（症状 → 检测器 → 处置）

| 症状 | 检测器 | 处置 |
|---|---|---|
| 变体之间只换了文件名 | 画面差异实测（像素差） | 重做：至少一个表达维度真实变化（钩子/画布/构图） |
| 字体/色板在各变体间漂移 | 与 recipe 基线比对 | 用同一 recipe 重渲染 |
| 自造折扣/权益 | 口径比对（确认单） | 一票否决：撤回该变体 |
| 超日配额仍批量渲染 | G-VIS3（`daily_rendered`） | 熔断：分批次日或申请上调 |
| 变体缺 sha256 无法绑定投放 | 清单字段校验 | 补哈希后再投放 |
| 重复生产已淘汰钩子 | 低效钩子库比对 | 复用库内结论，换新钩子 |
